# IA-32 CDECL: один непротиворечивый контракт

Эта страница — справочник по взаимодействию NASM-кода с 32-битными C-функциями. Она разделяет два правила, которые раньше смешивались:

1. **CDECL** определяет порядок аргументов, возвращаемое значение и владельца очистки;
2. **выравнивание места вызова** определяет дополнительные байты перед аргументами.

Арифметика выравнивания канонически описана на странице [Вызов libc и 16-байтное выравнивание](/patterns/libc_alignment). Другие страницы курса должны применять эту формулу, а не вводить собственные таблицы очистки.

## Главное за 30 секунд

Для используемой в курсе модели IA-32:

```text
аргументы       → обычный стек, справа налево
результат int    → eax
очистка          → вызывающая функция
можно изменить   → eax, ecx, edx
нужно сохранить  → ebx, esi, edi, ebp
перед call       → esp % 16 == 0
```

Если перед подготовкой вызова уже выполняется `esp % 16 == 0`, используй:

```text
argument_bytes = сумма размеров аргументов
padding        = (16 - argument_bytes % 16) % 16
cleanup        = padding + argument_bytes
```

`call` временно кладёт адрес возврата, а `ret` снимает его. Эти 4 байта **не входят** в очистку вызывающей функции.

## Почему нельзя считать только аргументы

Пусть вызывается:

```c
printf("%d\n", x);
```

Два 32-битных аргумента занимают 8 байт. Из выровненного начала нужны ещё 8 байт:

```asm
sub esp, 8
push dword [x]
push fmtOut
call printf
add esp, 16
```

Подготовлено 16 байт, поэтому удаляются 16 байт. Формула `argument_count * 4` здесь дала бы только 8 и оставила padding активной частью стека.

## Таблица для выровненного начала

| Аргументы | Байты аргументов | Padding | Очистка |
|---|---:|---:|---:|
| один `dword` | 4 | 12 | 16 |
| два `dword` | 8 | 8 | 16 |
| три `dword` | 12 | 4 | 16 |
| четыре `dword` | 16 | 0 | 16 |
| указатель + `double` | 12 | 4 | 16 |

Таблица применима только когда перед подготовкой доказано `esp % 16 == 0`. При неизвестном состоянии сначала создай выровненный кадр или вычисли padding из фактического остатка.

## Аргументы справа налево

Для:

```c
f(a, b, c);
```

последовательность имеет вид:

```asm
; из выровненного начала: 12 байт аргументов + 4 байта padding
sub esp, 4
push c
push b
push a
call f
add esp, 16
```

Перед `call` первый аргумент `a` находится ближе всего к вершине стека.

## Что делает `call`

Упрощённая модель:

```text
push адрес_возврата
перейти к функции
```

Сразу внутри функции вершина содержит адрес возврата. После классического пролога:

```asm
push ebp
mov ebp, esp
```

карта выглядит так:

```text
[ebp+16]  третий аргумент
[ebp+12]  второй аргумент
[ebp+8]   первый аргумент
[ebp+4]   адрес возврата
[ebp]     старый ebp
[ebp-4]   первая локальная ячейка
```

Padding располагается **выше всех аргументов**, поэтому не меняет смещения `[ebp+8]`, `[ebp+12]` и далее.

## Пример собственной функции

C:

```c
int sum(int a, int b) {
    return a + b;
}
```

NASM:

```asm
sum:
    push ebp
    mov ebp, esp

    mov eax, [ebp+8]
    add eax, [ebp+12]

    mov esp, ebp
    pop ebp
    ret
```

Вызов из участка, где `esp % 16 == 0`:

```asm
sub esp, 8
push dword [b]
push dword [a]
call sum
add esp, 16
; eax = результат
```

Даже если `sum` сама не использует инструкции, чувствительные к выравниванию, курс сохраняет единый контракт места вызова. Так ученик не должен угадывать исключения.

## `scanf`: передаётся адрес

C:

```c
scanf("%d", &x);
```

NASM:

```asm
sub esp, 8
push x
push fmtIn
call scanf
add esp, 16
```

`x` — адрес области памяти. Запись `[x]` дала бы текущее значение и ошибочно выдала его за указатель.

## `printf`: передаётся значение

C:

```c
printf("%d", x);
```

NASM:

```asm
sub esp, 8
push dword [x]
push fmtOut
call printf
add esp, 16
```

После вызова нельзя рассчитывать на прежние `eax`, `ecx` и `edx`.

## Функции с переменным числом аргументов

Для `%f` функция `printf` получает 8-байтный `double`:

```asm
sub esp, 12
fstp qword [esp]
push fmtFloat
call printf
add esp, 16
```

Здесь 12 байт аргументов: 8 байт `double` и 4 байта адреса строки формата. Ещё 4 байта являются padding.

## Какие регистры сохраняются

| Регистры | Правило |
|---|---|
| `eax`, `ecx`, `edx` | вызываемая функция может изменить |
| `ebx`, `esi`, `edi`, `ebp` | вызываемая функция обязана восстановить, если использовала |

Пример:

```asm
use_ebx:
    push ebp
    mov ebp, esp
    push ebx

    ; работа с ebx

    pop ebx
    mov esp, ebp
    pop ebp
    ret
```

## Проверка вызова

Перед внешним `call` проверь три утверждения:

1. аргументы расположены справа налево;
2. `esp % 16 == 0`;
3. после возврата `add esp, cleanup` возвращает `esp` к состоянию до подготовки.

В GDB:

```gdb
p/x $esp
p $esp % 16
```

## Типовые ошибки

| Ошибка | Почему неверно |
|---|---|
| `cleanup = argument_count * 4` | игнорируется padding |
| считать адрес возврата частью caller cleanup | его снимает `ret` |
| положить padding после аргументов | меняется расположение параметров |
| передать `[x]` в `scanf` | значение используется как адрес |
| надеяться на сохранность `eax/ecx/edx` | вызываемая функция может их изменить |
| писать пример без исходного состояния `esp` | невозможно проверить выравнивание |
