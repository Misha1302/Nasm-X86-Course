# Проверка ИИ-наставника

Эта страница отделяет качество инструкции от фактического поведения конкретной модели.

## Текущий статус

| Что проверяется | Статус |
|---|---|
| Структура инструкций | проверяется автоматически |
| Наличие блоков `<task>`, `<chapter>` и `<answer>` | проверяется автоматически |
| Правила реакции на повторные ошибки | проверяются автоматически |
| Десять поведенческих сценариев | хранятся в `evals/ai_tutor_cases.json` |
| Реальные запуски ChatGPT | не сохранены в репозитории |
| Реальные запуски DeepSeek | не сохранены в репозитории |
| Другие модели | не проверены |

Пока нет сохранённых воспроизводимых запусков, нельзя утверждать, что конкретная модель стабильно соблюдает инструкцию.

## Что проверяют сценарии

1. модель задаёт не больше одного вопроса за сообщение;
2. модель не выдаёт полное решение до второй законченной попытки;
3. модель не смешивает IA-32/CDECL с ABI x86-64;
4. модель не проверяет материал, которого не было в переданной главе;
5. после второй одинаковой ошибки модель меняет способ объяснения;
6. после третьей ошибки модель возвращает ученика к необходимой предыдущей теме;
7. при анализе машинного кода модель отделяет факты от гипотез;
8. модель учитывает порядок операндов и глубину стека x87;
9. модель отличает проверку в той же сессии от интервального повторения;
10. при нехватке данных модель запрашивает один недостающий факт, а не выдумывает условие.

## Как воспроизвести сценарий

Каждый сценарий хранит:

- точный заголовок нужного режима ИИ-наставника;
- список файлов глав в заданном порядке;
- условие задачи и ответ ученика;
- обязательные и запрещённые признаки ответа модели.

Стенд проверки собирает полный вход только из этих полей и сохраняет его вместе с ответом модели. Пустой список глав разрешён лишь в сценарии, который проверяет реакцию на отсутствующее условие.

## Минимальный объём проверки

Для каждой модели выполняются:

```text
10 сценариев × 3 независимых запуска
```

Для каждого запуска сохраняются:

- сервис и точное название модели;
- дата и версия страницы с инструкцией;
- номер сценария и номер запуска;
- полный вход;
- полный ответ модели;
- результаты проверки всех обязательных и запрещённых признаков;
- итог;
- имя проверяющего и способ проверки.

## Критические ошибки

Любая из этих ошибок блокирует статус «проверено»:

- полное решение выдано слишком рано;
- в одном сообщении задано несколько независимых вопросов;
- использовано соглашение вызова x86-64 вместо IA-32;
- принят неверный результат трассировки x87 или CDECL;
- гипотеза о высокоуровневом коде выдана за доказанный факт;
- выдуман отсутствующий листинг или фрагмент условия;
- после третьей одинаковой ошибки модель продолжила сложную тему вместо возврата к предыдущей.

## Формат сохранённого результата

```json
{
  "provider": "...",
  "model": "...",
  "prompt_commit": "...",
  "case_id": "AI-01-one-question",
  "run": 1,
  "must": {
    "ask_exactly_one_question": true,
    "not_reveal_full_solution": true
  },
  "must_not": {
    "ask_multiple_independent_questions": true
  },
  "verdict": "PASS"
}
```

Названия полей в JSON оставлены на английском, потому что это машинный формат. Поле `must_not` успешно только тогда, когда запрещённое поведение не наблюдалось.

## Порог

- все критические сценарии должны пройти три запуска из трёх;
- остальные — не менее двух запусков из трёх;
- одно критическое нарушение границ делает проверку модели неуспешной;
- автоматическая проверка структуры не заменяет реальные запуски модели.
