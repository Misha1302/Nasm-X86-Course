# День 25. Допуск и финальная проверка

День 25 не обучает новым приёмам и не содержит решений экзаменационных заданий. Он фиксирует только допуск, правила закрытой попытки, рубрику и маршрут после неё.

## Входные знания

Перед финалом закрой все шесть [контрольных точек](/checkpoints) по их полному skill/evidence-контракту. Если не закрыта хотя бы одна обязательная модель, вернись к соответствующей контрольной точке и её [ключу](/checkpoint_keys), а не компенсируй пробел общей суммой.

## За 30 секунд

- закрытая попытка длится **90 минут**;
- обязательные материалы, справочники, ключи и подсказки во время попытки закрыты;
- максимальный результат — **100** баллов, общий порог — **80**;
- одновременно обязательны минимумы блоков и evidence каждого mandatory atomic skill;
- финал не заменяет контрольные точки: итоговая готовность равна `CP1 + CP2 + CP3 + CP4 + CP5 + CP6 + FINAL`;
- 10F и 01-16 остаются bonus-only и не компенсируют обязательные навыки;
- решение `PASS/FAIL` можно воспроизводимо получить через `scripts/score_attempt.py`.

## Минимум после главы

Полная готовность подтверждена только при одновременном выполнении условий:

1. закрыты `CP1`–`CP6`;
2. финальный результат не ниже **80** из **100**;
3. достигнут минимум каждого блока;
4. выполнены critical-task rules;
5. каждый mandatory atomic skill имеет минимальное допустимое evidence;
6. после частичной ошибки выполнен новый вариант, если этого требует контракт;
7. сохранён входной JSON и результат канонического assessment engine.

| Блок | Задания | Проверяемая область | Максимум | Минимум | Время |
|---|---|---|---:|---:|---:|
| A | A1–A4 | вызовы, целочисленные модели и перенос | 20 | 12 | 18 мин |
| B | B1–B4 | чтение состояния машины | 20 | 12 | 18 мин |
| C | C1–C3 | стек, CDECL и собственная функция | 24 | 16 | 20 мин |
| D | D1–D3 | машинные факты и границы гипотез | 21 | 13 | 18 мин |
| E | E1–E3 | безопасность, x87/varargs и объектная модель | 15 | 9 | 16 мин |
| **Итого** | **17 заданий** |  | **100** | **80** | **90 минут** |

## Практика

### Проверка одной контрольной точки

Создай, например, `cp2-attempt.json`:

```json
{
  "scores": {
    "CP2-DIV": 2,
    "CP2-SCANF": 2,
    "CP2-MASK": 2,
    "CP2-SIGNMASK-BUG": 2,
    "CP2-IDIV-BUG": 2,
    "CP2-IDIV-OVERFLOW": 2,
    "CP2-CEIL": 2,
    "CP2-GARDEN": 2,
    "CP2-AREA": 2
  },
  "new_variants": []
}
```

Используй реальные баллы по рубрике, а не копируй максимумы из примера. Запусти:

```bash
python3 scripts/score_attempt.py assessment CP2 cp2-attempt.json \
  --json-output cp2-result.json
```

Команда выводит:

```text
CP2: PASS или FAIL
total: ...
missing skills: ...
new variants required: ...
failures: ...
```

Код завершения:

```text
0 → PASS
1 → корректный вход, но результат FAIL
2 → сам входной JSON или команда некорректны
```

Балл `1` в контрольной точке требует нового варианта. После его самостоятельного решения добавь ID задания в `new_variants` и повтори команду. Само добавление ID без выполненного решения является ложной фиксацией evidence.

### Проверка финальной попытки

Для отдельной оценки `FINAL`:

```bash
python3 scripts/score_attempt.py assessment FINAL final-attempt.json \
  --readiness \
  --json-output final-result.json
```

Флаг `--readiness` требует новые варианты для частичного финального evidence так же, как полная проверка курса.

### Проверка всего допуска

Создай `course-attempt.json`:

```json
{
  "scores": {
    "CP1": {},
    "CP2": {},
    "CP3": {},
    "CP4": {},
    "CP5": {},
    "CP6": {},
    "FINAL": {}
  },
  "variants": {
    "CP1": [],
    "CP2": [],
    "CP3": [],
    "CP4": [],
    "CP5": [],
    "CP6": [],
    "FINAL": []
  }
}
```

Внутри каждого объекта запиши баллы всех заданий соответствующей проверки. Затем:

```bash
python3 scripts/score_attempt.py course course-attempt.json \
  --json-output course-result.json
```

Итог `COURSE_READINESS: PASS` возможен только если одновременно прошли `CP1`–`CP6` и `FINAL`. Неизвестные задания, отсутствующие баллы, значения вне допустимого диапазона и некорректные контейнеры обрабатываются fail-closed.

### Закрытая попытка

Открой [финальный экзамен](/final_exam), зафиксируй время начала и выполни все задания одним непрерывным блоком без перехода к ключам и учебным главам.

```text
CP1…CP6 PASS → закрытая FINAL-попытка → фиксация evidence → engine → ключ → новый вариант
```

### Фиксация evidence

После остановки таймера сохрани:

- балл каждой подчасти;
- первую сомнительную строку;
- нарушенный инвариант;
- входной JSON;
- машинно-читаемый результат `--json-output`.

Не исправляй ответ до первичной фиксации результата.

## Порядок после попытки

1. Запусти assessment engine на первично зафиксированных баллах.
2. Открой [ключ и рубрику](/final_exam_keys) только после законченной попытки.
3. Сопоставь каждую ошибку с atomic skill и допустимым evidence.
4. Используй [маршрут восстановления](/final_remediation).
5. Для частичного или нулевого обязательного результата выполни новый вариант.
6. Повторный допуск фиксируй только после прохождения того же семантического контракта на новых данных.

## Типовые ошибки

| Ошибка | Почему результат не доказывает готовность |
|---|---|
| считать только общую сумму | можно полностью провалить обязательный навык |
| открыть ключ до фиксации попытки | измеряется узнавание ответа, а не самостоятельное воспроизведение |
| вписать ID нового варианта без решения | JSON утверждает evidence, которого фактически нет |
| считать финальные 100 баллов покрытием всего курса | часть outcomes доказывается только контрольными точками |
| переписать исправление без нового варианта | устранение модели ошибки не подтверждено |
| учитывать bonus как компенсацию | 10F и 01-16 не входят в обязательные 100 баллов |
| запускать `validate_assessment.py` вместо scoring CLI | валидируется устройство контракта, а не попытка ученика |

## Чеклист

- [ ] закрыты все шесть контрольных точек по atomic skills;
- [ ] для каждой проверки сохранён входной JSON;
- [ ] зафиксированы время начала и окончания 90-минутной попытки;
- [ ] записан балл каждой подчасти до просмотра ключа;
- [ ] проверены общий порог, минимумы блоков и critical-task rules;
- [ ] для каждого mandatory skill проверено минимальное evidence;
- [ ] после частичной ошибки решён новый вариант;
- [ ] `score_attempt.py course` вернул `COURSE_READINESS: PASS` и сохранён JSON-отчёт.
