## 3. Быстрый чеклист домашек Spring-01

### 01-4. Книжки

```text
years = Y - 2011
answer = X + years * (N - M)
```

Проверь, что формула не требует переходов и корректно работает при `N < M`.

### 01-8. Объединение по маске

```text
d = (a & c) | (b & ~c)
```

Крайние тесты:

```text
c = 0          → answer = b
c = FFFFFFFFh  → answer = a
```

### 01-14. Огород

```text
items = N * M * K
boxes = ceil(items / D)
blocked = ceil(boxes / 3)
day = boxes - blocked
```

После этого выбери `boxes` ночью и `day` днём через маску `0/-1`. Отдельно проверь вместимость произведения и суммы для округления вверх.

### 01-15. Площадь треугольника

```text
det = (x2-x1)*(y3-y1) - (x3-x1)*(y2-y1)
integerPart = absDet / 2
fractionDigit = (absDet % 2) * 5
```

Точная 32-битная формула модуля без ветвлений:

```cpp
uint32_t ux = static_cast<uint32_t>(det);
uint32_t mask = 0u - (ux >> 31);
uint32_t absDet = (ux ^ mask) - mask;
```

### 01-16. Система уравнений

Каждый из 32 битов решается независимо. Для каждого кандидата `(x_bit, y_bit)` построй маску подходящих позиций, затем выбери одно допустимое решение по каждому биту.

---

::: tip Про вывод битовых ответов
Если задача битовая и ответ проверяется как 32-битные беззнаковые, используй `%u`, а не `%d`:

```asm
fmtOut db "%u", 10, 0
```

Для знаковой арифметики оставляем `%d`.
:::

## Практика

### Пробный экзамен на 90 минут

### Часть A. Написать код / формулу

#### A1. Книжки — 01-4

Даны `X, N, M, Y`. Напиши формулу количества книг к началу года `Y` и Схема на NASM без переходов.

<details>
<summary>Ответ</summary>

```text
years = Y - 2011
answer = X + years * (N - M)
```

```asm
mov eax, [Y]
sub eax, 2011
mov ecx, [N]
sub ecx, [M]
imul eax, ecx
add eax, [X]
```

</details>

#### A2. Объединение по маске — 01-8

Даны `a,b,c`. Выбери биты из `a`, где `c=1`, иначе из `b`.

<details>
<summary>Ответ</summary>

```text
d = (a & c) | (b & ~c)
```

```asm
mov eax, [a]
and eax, [c]
mov edx, [c]
not edx
and edx, [b]
or eax, edx
```

</details>

#### A3. Огород — 01-14

Запиши формулы `boxes`, `blocked`, дневного ответа и выбора без ветвлений между ночью и днём. Укажи границу переполнения округления вверх.

<details>
<summary>Ответ</summary>

```text
items = N * M * K
boxes = ceil(items / D)
blocked = ceil(boxes / 3)
day = boxes - blocked
mask = -1, если X < 6, иначе 0
answer = (boxes & mask) | (day & ~mask)
```

Форма `(a+b-1)/b` допустима, только если промежуточная сумма помещается; иначе используй `a/b + (a%b != 0)`.

</details>

#### A4. Площадь треугольника — 01-15

Напиши целочисленную формулу результата с одной цифрой после точки без числа с плавающей точкой.

<details>
<summary>Ответ</summary>

```text
det = (x2-x1)*(y3-y1) - (x3-x1)*(y2-y1)
absDet = branchless_abs(det)
integerPart = absDet / 2
fractionDigit = (absDet % 2) * 5
```

Печатаем `integerPart`, точку и `fractionDigit` (`0` или `5`). Для `INT32_MIN` нужен заранее определённый более широкий тип или ограничение входа.

</details>

#### A5. Система уравнений — 01-16

Объясни, почему 32-битную систему с `&` и `^` можно решать параллельно по битам, и назови четыре кандидата для одного бита.

<details>
<summary>Ответ</summary>

Операции `&` и `^` не переносят информацию между разрядами, поэтому каждый бит независим. Для одного разряда проверяются кандидаты:

```text
(x_bit, y_bit) = (0,0), (1,0), (0,1), (1,1)
```

Для каждого кандидата строится 32-битная маска позиций, где обе строки системы выполняются.

</details>

### Часть B. Прочитать код

#### B1. `cmp`: знаковое и беззнаковое сравнение

```asm
cmp eax, ebx
jl .L1
jb .L2
```

Объясни разницу `jl` и `jb`.

<details>
<summary>Ответ</summary>

`jl` проверяет знаковое отношение `<` по флагам `SF` и `OF`.

`jb` проверяет беззнаковое отношение `<` по флагу переноса `CF`.

Для одних и тех же битов результат может отличаться.

</details>

#### B2. `test`

```asm
test eax, eax
je .zero
```

Что это значит?

<details>
<summary>Ответ</summary>

Проверка `eax == 0`. `test eax,eax` обновляет флаги как `eax & eax`, не меняя `eax`.

</details>

#### B3. Адресация

```asm
lea eax, [edx + 4*ecx + 8]
```

Что делает эта строка?

<details>
<summary>Ответ</summary>

Считает адрес/выражение `edx + 4*ecx + 8` и кладёт в `eax`. Память не читает.

</details>

#### B4. Массив

```asm
mov eax, [edx + 4*ecx]
```

Возможный C-смысл?

<details>
<summary>Ответ</summary>

Если `edx` — база `int`-массива, `ecx` — индекс, то:

```cpp
eax = a[i];
```

</details>

### Часть C. Стек и функции

#### C1. Нарисуй фрейм

Функция имеет два аргумента и две локальные `int`-переменные. Нарисуй расположение относительно `ebp`.

<details>
<summary>Ответ</summary>

```text
[ebp+12]  argument 2
[ebp+8]   argument 1
[ebp+4]   return address
[ebp]     old ebp
[ebp-4]   local 1
[ebp-8]   local 2
```

</details>

#### C2. Напиши `sum`

```c
int sum(int a, int b) { return a + b; }
```

<details>
<summary>Ответ</summary>

```asm
sum:
    push ebp
    mov ebp, esp

    mov eax, [ebp+8]
    add eax, [ebp+12]

    pop ebp
    ret
```

</details>

#### C3. Вызови `sum(a,b)`

<details>
<summary>Ответ</summary>

```asm
push dword [b]
push dword [a]
call sum
add esp, 8
```

Результат в `eax`.

</details>

### Часть D. Анализ машинного кода

Во всех трёх заданиях показана полная функция с классическим прологом и эпилогом.

#### D1. Восстанови смысл

```asm
f:
    push ebp
    mov ebp, esp
    mov eax, [ebp+8]
    add eax, [ebp+12]
    pop ebp
    ret
```

<details>
<summary>Ответ</summary>

Возможный C-смысл:

```cpp
int f(int a, int b)
{
    return a + b;
}
```

</details>

#### D2. Указатель

```asm
f:
    push ebp
    mov ebp, esp
    mov eax, [ebp+8]
    mov edx, [ebp+12]
    mov [eax], edx
    pop ebp
    ret
```

<details>
<summary>Ответ</summary>

Первый аргумент похож на указатель:

```cpp
void f(int* p, int x)
{
    *p = x;
}
```

Точный тип может зависеть от контекста, но запись через адрес подтверждена.

</details>

#### D3. Маленький тип

```asm
f:
    push ebp
    mov ebp, esp
    mov edx, [ebp+8]
    movsx eax, byte [edx]
    pop ebp
    ret
```

<details>
<summary>Ответ</summary>

Первый аргумент похож на указатель на знаковый байт:

```cpp
int f(const signed char* p)
{
    return *p;
}
```

`movsx` подтверждает знаковое расширение байта до `int`.

</details>

### Часть E. Объяснить словами

#### E1. Что делает стековая канарейка?

<details>
<summary>Ответ</summary>

Стековая канарейка — защитное значение между локальным буфером и служебными данными кадра стека. Перед возвратом функция проверяет канарейку. Если значение изменилось, вероятно переполнение буфера.

</details>

#### E2. Почему `printf("%f")` ждёт `qword`?

<details>
<summary>Ответ</summary>

В variadic C-функциях `float` продвигается до `double`, а `double` занимает 8 байт. Поэтому для `%f` нужно передавать `qword`.

</details>

#### E3. Что такое hidden `this`?

<details>
<summary>Ответ</summary>

Это скрытый параметр метода: адрес объекта, для которого вызван метод.

</details>

### Рубрика отдельного задания

- **Полный балл:** корректна модель, соблюдены ABI/размеры/знаковость, ответ объяснён.
- **Половина балла с округлением вниз:** основная идея верна, но есть одна локальная синтаксическая ошибка или пропущено неключевое пояснение.
- **0 баллов:** нарушен центральный инвариант задания — перепутаны адрес и значение, знаковая/беззнаковая интерпретация, `edx:eax`, направление вызова, расположение данных в кадре стека, баланс `esp` или размер `double`.

Для блока C половина от 8 — 4 балла; для D половина от 7 — 3 балла; для остальных — 2 балла. Не выдавай промежуточные значения «на глаз».

Интерпретация:

- **80–100** — экзаменационное ядро готово; повтори только ошибки из журнала.
- **60–79** — повтори главы, соответствующие двум самым слабым блокам, и пройди контрольную точку ещё раз.
- **0–59** — не заучивай ответы: вернись к диагностическим контрольным точкам по порядку.

Даже при высоком общем балле ошибка в обязательном инварианте требует повторения соответствующей темы.

## 6. Последняя проверка “на листочке”

Без компьютера нарисуй:

1. `EAX/AX/AH/AL`.
2. `.text/.data/.bss`.
3. `x` и `[x]`.
4. `edx:eax / operand`.
5. `cmp` выполняет вычитание без сохранения результата.
6. `if/else` через `jcc` и `jmp`.
7. стек после `call`.
8. фрейм с `[ebp+8]`, `[ebp-4]`.
9. `[основа + индекс * множитель + смещение]`.
10. структуру с выравнивающими байтами.

Если все 10 схем рисуются уверенно — база реально есть.

## 7. Финальный принцип

Ассемблер становится понятным не тогда, когда ты выучил 100 команд.

Он становится понятным, когда ты видишь движение данных:

```text
memory -> register -> operation -> flags / memory / stack
```

И можешь честно ответить на вопросы:

```text
где лежит значение?
какого оно размера?
это адрес или данные?
какая инструкция меняет флаги?
куда прыгнет управление?
кто чистит стек?
что будет в eax перед ret?
```

Если эти вопросы стали привычными, ты уже не “боишься NASM”, а читаешь его как нормальный низкоуровневый язык.
