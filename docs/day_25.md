# День 25. Финальная проверка без смешивания обучения и ответов

## Опора на материалы ВШЭ

Все темы Дней 01–24. День 25 не добавляет новую теорию и не хранит ответы рядом с экзаменом.

## Входные знания

Перед началом:

- закрой шесть [контрольных точек](/checkpoints) по их полному контракту;
- подготовь 90 минут без справочника;
- открой [финальный экзамен](/final_exam), но не открывай ключ.

Если контрольная точка не пройдена по сумме, критическому заданию или минимуму измерения, сначала вернись к соответствующей главе.

## За 30 секунд

- Экзамен и ответы находятся на разных страницах.
- Итог определяется не только общей суммой, но и минимумом по каждому блоку.
- Задача 01-16 относится к дополнительному challenge и не входит в обязательные 100 баллов.
- Любой исполняемый вызов функции должен указывать исходное состояние `esp` и соблюдать канонический контракт выравнивания.
- После проверки используется отдельный маршрут восстановления, а затем новый вариант.

## Минимум после главы

Ты должен уметь:

- пройти [финальный экзамен](/final_exam) за **90 мин** без раскрытия ответов;
- набрать не менее **80 из 100**;
- выполнить минимум каждого блока;
- не получить `0` за критическое задание;
- объяснить каждую ошибку через первую неверную строку и нарушенный инвариант.

## Два режима примеров со стеком

### Абстрактная трассировка `call`/`ret`

Она объясняет только механику:

```text
call кладёт адрес возврата;
ret снимает адрес возврата;
аргументы остаются у вызывающей стороны.
```

Такой фрагмент не является готовым ABI-совместимым вызовом.

### Исполняемый ABI-совместимый вызов

В экзамене и ключе используется только фрагмент с доказанным начальным состоянием:

```text
до подготовки: esp % 16 == 0
argument_bytes = 8
padding = 8
cleanup = 16
```

```asm
sub esp, 8
push dword [b]
push dword [a]
call sum
add esp, 16
```

## Границы арифметических шаблонов

Безветвленный модуль в 32-битном беззнаковом представлении:

```cpp
uint32_t ux = static_cast<uint32_t>(det);
uint32_t mask = 0u - (ux >> 31);
uint32_t absDet = (ux ^ mask) - mask;
```

Это сохраняет битовый модуль, включая случай `INT32_MIN`, но дальнейшая знаковая интерпретация результата должна быть оговорена.

Округление вверх через `(a+b-1)/b` допустимо только при доказанном отсутствии переполнения. Универсальная форма для `a>=0`, `b>0`:

```text
q = a / b
r = a % b
ceil = q + (r != 0)
```

## Практика

### 1. Проверка допуска

Для каждой контрольной точки выпиши:

```text
общий балл;
баллы критических заданий;
минимумы по измерениям;
решён ли новый вариант после единицы.
```

### 2. Пробный экзамен

Пройди [экзамен](/final_exam) одним непрерывным блоком. До завершения не открывай `/final_exam_keys`.

### 3. План восстановления

После оценки выбери не «самую неприятную тему», а первый обязательный инвариант, который дал `0` или не достиг минимума блока.

### Часть D. Анализ машинного кода

В полном экзамене три листинга имеют согласованные кадры стека. Их форма:

```asm
push ebp
mov ebp, esp
mov eax, [ebp+8]
pop ebp
ret
```

```asm
push ebp
mov ebp, esp
mov eax, [ebp+8]
mov [eax], edx
pop ebp
ret
```

```asm
push ebp
mov ebp, esp
movsx eax, byte [edx]
pop ebp
ret
```

---

### Часть E. Объяснение моделей

Проверяются отдельные модели: безопасность памяти, передача `double` в функцию с переменным числом аргументов и границы гипотез о модели объектов C++.

## Типовые ошибки финала

| Ошибка | Почему блокирует готовность |
|---|---|
| считать только общую сумму | можно полностью провалить целый навык |
| открыть ключ во время экзамена | измеряется узнавание, а не воспроизведение |
| использовать `add esp,8` после подготовки 16 байт | нарушается баланс области вызова |
| считать 01-16 обязательной частью ядра | 10F является дополнительным challenge |
| переписать правильный ответ без нового варианта | исправление модели не доказано |
