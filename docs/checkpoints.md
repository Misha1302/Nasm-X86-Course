# Контрольные точки курса

Контрольная точка отвечает на вопрос: можно ли идти дальше без скрытого пробела. Выполняй её без глав, ключей и справочников, затем используй [зеркальные ключи](/checkpoint_keys).

## Общий контракт перехода

Каждое задание оценивается отдельно:

- `2` — состояние/код верны и объяснён инвариант;
- `1` — центральная модель верна, но есть одна локальная ошибка;
- `0` — центральная модель неверна или обязательный элемент отсутствует.

Переход разрешён только при выполнении **всех** условий:

1. общий балл не ниже порога;
2. ни одно критическое задание не получило `0`;
3. выполнены минимумы по измерениям;
4. после каждой единицы решён новый вариант из ключа.

Высокая сумма не компенсирует полностью отсутствующий обязательный навык.

<a id="checkpoint-1-после-дня-04"></a>
## Контрольная точка 1 — после Дня 04

**Проверяет:** инструкции, размеры и перекрывающиеся регистры.

**Максимум:** 12. **Проход:** 10. **Критические задания:** `CP1-REG`, `CP1-SIZE-R`, `CP1-SIZE-W`.

**Минимумы по измерениям:** регистры `CP1-REG+CP1-ZERO+CP1-TRANSFER ≥ 4`; размеры памяти `CP1-SIZE-R+CP1-SIZE-W ≥ 3`; интерпретация `CP1-SIGNED ≥ 1`.

### CP1-REG — трассировка регистра

```asm
mov eax, 0x12345678
mov ebx, eax
mov al, 0xAA
add eax, 2
```

Выпиши `eax`, `ebx`, `ax`, `ah`, `al`.

### CP1-SIZE-R — чтение одного байта

```asm
mov al, ___ [esi]
```

Заполни размер и объясни состояние старших 24 бит `eax`.

### CP1-SIZE-W — запись слова

```asm
mov ___ [edi], ax
```

Объясни различие с `mov dword [edi],eax`.

### CP1-SIGNED — два числовых смысла

Для `eax=FFFFFFFFh` запиши знаковое и беззнаковое значения. Меняются ли биты?

### CP1-ZERO — частичное обнуление

```asm
mov eax, 0x12345678
mov ax, 0
```

Исправь утверждение «`eax` теперь равен нулю».

### CP1-TRANSFER — новое состояние

Начальное `eax=80FF1020h`:

```asm
mov ah, 7Fh
mov al, 90h
```

Выпиши полный `eax` и две интерпретации `al`.

**Повторять:** [День 03](/day_03), [День 04](/day_04).

<a id="checkpoint-2-после-дня-10"></a>
## Контрольная точка 2 — после Дня 10

**Проверяет:** адрес/значение, libc, деление и обязательное ядро 10A–10E. Сессия 10F не входит в зачёт.

**Максимум:** 16. **Проход:** 13. **Критические задания:** `CP2-DIV`, `CP2-SCANF`, `CP2-MASK`, `CP2-IDIV-BUG`, `CP2-GARDEN`, `CP2-AREA`.

**Минимумы по измерениям:** деление `CP2-DIV+CP2-IDIV-BUG+CP2-CEIL ≥ 4`; адрес и ABI `CP2-SCANF ≥ 1`; маски `CP2-MASK+CP2-SIGNMASK-BUG ≥ 3`; прикладной перенос `CP2-GARDEN+CP2-AREA ≥ 2`.

### CP2-DIV — знаковое деление

```asm
mov eax, -7
cdq
mov ecx, 3
idiv ecx
```

Запиши `edx:eax` до деления, частное и остаток.

### CP2-SCANF — адрес и область вызова

В начале `esp%16==0`. Восстанови `scanf("%d",&x)`:

```asm
sub esp, ___
push ___
push ___
call scanf
add esp, ___
```

Докажи выравнивание и объясни адрес против значения.

### CP2-MASK — слияние по маске

Напиши `(a&mask)|(b&~mask)` и объясни, почему `0/1` не выбирает полное слово.

### CP2-SIGNMASK-BUG — неверная маска

```asm
mov edx, eax
shr edx, 31
```

Почему результат не равен `0/-1`? Исправь.

### CP2-IDIV-BUG — неверная старшая половина

```asm
mov eax, -7
xor edx, edx
mov ecx, 3
idiv ecx
```

Назови фактическое делимое и корректную подготовку.

### CP2-CEIL — округление вверх без переполнения суммы

Вычисли `ceil(a/b)` для `a>=0,b>0`, используя частное и остаток после `div`.

### CP2-GARDEN — обязательная задача 10D

Для `items=17`, `D=5` вычисли `boxes`, `blocked=ceil(boxes/3)` и дневной ответ. Перечисли задержанные индексы коробок.

### CP2-AREA — обязательная задача 10E

Для `det=-11` получи текстовый результат площади с одной цифрой после точки без x87. Объясни границу `INT32_MIN`.

**Повторять:** [Дни 05–10](/day_05), [маршрут Дня 10](/day_10_learning_path).

## Контрольная точка 3 — после Дня 15

**Проверяет:** флаги, сравнения, циклы, таблицы переходов и адресацию.

**Максимум:** 12. **Проход:** 10. **Критические задания:** `CP3-CMP`, `CP3-TABLE`, `CP3-LOOP`, `CP3-FLAGS`.

**Минимумы по измерениям:** сравнения `CP3-CMP+CP3-BIT ≥ 2`; поток управления `CP3-TABLE+CP3-LOOP+CP3-TRANSFER ≥ 4`; владелец флагов `CP3-FLAGS ≥ 1`.

### CP3-CMP — две интерпретации

Для `eax=FFFFFFFFh`, `ebx=1` после `cmp eax,ebx` объясни `jl` и `ja`.

### CP3-BIT — нечётность

```asm
test eax, ___
j___ .odd
```

### CP3-TABLE — безопасная таблица

```asm
sub eax, 10
cmp eax, 3
j___ .default
jmp [.table + 4*eax]
```

Почему тот же переход отбрасывает исходные значения ниже 10?

### CP3-LOOP — цикл и адрес

Переведи в GOTO-форму и NASM:

```cpp
for (int i=0; i<n; ++i) sum += a[i];
```

Отметь проверку, тело, шаг и формулу адреса.

### CP3-FLAGS — потерянные флаги

```asm
cmp eax, ebx
add ecx, 1
jl .less
```

Назови фактического владельца флагов и две корректные перестановки.

### CP3-TRANSFER — диапазон `switch`

```asm
sub eax, 4
cmp eax, 5
ja .default
jmp [.T + 4*eax]
```

Назови исходный диапазон и поведение для `eax=3`.

**Повторять:** [Дни 11–15](/day_11).

<a id="checkpoint-4-после-дня-19"></a>
## Контрольная точка 4 — после Дня 19

**Проверяет:** механику стека, кадр CDECL, сохраняемые регистры, структуры и осторожный анализ.

**Максимум:** 10. **Проход:** 8. **Критические задания:** `CP4-STACK`, `CP4-FRAME`, `CP4-STRUCT`, `CP4-EBX`, `CP4-TRANSFER`.

**Минимумы по измерениям:** стек/CDECL `CP4-STACK+CP4-FRAME+CP4-EBX ≥ 4`; данные и анализ `CP4-STRUCT+CP4-TRANSFER ≥ 2`.

### CP4-STACK — абстрактная трассировка `call/ret`

Это **не готовый ABI-вызов**: padding намеренно исключён, проверяется только механика.

При `esp=1000h`:

```asm
push 10
push 20
call f
```

Нарисуй стек внутри `f`, затем `esp` после `ret`. Не добавляй правило выравнивания к этой абстрактной трассировке.

### CP4-FRAME — классический кадр

Заполни:

```asm
push ___
mov ebp, ___
sub esp, ___
mov dword [ebp-4], 0
mov esp, ___
pop ___
ret
```

### CP4-STRUCT — доступ к полям

```cpp
struct Node { int value; Node* next; };
```

`Node* p` находится в `[ebp+8]`. Загрузи оба поля.

### CP4-EBX — сохраняемый регистр

Функция изменяет `ebx`. Покажи симметричное сохранение и восстановление на всех возвратах.

### CP4-TRANSFER — факт и гипотеза

Листинг читает `[p]` и `[p+4]`. Раздели подтверждённые факты, допустимые гипотезы и недоказуемые имена/типы/владение.

**Повторять:** [Дни 16–19](/day_16).

## Контрольная точка 5 — после Дня 23

**Проверяет:** запуск программы, безопасность, двоичные дроби, NaN и x87.

**Максимум:** 16. **Проход:** 13. **Критические задания:** `CP5-X87`, `CP5-VARARGS`, `CP5-STARTUP`, `CP5-SAFETY`, `CP5-X87-TRANSFER`.

**Минимумы по измерениям:** запуск `CP5-STARTUP ≥ 1`; безопасность `CP5-SAFETY ≥ 1`; представление чисел `CP5-FP-BINARY+CP5-FP-REPR+CP5-NAN ≥ 3`; x87/ABI `CP5-X87+CP5-VARARGS+CP5-X87-TRANSFER ≥ 4`.

### CP5-FP-BINARY — двоичная дробь

Представь `5.75` в двоичной системе.

### CP5-FP-REPR — приближённость

Почему `0.1` не имеет конечной двоичной записи?

### CP5-X87 — глубина стека

```asm
fld qword [a]
fld qword [b]
faddp st1, st0
```

Выпиши `st(0..)` и глубину после каждой инструкции.

### CP5-VARARGS — `%f`

При исходном `esp%16==0` восстанови:

```asm
sub esp, ___
fstp ___ [esp]
push fmt
call printf
add esp, ___
```

### CP5-STARTUP — путь запуска

Объясни `exec → загрузчик → _start → среда выполнения → main → exit` и отличие `global main` от точки входа ELF.

### CP5-SAFETY — границы защиты

Почему запись за массив может повредить адрес возврата, но не обязана немедленно завершить программу? Раздели канарейку и NX.

### CP5-NAN — сравнение

Почему `x == NaN` не является проверкой NaN?

### CP5-X87-TRANSFER — порядок операций

Построй `(a-b)/c`, выпиши глубину и проверь на `10,4,3`.

**Повторять:** [Дни 20–23](/day_20).

<a id="checkpoint-6-после-дня-24"></a>
## Контрольная точка 6 — после Дня 24

**Проверяет:** машинные факты и ABI-зависимые гипотезы о модели объектов C++.

**Максимум:** 10. **Проход:** 8. **Критические задания:** `CP6-VCALL`, `CP6-ABI`, `CP6-CALLS`.

**Минимумы по измерениям:** объект и поля `CP6-THIS+CP6-OBJECT ≥ 2`; косвенные вызовы и границы доказательства `CP6-VCALL+CP6-ABI+CP6-CALLS ≥ 4`.

### CP6-THIS — скрытый параметр и поля

Если `ecx` — адрес объекта, объясни:

```asm
mov eax, [ecx+4]
add eax, [ecx+8]
```

Раздели факты и предполагаемые имена полей.

### CP6-VCALL — возможная форма

```asm
mov ecx, [ebp+8]
mov eax, [___]
call dword [eax+___]
```

Заполни возможный `vptr` и третью 4-байтную ячейку.

### CP6-OBJECT — схема

Нарисуй `object → vptr → vtable slot → function` и отдельное поле со смещением 4.

### CP6-ABI — ложная уверенность

Почему `call [eax+8]` не доказывает третий виртуальный метод без контекста?

### CP6-CALLS — три формы цели

Сравни:

```asm
call method
call eax
call dword [eax+8]
```

Где находится адрес цели и какая форма сама по себе доказывает виртуальность?

**Повторять:** [День 24](/day_24).
