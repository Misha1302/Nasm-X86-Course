# Контрольные точки курса

Контрольная точка отвечает на один вопрос: можно ли идти дальше без скрытого пробела. Выполняй её целиком без главы и справочника. Затем открывай [ключи и рубрики](/checkpoint_keys).

## Как оценивать

Здесь оцениваются **отдельные навыки**, а не формат задания целиком:

- **2 балла** — ответ верен и объяснён правилом;
- **1 балл** — модель верна, но есть локальная ошибка;
- **0 баллов** — нарушен центральный инвариант или ответа нет.

Переход разрешён при результате не ниже 80% и отсутствии нуля по критическому навыку. После `1` реши дополнительный вариант из ключей. После `0` вернись к указанной главе.

Каждая точка содержит пять действий:

```text
trace → пропуски → написать → найти баг → transfer
```

## Checkpoint 1 — после Дня 04

Проверяет инструкции, перекрывающиеся регистры, размеры и signed/unsigned-интерпретацию. Здесь **нет** материала Дня 05 про `x/[x]`.

### 1. Trace — перекрытие регистров

После кода выпиши `eax`, `ebx`, `ax`, `ah`, `al`:

```asm
mov eax, 0x12345678
mov ebx, eax
mov al, 0xAA
add eax, 2
```

### 2. Пропуски — размер и расширение

Заполни команды:

```asm
; unsigned byte x -> eax
mov___ eax, byte [esi]

; записать только младшие 16 бит eax в y
mov ___ [edi], ax
```

Объясни, почему `mov dword [edi], eax` — другая операция.

### 3. Напиши — одна битовая картина, два смысла

Для `eax=FFFFFFFFh` запиши signed- и unsigned-значение. Объясни, изменились ли биты при смене интерпретации.

### 4. Найди баг — частичное обнуление

```asm
mov eax, 0x12345678
mov ax, 0
; автор считает, что eax теперь равен 0
```

Объясни фактический результат и исправь код.

### 5. Transfer — новое состояние

Начальное `eax=0x80FF1020`. Выполняются:

```asm
mov ah, 0x7F
mov al, 0x90
```

Выпиши полный `eax`, затем интерпретируй `al` как signed и unsigned.

**Критические навыки:** перекрытие регистров, размер операнда. Повторять: [День 03](/day_03), [День 04](/day_04).

## Checkpoint 2 — после Дня 10

Проверяет адрес/значение, CDECL-ввод/вывод, расширение, `edx:eax`, маски и безопасный `ceil`.

### 1. Trace — signed division

```asm
mov eax, -7
cdq
mov ecx, 3
idiv ecx
```

Запиши `eax`, `edx` и смысл пары до деления.

### 2. Пропуски — `scanf`

```asm
push ___
push ___
call scanf
add esp, ___
```

Восстанови `scanf("%d", &x)` и объясни адрес против значения.

### 3. Напиши — masked merge

Собери `(a & mask) | (b & ~mask)` без переходов. Объясни, почему маска `0/1` не выбирает всё 32-битное значение.

### 4. Найди баг — подготовка знака

Объясни обе ошибки:

```asm
shr edx, 31       ; хотели получить 0/-1 по знаку
```

```asm
mov eax, -7
xor edx, edx
idiv ecx
```

### 5. Transfer — безопасное округление вверх

Напиши `ceil(a/b)` для `a>=0`, `b>0`, не предполагая, что `a+b-1` помещается в 32 бита. Укажи, где лежат quotient и remainder.

**Критические навыки:** `x/[x]`, `edx:eax`, полная маска. Повторять: [День 05](/day_05), [День 09](/day_09), [День 10](/day_10), [маршрут Дня 10](/day_10_learning_path).

## Checkpoint 3 — после Дня 15

Проверяет флаги, signed/unsigned `jcc`, GOTO-form, jump table и адресацию.

### 1. Trace — два смысла сравнения

Для `eax=FFFFFFFFh`, `ebx=1` после `cmp eax,ebx` объясни, почему signed `jl` и unsigned `ja` могут быть истинны одновременно.

### 2. Пропуски — бит и jump table

```asm
test eax, ___
j___ .odd

sub eax, 10
cmp eax, 3
j___ .default
jmp [.table + 4*eax]
```

### 3. Напиши — цикл и адрес

Переведи в GOTO-form и NASM-shape:

```cpp
for (int i=0; i<n; ++i)
    sum += a[i];
```

Выпиши формулу адреса `a[i]` для `int`.

### 4. Найди баг — потерянные флаги

```asm
cmp eax, ebx
add ecx, 1
jl .less
```

Объясни фактического владельца флагов и предложи две корректные перестановки.

### 5. Transfer — восстановление switch

```asm
sub eax, 4
cmp eax, 5
ja .default
jmp [.T+4*eax]
```

Назови диапазон исходных `case` и объясни, почему проверка unsigned одновременно отбрасывает исходные значения ниже 4.

**Критические навыки:** выбор signed/unsigned перехода, сохранность флагов, проверка индекса. Повторять: [День 11](/day_11), [День 12](/day_12), [День 14](/day_14), [День 15](/day_15).

## Checkpoint 4 — после Дня 19

Проверяет обычный стек, frame layout, CDECL, reverse engineering и структуры.

### 1. Trace — вызов и пролог

Нарисуй стек после:

```asm
push b
push a
call sum
```

а затем после:

```asm
push ebp
mov ebp, esp
sub esp, 4
```

Отметь `[ebp]`, `[ebp+4]`, `[ebp+8]`, `[ebp+12]`, `[ebp-4]`.

### 2. Пропуски — frame

```asm
push ___
mov ebp, ___
sub esp, ___
mov dword [ebp-4], 0
mov esp, ___
pop ___
ret
```

### 3. Напиши — структура

```cpp
struct Node { int value; Node* next; };
```

Функция получает `Node* p` в `[ebp+8]`. Загрузи `p->value` в `eax`, `p->next` — в `edx`.

### 4. Найди баг — callee-saved

Функция использует `ebx`, но не восстанавливает его. Объясни контракт и покажи минимальную симметричную правку на всех путях.

### 5. Transfer — осторожный reverse

По обращениям `[p]` и `[p+4]` перечисли подтверждённые факты и то, что нельзя доказать: имена полей, точное объявление, ownership, nullable/non-null.

**Критические навыки:** return address, баланс `esp`, callee-saved. Повторять: [День 16](/day_16), [День 17](/day_17), [День 18](/day_18), [День 19](/day_19).

## Checkpoint 5 — после Дня 23

Проверяет startup, memory safety, floating point и x87. Каждый подпункт оценивается отдельно: знание startup не компенсирует ошибку x87.

### 1. Trace — floating point

Представь `5.75` в binary. Объясни, почему `0.1` хранится приближённо.

### 2. Trace — x87

Нарисуй `st(0..)` и глубину после:

```asm
fld qword [a]
fld qword [b]
faddp st1, st0
```

### 3. Пропуски — variadic `%f`

```asm
sub esp, ___
fstp ___ [esp]
push fmt
call printf
add esp, ___
```

### 4. Напиши — startup

Объясни путь `exec → loader → _start → runtime → main → exit` в пяти–семи предложениях. Отдельно скажи, почему `global main` не делает `main` первой инструкцией процесса.

### 5. Найди баг — UB и NaN

Объясни обе ситуации:

- out-of-bounds запись может повредить return address, но не обязана сразу уронить программу;
- `if (x == NaN)` не является корректной проверкой NaN.

### 6. Transfer — некоммутативный x87

Составь порядок `fld/fsubp/fdivp` для `(a-b)/c` и проверь результат на `a=10`, `b=4`, `c=3`.

**Критические навыки:** глубина x87, `qword` для `%f`, направление startup. Повторять: [День 20](/day_20), [День 21](/day_21), [День 22](/day_22), [День 23](/day_23).

## Checkpoint 6 — после Дня 24

Проверяет отдельный новый блок C++ object model перед финальным экзаменом.

### 1. Trace — hidden `this` и поля

Если `ecx` содержит адрес объекта, объясни:

```asm
mov eax, [ecx+4]
add eax, [ecx+8]
```

Какие факты подтверждены, а какие имена полей только предполагаются?

### 2. Пропуски — virtual call shape

```asm
mov ecx, [ebp+8]       ; possible this/object
mov eax, [___]         ; possible vptr
call dword [eax+___]   ; indirect slot
```

Заполни минимальную форму для третьего 4-байтового slot.

### 3. Напиши — схема объекта

Нарисуй:

```text
object → vptr → vtable slot → function
```

и отдельно покажи поле объекта по offset 4.

### 4. Найди баг — ложная уверенность

Утверждение: «любой `call [eax+8]` — это точно вызов третьего virtual-метода объекта». Объясни, что доказано инструкцией, а что требует ABI-контекста.

### 5. Transfer — direct vs indirect

Сравни:

```asm
call method
call eax
call dword [eax+8]
```

Для каждой формы укажи, где находится адрес цели и какая из них сама по себе доказывает виртуальность.

**Критические навыки:** direct/indirect call и граница ABI-реконструкции. Повторять: [День 24](/day_24).
