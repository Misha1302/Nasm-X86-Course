# Контрольные точки курса

Контрольная точка нужна не для оценки ради оценки, а для решения: можно ли идти дальше без скрытого пробела. Выполняй задания без справочника, затем проверяй себя по соответствующим главам.

Каждый checkpoint содержит четыре разных режима:

```text
trace → заполнить пропуски → написать самому → найти баг
```

Внутри одного режима может быть несколько связанных подпунктов. Балл за режим засчитывается, только если выполнены все его подпункты.

## Как оценивать

- **4/4** — переходи дальше.
- **3/4** — исправь ошибку и реши ещё одно похожее задание.
- **0–2/4** — вернись к указанным дням: следующий блок опирается на эту модель.
- Ошибка в обязательном инварианте (`x/[x]`, signed/unsigned, `edx:eax`, баланс `esp`, размер аргумента) блокирует переход независимо от суммы.

## Checkpoint 1 — после Дня 04

Проверяет модель инструкций, регистры и размеры операндов из дней 01–04.

1. **Trace.** После кода выпиши `eax`, `ebx`, `ax`, `ah`, `al`:

   ```asm
   mov eax, 0x12345678
   mov ebx, eax
   mov al, 0xAA
   add eax, 2
   ```

2. **Пропуски.** Дополни загрузку значения `x` в `eax` и запись результата в `y`:

   ```asm
   mov ___, [x]
   add eax, 7
   mov [y], ___
   ```

3. **Напиши.** Переведи `a = b + 7` в последовательность с одним рабочим регистром и памятью.

4. **Найди баг.** Объясни, почему `mov [a], [b]` не является обычной допустимой формой и как исправить код.

Повторять: [День 03](/day_03) и [День 04](/day_04).

## Checkpoint 2 — после Дня 10

Проверяет память, ввод/вывод, арифметику, расширение, деление и битовые формулы из дней 05–10.

1. **Trace.** Выполни руками и запиши итоговые `eax` и `edx`:

   ```asm
   mov eax, -7
   cdq
   mov ecx, 3
   idiv ecx
   ```

2. **Пропуски.** Восстанови `scanf("%d", &x)` и очистку стека:

   ```asm
   push ___
   push ___
   call scanf
   add esp, ___
   ```

3. **Напиши.** Собери `(a & mask) | (b & ~mask)` без переходов и отдельно укажи, почему маска `0/1` недостаточна.

4. **Найди баг.** Объясни две ошибки:
   - `shr edx, 31` используется для маски знака;
   - перед `idiv` отрицательного `eax` выполнено `xor edx, edx` вместо `cdq`.

Повторять: [Дни 05–10](/day_05), особенно [День 09](/day_09) и [День 10](/day_10).

## Checkpoint 3 — после Дня 15

Проверяет флаги, условия, циклы, `switch` и адресацию из дней 11–15.

1. **Trace.** Для `eax=FFFFFFFFh`, `ebx=1` после `cmp eax, ebx` объясни результаты signed `jl` и unsigned `ja`. Затем объясни, какой индекс таблицы получится после `sub eax, 10`, если исходный `eax=12`.

2. **Пропуски.** Дополни проверку нечётности и безопасный вход в jump table:

   ```asm
   test eax, ___
   j___ .odd

   sub eax, 10
   cmp eax, 3
   j___ .default
   jmp [.table + 4*eax]
   ```

3. **Напиши.** Переведи `for (i=0; i<n; ++i) sum += a[i]` в GOTO-shape и выпиши адресную формулу для `a[i]`.

4. **Найди баг.** Между `cmp eax, ebx` и `jl .less` стоит `add ecx, 1`. Объясни последствие и предложи исправление, не меняющее условие.

Повторять: [Дни 11–15](/day_11), особенно [День 12](/day_12), [День 14](/day_14) и [День 15](/day_15).

## Checkpoint 4 — после Дня 19

Проверяет стек, CDECL, reverse engineering и структуры из дней 16–19.

1. **Trace.** Нарисуй стек после `push b; push a; call sum`, а затем после стандартного пролога `sum`.

2. **Пропуски.** Восстанови классический пролог, локальную переменную и эпилог:

   ```asm
   push ___
   mov ebp, ___
   sub esp, ___
   mov dword [ebp-4], 0
   mov esp, ___
   pop ___
   ret
   ```

3. **Напиши.** Для структуры

   ```cpp
   struct Node { int value; Node* next; };
   ```

   напиши NASM-фрагмент, который получает `Node* p` в `[ebp+8]`, загружает `p->value` в `eax`, а `p->next` — в `edx`. Затем объясни, какой C-смысл можно восстановить по offsets `0` и `4`.

4. **Найди баг.** Функция изменила `ebx` и не восстановила его. Объясни нарушение контракта и покажи минимальное исправление.

Повторять: [Дни 16–19](/day_16), особенно [День 17](/day_17), [День 18](/day_18) и [День 19](/day_19).

## Checkpoint 5 — после Дня 23

Проверяет startup, memory safety, floating point и x87 из дней 20–23.

1. **Trace.** Выполни оба подпункта:
   - представь `5.75` в двоичном виде и объясни, почему `0.1` хранится приближённо;
   - нарисуй `st(0..)` после `fld a; fld b; faddp`.

2. **Пропуски.** Сохрани результат x87 и передай его в `printf("%f")`:

   ```asm
   sub esp, ___
   fstp ___ [esp]
   push fmt
   call printf
   add esp, ___
   ```

3. **Напиши.** Объясни путь `exec → loader → _start → runtime → main → exit` в пяти–семи строках.

4. **Найди баг.** Объясни обе ситуации:
   - out-of-bounds запись может повредить return address, но не обязана сразу уронить программу;
   - проверка `if (x == NaN)` не обнаруживает NaN.

Повторять: [Дни 20–23](/day_20), особенно [День 21](/day_21), [День 22](/day_22) и [День 23](/day_23).
