# Контрольные точки курса

Контрольная точка отвечает на один вопрос: можно ли идти дальше без скрытого пробела. Выполняй её целиком без главы, ключей и справочника. Затем открывай [зеркальные ключи и варианты повторения](/checkpoint_keys).

## Как оценивать

Каждый пункт имеет стабильный ID и оценивается отдельно:

- **2 балла** — ответ верен, полный и объяснён инвариантом;
- **1 балл** — центральная модель верна, но есть одна локальная вычислительная, синтаксическая или терминологическая ошибка;
- **0 баллов** — центральная модель неверна, обязательный элемент отсутствует либо нарушен критический инвариант.

В начале каждого checkpoint указаны максимум, проходной балл и критические ID. Переход разрешён только когда одновременно выполнены два условия:

1. набран проходной балл;
2. ни один критический ID не получил `0`.

После `1` реши дополнительный вариант с тем же ID из [ключей](/checkpoint_keys). После `0` сначала вернись к указанной главе, затем повтори исходное задание и вариант.

Полный набор действий:

```text
trace → пропуски → написать → найти баг → transfer
```

## Checkpoint 1 — после Дня 04

**Проверяет:** инструкции, перекрывающиеся регистры, размеры и signed/unsigned-интерпретацию из Дней 01–04.

**Максимум:** 12. **Проход:** 10. **Критические ID:** `CP1-REG`, `CP1-SIZE-R`, `CP1-SIZE-W`.

<a id="cp1-reg"></a>
### CP1-REG — Trace перекрывающихся регистров

После кода выпиши `eax`, `ebx`, `ax`, `ah`, `al`:

```asm
mov eax, 0x12345678
mov ebx, eax
mov al, 0xAA
add eax, 2
```

<a id="cp1-size-r"></a>
### CP1-SIZE-R — Пропуск: чтение одного байта

Заполни размер, не расширяя значение до 32 бит:

```asm
mov al, ___ [esi]
```

Объясни, сколько байтов читается и какие биты `eax` могут остаться прежними.

<a id="cp1-size-w"></a>
### CP1-SIZE-W — Пропуск: запись одного слова

```asm
mov ___ [edi], ax
```

Объясни, почему `mov dword [edi], eax` — другая операция.

<a id="cp1-signed"></a>
### CP1-SIGNED — Напиши два числовых смысла

Для `eax=FFFFFFFFh` запиши signed- и unsigned-значение. Объясни, изменяются ли биты при смене интерпретации.

<a id="cp1-zero"></a>
### CP1-ZERO — Найди баг: частичное обнуление

```asm
mov eax, 0x12345678
mov ax, 0
; автор считает, что eax теперь равен 0
```

Объясни фактический результат и исправь код.

<a id="cp1-transfer"></a>
### CP1-TRANSFER — Transfer на новое состояние

Начальное `eax=0x80FF1020`:

```asm
mov ah, 0x7F
mov al, 0x90
```

Выпиши полный `eax`, затем интерпретируй `al` как signed и unsigned.

**Повторять:** [День 03](/day_03), [День 04](/day_04).

## Checkpoint 2 — после Дня 10

**Проверяет:** адрес/значение, libc-вызовы, расширение, `edx:eax`, маски и безопасный `ceil` из Дней 05–10.

**Максимум:** 12. **Проход:** 10. **Критические ID:** `CP2-DIV`, `CP2-SCANF`, `CP2-MASK`, `CP2-IDIV-BUG`.

<a id="cp2-div"></a>
### CP2-DIV — Trace signed division

```asm
mov eax, -7
cdq
mov ecx, 3
idiv ecx
```

Запиши `edx:eax` до деления, quotient и remainder после деления.

<a id="cp2-scanf"></a>
### CP2-SCANF — Пропуски: `scanf`

Восстанови `scanf("%d", &x)`:

```asm
push ___
push ___
call scanf
add esp, ___
```

Объясни, почему передаётся адрес, а не `[x]`.

<a id="cp2-mask"></a>
### CP2-MASK — Напиши masked merge

Собери `(a & mask) | (b & ~mask)` без переходов. Объясни, почему маска `0/1` не выбирает полное 32-битное значение.

<a id="cp2-signmask-bug"></a>
### CP2-SIGNMASK-BUG — Найди баг в маске знака

```asm
mov edx, eax
shr edx, 31       ; хотели получить 0 или -1
```

Объясни фактический результат и минимальную правку.

<a id="cp2-idiv-bug"></a>
### CP2-IDIV-BUG — Найди баг в signed dividend

```asm
mov eax, -7
xor edx, edx
mov ecx, 3
idiv ecx
```

Объясни, какое делимое фактически образовано и как подготовить его корректно.

<a id="cp2-ceil"></a>
### CP2-CEIL — Transfer: безопасное округление вверх

Напиши `ceil(a/b)` для `a>=0`, `b>0`, не предполагая, что `a+b-1` помещается в 32 бита. Укажи, где после `div` лежат quotient и remainder.

**Повторять:** [День 05](/day_05), [День 06](/day_06), [День 08](/day_08), [День 09](/day_09), [День 10](/day_10), [маршрут Дня 10](/day_10_learning_path).

## Checkpoint 3 — после Дня 15

**Проверяет:** флаги, signed/unsigned `jcc`, GOTO-form, jump table и адресацию из Дней 11–15.

**Максимум:** 12. **Проход:** 10. **Критические ID:** `CP3-CMP`, `CP3-TABLE`, `CP3-FLAGS`.

<a id="cp3-cmp"></a>
### CP3-CMP — Trace двух интерпретаций

Для `eax=FFFFFFFFh`, `ebx=1` после `cmp eax, ebx` объясни результаты signed `jl` и unsigned `ja`.

<a id="cp3-bit"></a>
### CP3-BIT — Пропуски: проверка нечётности

```asm
test eax, ___
j___ .odd
```

<a id="cp3-table"></a>
### CP3-TABLE — Пропуски: безопасный jump table

```asm
sub eax, 10
cmp eax, 3
j___ .default
jmp [.table + 4*eax]
```

Объясни, почему выбранный переход отбрасывает и исходные значения ниже 10.

<a id="cp3-loop"></a>
### CP3-LOOP — Напиши цикл и адресную формулу

Переведи в GOTO-form и NASM-shape:

```cpp
for (int i=0; i<n; ++i)
    sum += a[i];
```

Выпиши формулу адреса `a[i]` для массива `int`.

<a id="cp3-flags"></a>
### CP3-FLAGS — Найди баг: потерянные флаги

```asm
cmp eax, ebx
add ecx, 1
jl .less
```

Назови инструкцию-владельца актуальных флагов и предложи две корректные перестановки.

<a id="cp3-transfer"></a>
### CP3-TRANSFER — Transfer: восстановление диапазона `switch`

```asm
sub eax, 4
cmp eax, 5
ja .default
jmp [.T + 4*eax]
```

Назови диапазон исходных `case`, допустимые индексы таблицы и поведение для исходного `eax=3`.

**Повторять:** [День 11](/day_11), [День 12](/day_12), [День 13](/day_13), [День 14](/day_14), [День 15](/day_15).

## Checkpoint 4 — после Дня 19

**Проверяет:** обычный стек, frame layout, CDECL, reverse engineering и структуры из Дней 16–19.

**Максимум:** 10. **Проход:** 8. **Критические ID:** `CP4-STACK`, `CP4-FRAME`, `CP4-EBX`.

<a id="cp4-stack"></a>
### CP4-STACK — Trace вызова и пролога

Нарисуй стек после:

```asm
push b
push a
call sum
```

а затем после:

```asm
push ebp
mov ebp, esp
sub esp, 4
```

Отметь `[ebp]`, `[ebp+4]`, `[ebp+8]`, `[ebp+12]`, `[ebp-4]`.

<a id="cp4-frame"></a>
### CP4-FRAME — Пропуски: классический frame

```asm
push ___
mov ebp, ___
sub esp, ___
mov dword [ebp-4], 0
mov esp, ___
pop ___
ret
```

<a id="cp4-struct"></a>
### CP4-STRUCT — Напиши доступ к структуре

```cpp
struct Node { int value; Node* next; };
```

Функция получает `Node* p` в `[ebp+8]`. Загрузи `p->value` в `eax`, `p->next` — в `edx`.

<a id="cp4-ebx"></a>
### CP4-EBX — Найди баг: callee-saved

Функция использует `ebx`, но не восстанавливает его. Объясни контракт и покажи симметричную правку на всех путях возврата.

<a id="cp4-transfer"></a>
### CP4-TRANSFER — Transfer: осторожный reverse

Листинг читает `[p]` и `[p+4]`. Перечисли отдельно:

1. подтверждённые факты;
2. допустимые гипотезы;
3. то, что нельзя доказать: имена полей, точное объявление, ownership, nullable/non-null.

**Повторять:** [День 16](/day_16), [День 17](/day_17), [День 18](/day_18), [День 19](/day_19).

## Checkpoint 5 — после Дня 23

**Проверяет:** startup, memory safety, floating point и x87 из Дней 20–23. Несвязанные навыки оцениваются раздельно.

**Максимум:** 16. **Проход:** 13. **Критические ID:** `CP5-X87`, `CP5-VARARGS`, `CP5-STARTUP`, `CP5-X87-TRANSFER`.

<a id="cp5-fp-binary"></a>
### CP5-FP-BINARY — Представь двоичную дробь

Представь `5.75` в binary и покажи разложение дробной части.

<a id="cp5-fp-repr"></a>
### CP5-FP-REPR — Объясни приближённость

Объясни, почему `0.1` не имеет конечной двоичной записи.

<a id="cp5-x87"></a>
### CP5-X87 — Trace x87-стека

Нарисуй `st(0..)` и глубину после каждой инструкции:

```asm
fld qword [a]
fld qword [b]
faddp st1, st0
```

<a id="cp5-varargs"></a>
### CP5-VARARGS — Пропуски: `%f`

```asm
sub esp, ___
fstp ___ [esp]
push fmt
call printf
add esp, ___
```

Объясни размер variadic-аргумента.

<a id="cp5-startup"></a>
### CP5-STARTUP — Напиши startup path

Объясни путь `exec → loader → _start → runtime → main → exit` в пяти–семи предложениях. Отдельно скажи, почему `global main` не делает `main` ELF entry point.

<a id="cp5-safety"></a>
### CP5-SAFETY — Найди ошибочную модель UB

Объясни, почему out-of-bounds запись может повредить return address, но не обязана сразу завершить программу.

<a id="cp5-nan"></a>
### CP5-NAN — Найди ошибку сравнения

Объясни, почему `if (x == NaN)` не является корректной проверкой NaN.

<a id="cp5-x87-transfer"></a>
### CP5-X87-TRANSFER — Transfer: некоммутативный x87

Составь порядок `fld`, `fsubp`, `fdivp` для `(a-b)/c`. После каждой инструкции выпиши `st(0..)` и проверь результат на `a=10`, `b=4`, `c=3`.

**Повторять:** [День 20](/day_20), [День 21](/day_21), [День 22](/day_22), [День 23](/day_23).

## Checkpoint 6 — после Дня 24

**Проверяет:** отдельный блок C++ object model перед финальным экзаменом.

**Максимум:** 10. **Проход:** 8. **Критические ID:** `CP6-VCALL`, `CP6-ABI`, `CP6-CALLS`.

<a id="cp6-this"></a>
### CP6-THIS — Trace hidden `this` и offsets

Если `ecx` содержит адрес объекта, объясни:

```asm
mov eax, [ecx+4]
add eax, [ecx+8]
```

Какие факты подтверждены, а какие имена полей только предполагаются?

<a id="cp6-vcall"></a>
### CP6-VCALL — Пропуски: virtual-call shape

```asm
mov ecx, [ebp+8]       ; possible object/this
mov eax, [___]         ; possible vptr
call dword [eax+___]   ; third 4-byte slot
```

<a id="cp6-object"></a>
### CP6-OBJECT — Нарисуй модель

Нарисуй:

```text
object → vptr → vtable slot → function
```

и отдельно покажи поле объекта по offset 4.

<a id="cp6-abi"></a>
### CP6-ABI — Найди ложную уверенность

Утверждение: «любой `call [eax+8]` — это точно вызов третьего virtual-метода объекта». Объясни, что доказано инструкцией, а что требует ABI-контекста.

<a id="cp6-calls"></a>
### CP6-CALLS — Transfer: direct и indirect targets

Сравни:

```asm
call method
call eax
call dword [eax+8]
```

Для каждой формы укажи, где находится адрес цели и какая из них сама по себе доказывает виртуальность.

**Повторять:** [День 24](/day_24).

| | | | | | |
