# Источники и границы проверяемости

Курс использует несколько типов материалов. Их наличие в тексте главы не означает, что все исходные файлы опубликованы в этом репозитории.

## Иерархия источников

| Источник | Статус | Как использовать |
|---|---|---|
| Канонические страницы `docs/*.md` | опубликованы в репозитории | основной учебный материал курса |
| Исполняемые примеры `examples/*.asm` и golden output | опубликованы и проверяются CI | наблюдаемая проверка конкретных машинных утверждений |
| Контракты и валидаторы `scripts/*` | опубликованы и выполняются CI | владельцы структуры, оценивания и регрессионных ограничений |
| Слайды ВШЭ с именами `Slides2026-*.pdf` | внешние/course-only; в репозитории не хранятся | указатели на происхождение темы, но не обязательный шаг самостоятельного прохождения |
| Документация архитектуры и ABI | внешняя | источник для независимой перепроверки; конкретная версия должна фиксироваться при формальном аудите |

## Слайды ВШЭ

Главы могут ссылаться на имена файлов вида:

```text
Slides2026-04.pdf
Slides2026-0xB.pdf
Slides2026-0x10.pdf
```

Эти ссылки означают, что тема сопоставлена с соответствующим учебным материалом. Сами PDF не включены в репозиторий, и их публичная доступность этим курсом не утверждается.

Самостоятельное прохождение не должно требовать открытия этих файлов: обязательная модель, примеры, практика и контроль находятся в опубликованных страницах курса. Если содержание внешнего слайда расходится с канонической страницей, нельзя молча смешивать версии — сначала нужно зафиксировать конкретный PDF и ревизию курса, затем разобрать расхождение.

## Что считается доказательством

Для утверждения «пример работает» нужны фактическая сборка, запуск и проверка результата, а не только листинг в Markdown.

Для утверждения «ученик готов» нужны результаты канонического assessment engine, включая обязательные навыки и новые варианты после частичных ошибок, а не только общая сумма.

Для утверждения «ИИ-наставник соблюдает инструкцию» нужны сохранённые provider-backed ответы и отдельная семантическая проверка. Успешный mock-запуск доказывает работу стенда, но не качество конкретной модели.

## Как проводить независимый аудит

Зафиксируй:

1. полный Git SHA курса;
2. точные версии внешних документов;
3. среду сборки и ABI;
4. выполненные команды и их результаты;
5. отдельно — непроверенные внешние условия.

Не переносите выводы между разными ревизиями без повторной проверки изменившихся контрактов.
