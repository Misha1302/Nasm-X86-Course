## За 30 секунд

- `main` обычно не является первой инструкцией процесса.
- Загрузчик отображает исполняемый файл и библиотеки в память.
- Точка входа обычной C-программы обычно ведёт в `_start`.
- Стартовый код и среда выполнения подготавливают окружение и вызывают `main`.
- После `main` среда выполнения завершает процесс и вызывает нужную финализацию.
- `global main` экспортирует символ, но не назначает точку входа ELF.

## Минимум после главы

После главы ты должен уметь:

- объяснить путь `exec → загрузчик → _start → среда выполнения → main → exit`;
- различить символ `main` и точку входа ELF;
- объяснить роль начального стека;
- узнать служебный код запуска в дизассемблировании;
- назвать команды для просмотра точки входа и секций.

## Главная модель

```text
исполняемый файл
      ↓ загрузчик ОС
процесс и начальный стек
      ↓ точка входа ELF
_start
      ↓ среда выполнения C
main(argc, argv, envp)
      ↓ завершение и финализация
exit
```

Центральный инвариант:

> Видимый символ `main` и адрес первой инструкции процесса являются разными свойствами программы.

---

## Исполняемый файл и процесс

Исполняемый файл — данные на диске. Процесс — состояние конкретного запуска:

```text
файл: код, данные, таблицы, точка входа
процесс: отображённая память, регистры, стек, библиотеки, ресурсы
```

Один файл можно запустить несколько раз, получив несколько процессов с разным состоянием.

---

## Что делает загрузчик

Упрощённо загрузчик:

1. читает заголовки ELF;
2. создаёт адресное пространство процесса;
3. отображает код и данные;
4. подключает нужные динамические библиотеки;
5. формирует начальный стек;
6. передаёт управление точке входа.

Типичная учебная карта памяти:

```text
большие адреса
+------------------------+
| стек                   |
+------------------------+
| библиотеки / mmap      |
+------------------------+
| куча                   |
+------------------------+
| .bss                   |
| .data                  |
| .rodata                |
| .text                  |
+------------------------+
малые адреса
```

Точные адреса и порядок областей зависят от системы и параметров запуска.

---

## Начальный стек

При запуске ОС помещает на стек данные, необходимые стартовому коду:

- `argc` — количество аргументов;
- `argv` — массив указателей на строки аргументов;
- `envp` — массив переменных окружения;
- служебные записи для загрузчика и среды выполнения.

При запуске:

```bash
./main hello 123
```

C-функция получает:

```text
argc = 3
argv[0] = "./main"
argv[1] = "hello"
argv[2] = "123"
```

`main` видит уже подготовленные аргументы, хотя исходно они находились в начальном стеке процесса.

---

## `_start`

`_start` — типичная точка входа обычной C-программы. Она приходит из стартовых объектных файлов, которые подключает GCC при компоновке.

```asm
global main
```

означает:

```text
символ main виден компоновщику
```

но не:

```text
main является первой инструкцией процесса
```

Программа без среды выполнения C может самостоятельно определить `_start` и вообще не иметь `main`.

---

## Среда выполнения C

Упрощённая роль среды выполнения:

- принять начальное состояние от `_start`;
- подготовить библиотечное окружение;
- вызвать функции инициализации;
- вызвать `main`;
- обработать код возврата;
- выполнить финализацию и завершить процесс.

```text
_start → __libc_start_main → main → exit
```

Внутренности конкретной libc могут различаться. Для курса важна граница ответственности.

---

## Код до и после `main`

В C++ глобальные объекты могут иметь конструкторы и деструкторы:

```cpp
struct A {
    A();
    ~A();
};

A global;
```

Конструктор `global` должен выполниться до пользовательского тела `main`, деструктор — при корректной финализации.

Для списков таких функций используются, например, секции `.init_array` и `.fini_array`.

---

## Как проверить программу

Точка входа:

```bash
readelf -h main
```

Секции:

```bash
readelf -S main
objdump -h main
```

Дизассемблирование:

```bash
objdump -d -M intel main
```

Символы:

```bash
nm -n main
readelf -s main
```

Сравни адрес точки входа с адресом символа `main`: это позволяет наблюдаемо проверить, что они различаются.

### 2. Что доказывает `global main`?

<details>
<summary>Ответ</summary>

Только видимость символа `main` для компоновщика. Точку входа хранит заголовок ELF.

</details>

### 3. Проверка инструментами

Назови команду для точки входа и команду для списка символов.

<details>
<summary>Ответ</summary>

Например, `readelf -h main` и `nm -n main`.

</details>

### 4. Два запуска

Почему два запуска одного файла являются двумя процессами?

<details>
<summary>Ответ</summary>

У каждого запуска собственное состояние памяти, регистров, стека и ресурсов.

</details>

## Типовые ошибки

| Ошибка | Почему неверно |
|---|---|
| считать `main` первой инструкцией | до неё работает стартовый код |
| считать `global main` назначением точки входа | директива экспортирует символ |
| смешивать компоновщик и загрузчик | первый создаёт файл, второй — процесс |
| считать начальный стек обычным кадром `main` | он существует до вызова `main` |
| объявлять конкретную карту памяти гарантированной | размещение зависит от системы |
