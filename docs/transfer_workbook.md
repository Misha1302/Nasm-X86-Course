# Рабочая тетрадь: перенос на новые задачи

У каждой главы есть одна новая задача `TR-XX`. Сначала закончи попытку, затем открывай [диагностический ключ](/transfer_keys). Для сложных задач доступны [пошаговые разборы](/transfer_walkthroughs).

<a id="tr-01"></a>
## TR-01 — путь программы

Расположи и объясни: ассемблер, объектный файл, компоновщик, исполняемый файл, загрузчик, процесс, процессор.

<a id="tr-02"></a>
## TR-02 — сборка

`nasm -f elf32` прошёл, но линковка сообщает несовместимую архитектуру. Назови три проверки, отделяющие ошибку исходника от проблемы 32-битной среды.

<a id="tr-03"></a>
## TR-03 — инструкции и владелец флагов

```asm
mov eax, 9
mov ebx, eax
sub eax, 4
add ebx, eax
```

Выпиши итоговые регистры, приёмники арифметических инструкций и последнего владельца `eflags`.

<a id="tr-04"></a>
## TR-04 — регистры и размеры

Для `eax=81ABCDEFh` выполни `mov ah,10h; mov al,80h`. Выпиши `eax/ax/ah/al` и две интерпретации `al`.

<a id="tr-05"></a>
## TR-05 — адрес и значение

Для `x dd 17` объясни независимо:

```asm
mov eax, x
mov ebx, [x]
lea ecx, [x]
mov [x], ebx
```

<a id="tr-06"></a>
## TR-06 — libc-вызов

В теле функции с `esp%16==0` напиши `scanf("%d%d",&a,&b)`, затем `printf("%d",a-b)`. Для каждого вызова посчитай `argument_bytes`, `padding`, `cleanup` и изменяемые регистры.

<a id="tr-07"></a>
## TR-07 — два вида переполнения

В 8-битной модели вычисли `7Fh+02h` и `FFh+02h`. Для каждого укажи сохранённые биты, две интерпретации, `CF` и `OF`.

<a id="tr-08"></a>
## TR-08 — расширение

Байт `A0h` прочитай как `160` и `-96`. Объясни, почему `mov al,[x]` недостаточно при неизвестных старших битах.

<a id="tr-09"></a>
## TR-09 — два деления

Протрассируй `-20/6`. Затем интерпретируй `FFFFFFECh` как беззнаковое число и раздели его на 6 с правильной подготовкой `edx:eax`.

<a id="tr-10"></a>
## TR-10 — минимум без переходов и граница

Построй `min(a,b)` через маску знака `a-b`. Укажи условие корректности и контрпример со знаковым переполнением разности.

<a id="tr-11"></a>
## TR-11 — владелец флагов

Для каждой последовательности назови флаги, которые увидит следующий `jcc`:

```asm
cmp eax, ebx
mov ecx, 10
sub edx, edx
```

```asm
test eax, eax
lea ecx, [ecx+1]
```

<a id="tr-12"></a>
## TR-12 — составное условие

Переведи в NASM:

```cpp
if (x != 0 && (unsigned)y <= 15 && (x & 8) != 0) answer = 1;
```

Не меняй флаги между проверкой и её переходом.

<a id="tr-13"></a>
## TR-13 — `continue`, `break` и шаг

Сначала GOTO-форма, затем NASM:

```cpp
for (int i=0; i<n; ++i) {
    if (a[i] < 0) continue;
    if (a[i] == 0) break;
    sum += a[i];
}
```

Отметь проверку, тело, шаг, `continue`, `break`.

<a id="tr-14"></a>
## TR-14 — таблица переходов

```asm
sub eax, 5
cmp eax, 6
ja .default
jmp [.T + 4*eax]
.T: dd .A, .B, .B, .D, .default, .F, .A
```

Построй таблицу индекс→исходное значение→метка.

<a id="tr-15"></a>
## TR-15 — двумерная адресация

Для `short matrix[4][7]` выведи адрес `matrix[i][j]` и загрузи элемент со знаковым расширением при базе `edx`, `i` в `eax`, `j` в `ecx`.

<a id="tr-16"></a>
## TR-16 — абстрактная механика стека

> Это трассировка `push/call/ret`, а не готовый ABI-совместимый вызов. Выравнивающие байты намеренно исключены.

При `esp=1000h`:

```asm
push 10
push 20
call f
```

Нарисуй стек внутри `f`, затем `esp` после `ret`. Объясни, какие байты принадлежат вызывающей стороне и какие обрабатывает `call/ret`.

<a id="tr-17"></a>
## TR-17 — CDECL-функция

Напиши `int store_sum(int a,int b,int* out)`: записать сумму по `out`, использовать `ebx`, вернуть сумму в `eax`, восстановить регистры и кадр.

<a id="tr-18"></a>
## TR-18 — две допустимые реконструкции

```asm
push ebp
mov ebp, esp
mov edx, [ebp+8]
movzx eax, byte [edx]
add eax, [ebp+12]
pop ebp
ret
```

Перечисли факты и предложи два совместимых объявления, не выдавая имена и знаковость за доказанные.

<a id="tr-19"></a>
## TR-19 — расположение структуры

Для типичного IA-32 ABI оцени смещения и `sizeof`:

```cpp
struct Item { char tag; int value; short flags; Item* next; };
```

Напиши доступ к `p->next` и оговори зависимость от упаковки.

<a id="tr-20"></a>
## TR-20 — точка входа ELF

Почему `global main` не делает `main` точкой входа? Назови команду просмотра entry point и путь `загрузчик → _start → среда выполнения → main`.

<a id="tr-21"></a>
## TR-21 — безопасность и защиты

Нарисуй возможный кадр с `char buf[8]`, канарейкой, сохранённым `ebp` и адресом возврата. Раздели канарейку, NX и зависимость расположения от компилятора.

<a id="tr-22"></a>
## TR-22 — точная и неточная дробь

Представь `6.625` в двоичном и нормализованном виде. Объясни, почему `0.125` конечно, `0.2` периодично и точное сравнение вычисленного результата с `0.2` ненадёжно.

<a id="tr-23"></a>
## TR-23 — некоммутативный x87

Построй `(a-b)/(c+d)`, выпиши `st(0..)` и глубину после каждой инструкции, затем передай результат в `printf("%f")` из состояния `esp%16==0`.

<a id="tr-24"></a>
## TR-24 — факты и гипотезы модели объектов

```asm
mov ecx, [ebp+8]
mov eax, [ecx]
mov edx, [ecx+4]
call dword [eax+8]
```

Раздели машинные факты, гипотезу `this/vptr/поле/ячейка метода` и ABI-зависимые детали.

<a id="tr-25"></a>
## TR-25 — смешанный допуск к финалу

За 25 минут:

1. исправь `scanf`, которому передали `[x]`;
2. протрассируй `-13/5`;
3. выбери знаковый переход для `x>=y`;
4. нарисуй кадр функции с двумя аргументами и локальной переменной;
5. передай x87-результат в `printf("%f")` с полным расчётом области вызова.

После ключа переходи к [финальному экзамену](/final_exam), только если критические инварианты закрыты.
