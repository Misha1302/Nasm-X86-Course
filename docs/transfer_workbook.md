# Рабочая тетрадь: перенос на новые задачи

Здесь находится по одной новой задаче на каждый день курса. У каждой задачи стабильный ID `TR-XX`, совпадающий с ID в [диагностических ключах](/transfer_keys).

Сначала реши задачу полностью. Затем открой ключ и проверь не только результат, но и обязательный инвариант. Просмотренное решение не считается выполненной попыткой.

<a id="tr-01"></a>
## TR-01 — путь программы

Расположи в правильном порядке и объясни границы ответственности: linker, CPU, assembler, loader, object file, process, executable.

<a id="tr-02"></a>
## TR-02 — сборка

Программа успешно проходит `nasm -f elf32`, но линковка падает с сообщением о несовместимой архитектуре. Назови три проверки, которые отделяют ошибку NASM-исходника от отсутствующей или неверной 32-битной среды.

<a id="tr-03"></a>
## TR-03 — инструкции и владелец флагов

Протрассируй:

```asm
mov eax, 9
mov ebx, eax
sub eax, 4
add ebx, eax
```

Выпиши итоговые `eax` и `ebx`, destination каждой арифметической инструкции и назови инструкцию, которая оставила актуальное состояние `eflags`. Конкретные формулы `CF/OF` пока не требуются.

<a id="tr-04"></a>
## TR-04 — регистры и размеры

Дано `eax=0x81ABCDEF`. После `mov ah,0x10` и `mov al,0x80` выпиши `eax`, `ax`, `ah`, `al`. Затем прочитай `al` как signed и unsigned.

<a id="tr-05"></a>
## TR-05 — адрес и значение

Для `x dd 17` объясни результат каждой строки независимо:

```asm
mov eax, x
mov ebx, [x]
lea ecx, [x]
mov [x], ebx
```

Какие регистры содержат адрес, а какие значение? Какая инструкция не читает память, несмотря на скобки в адресном выражении?

<a id="tr-06"></a>
## TR-06 — libc-вызов

Напиши полный фрагмент `scanf("%d%d", &a, &b)` и затем `printf("%d", a-b)` внутри body, где `esp % 16 == 0`. Для каждого вызова посчитай padding, argument bytes и полный cleanup; укажи регистры, на сохранность которых caller не может рассчитывать.

<a id="tr-07"></a>
## TR-07 — арифметика и два вида переполнения

В 8-битной модели вычисли `0x7F+0x02` и `0xFF+0x02`. Для каждого случая укажи сохранённые 8 бит, signed-смысл, unsigned-смысл, `CF` и `OF`.

<a id="tr-08"></a>
## TR-08 — расширение

В памяти лежит `byte 0xA0`. Получи в `eax` сначала `160`, затем `-96`. Объясни, почему `mov al,[x]` не решает задачу надёжно, если старшие биты `eax` неизвестны.

<a id="tr-09"></a>
## TR-09 — signed и unsigned division

Протрассируй signed `-20/6`: подготовку `edx:eax`, quotient и remainder. Затем интерпретируй те же младшие 32 бита `0xFFFFFFEC` как unsigned, выполни корректную unsigned-подготовку и вычисли точные quotient и remainder.

<a id="tr-10"></a>
## TR-10 — branchless minimum и граница метода

Построй без переходов `min(a,b)` для signed 32-bit через маску знака разности `a-b`. Обязательно укажи предусловие корректности и минимальный контрпример, где signed overflow разности меняет выбранное значение.

<a id="tr-11"></a>
## TR-11 — владелец флагов

Для каждой последовательности назови инструкцию, чьи флаги увидит следующий `jcc`, и объясни почему:

```asm
cmp eax, ebx
mov ecx, 10
sub edx, edx
```

```asm
test eax, eax
lea ecx, [ecx+1]
```

<a id="tr-12"></a>
## TR-12 — составное условие

Переведи в NASM:

```cpp
if (x != 0 && (unsigned)y <= 15 && (x & 8) != 0)
    answer = 1;
```

Прыгай через тело по каждому ложному условию и не теряй флаги между producer и consumer.

<a id="tr-13"></a>
## TR-13 — `continue`, `break` и шаг цикла

Построй GOTO-form и NASM-shape:

```cpp
for (int i=0; i<n; ++i) {
    if (a[i] < 0) continue;
    if (a[i] == 0) break;
    sum += a[i];
}
```

Отдельно отметь метки проверки, тела, шага, `continue` и `break`.

<a id="tr-14"></a>
## TR-14 — восстановление jump table

```asm
sub eax, 5
cmp eax, 6
ja .default
jmp [.T + 4*eax]
.T: dd .A, .B, .B, .D, .default, .F, .A
```

Построй таблицу `index → исходный case → target` и назови объединённые ветки.

<a id="tr-15"></a>
## TR-15 — двумерная адресация

Для `short matrix[4][7]` выведи адрес `matrix[i][j]`. Затем напиши NASM-фрагмент signed-загрузки элемента, если base находится в `edx`, `i` — в `eax`, `j` — в `ecx`.

<a id="tr-16"></a>
## TR-16 — стек без frame pointer

Пусть перед кодом `esp=0x1000`:

```asm
push 10
push 20
call f
```

Внутри `f` сразу после `call` нарисуй адреса и содержимое стека. Затем покажи `esp` после `ret` и после очистки двух аргументов caller-ом.

<a id="tr-17"></a>
## TR-17 — CDECL-функция

Напиши функцию `int store_sum(int a,int b,int* out)`, которая записывает `a+b` по `out`, использует `ebx` как временный регистр и возвращает сумму в `eax`. Сохрани обязательные регистры и нарисуй frame layout.

<a id="tr-18"></a>
## TR-18 — две допустимые реконструкции

Для листинга перечисли подтверждённые факты и предложи **два** разных C-подобных объявления, совместимых с наблюдаемыми инструкциями:

```asm
push ebp
mov ebp, esp
mov edx, [ebp+8]
movzx eax, byte [edx]
add eax, [ebp+12]
pop ebp
ret
```

Не придумывай имена, signedness или ownership там, где листинг их не доказывает.

<a id="tr-19"></a>
## TR-19 — layout структуры

Для типичного IA-32 ABI оцени layout:

```cpp
struct Item {
    char tag;
    int value;
    short flags;
    Item* next;
};
```

Укажи offsets, padding, возможный `sizeof(Item)` и NASM-доступ к `p->next`. Отдельно назови ABI/packing-оговорку.

<a id="tr-20"></a>
## TR-20 — ELF entry point

Объясни, почему `global main` не делает `main` ELF entry point. Назови команду, которой можно посмотреть entry point, и восстанови путь `loader → _start → runtime → main`.

<a id="tr-21"></a>
## TR-21 — memory safety и защиты

Нарисуй возможный frame с `char buf[8]`, canary, saved `ebp` и return address. Объясни отдельно:

1. что обнаруживает canary;
2. что запрещает NX;
3. почему ни одна защита не делает выход за границы корректным;
4. почему точный порядок объектов требует проверки компилятора/ABI.

<a id="tr-22"></a>
## TR-22 — точная и неточная двоичная дробь

1. Представь `6.625` в binary и нормализованном виде.
2. Объясни, почему `0.125` представляется конечной двоичной дробью, а `0.2` — нет.
3. Назови, почему точное сравнение результата вычислений с `0.2` может быть ненадёжным.

Численный анализ relative/absolute tolerance здесь не требуется.

<a id="tr-23"></a>
## TR-23 — некоммутативный x87

Составь x87-последовательность для `(a-b)/(c+d)`. После каждой инструкции выпиши `st(0..)` и глубину, затем передай результат в `printf("%f")` с правильным размером аргумента и очисткой `esp`.

<a id="tr-24"></a>
## TR-24 — факты и гипотезы object model

Проанализируй:

```asm
mov ecx, [ebp+8]
mov eax, [ecx]
mov edx, [ecx+4]
call dword [eax+8]
```

Раздели ответ на:

1. подтверждённые машинные факты;
2. гипотезу `this/vptr/field/virtual slot`;
3. ABI-зависимые детали.

<a id="tr-25"></a>
## TR-25 — смешанный мини-финал

За 25 минут без справочника:

1. исправь `scanf`, которому передали `[x]`;
2. протрассируй `-13/5`;
3. выбери signed `jcc` для `x>=y`;
4. нарисуй frame функции с двумя аргументами и одной локальной;
5. объясни передачу x87-результата в `printf("%f")`.

После проверки выбери самый слабый инвариант и повтори соответствующий вариант на следующий день.
