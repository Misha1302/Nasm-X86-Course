## За 30 секунд

- Компилятор переводит C++ в более низкоуровневое представление.
- Ассемблер превращает текст NASM в объектный файл.
- Компоновщик объединяет объектные файлы и библиотеки в исполняемый файл.
- Загрузчик создаёт процесс и размещает программу в памяти.
- Процессор исполняет машинные инструкции уже созданного процесса.
- Объектный файл и исполняемый файл — не одно и то же.

## Минимум после главы

После главы ты должен уметь:

- отличить файл программы от выполняющегося процесса;
- разложить простое выражение C++ на загрузку, вычисление и запись;
- объяснить, почему процессор не знает конструкцию `while`.

Детали формата ELF, таблиц символов и записей перемещения будут углубляться позже. Сейчас требуется только их роль.

## Главная модель

```text
текст программы
      ↓ инструмент перевода
машинный код и данные в файлах
      ↓ компоновка
исполняемый файл
      ↓ загрузка
состояние процесса в памяти
      ↓ выполнение
изменения регистров, памяти и вывода
```

Центральный инвариант:

> Инструменты сборки создают файлы; загрузчик создаёт процесс; процессор выполняет инструкции процесса.

## Термины до первой задачи

| Термин | Вход | Что делает | Выход |
|---|---|---|---|
| исходный файл | текст C++ или NASM | хранит программу в форме для человека и инструментов | текст |
| компилятор | C++ | переводит высокоуровневые конструкции | ассемблер или объектный код |
| ассемблер | текст NASM | кодирует инструкции и данные | объектный файл |
| объектный файл | машинный код и служебные таблицы | хранит часть программы, ещё не обязательно готовую к запуску | `.o` |
| компоновщик | объектные файлы и библиотеки | связывает части, разрешает внешние имена, назначает итоговые адреса | исполняемый файл |
| исполняемый файл | машинный код и описание размещения | хранит программу в форме, которую может загрузить ОС | ELF-файл программы |
| загрузчик | исполняемый файл | создаёт адресное пространство, размещает код и данные, готовит запуск | процесс |
| процесс | загруженная программа и её состояние | содержит память, регистры, открытые ресурсы | выполняющееся состояние |
| процессор | инструкции процесса | читает и выполняет команды | новое состояние машины |

### ELF

ELF — используемый в Linux формат объектных и исполняемых файлов. Он описывает код, данные, секции, символы и параметры загрузки.

### Символ

Символ — имя функции или объекта, например `main` или `printf`, которое используют инструменты сборки.

### Неразрешённый символ

Если объектный файл вызывает `printf`, но сам не содержит её код, имя остаётся неразрешённым до компоновки с библиотекой.

### Запись перемещения

Запись перемещения сообщает компоновщику: «когда станет известен итоговый адрес, исправь это место в машинном коде или данных».

На первом проходе не нужно знать двоичный формат записи; важно понимать, почему `.o` может быть правильным, но ещё не запускаться.

## Разобранный пример пути

Пусть есть `main.asm`:

```asm
section .text
global main

main:
    xor eax, eax
    ret
```

Этапы:

```text
main.asm
  ↓ nasm -f elf32
main.o
  ↓ gcc -m32 -no-pie
main
  ↓ loader
process
  ↓ CPU
return code 0
```

### После NASM

`main.o` уже содержит машинные байты для `xor` и `ret`, но может содержать служебные таблицы и внешние ссылки. Это ещё не гарантирует готовность к запуску.

### После компоновки

Исполняемый файл содержит связанные части программы и данные для загрузки.

### После запуска

Файл не «превращается» навсегда. ОС создаёт отдельный процесс: состояние конкретного запуска программы.

---

## C++ превращается в маленькие шаги

C++:

```cpp
z = x + y;
```

Одна возможная низкоуровневая форма:

```asm
mov eax, [x]
add eax, [y]
mov [z], eax
```

Схема:

```text
прочитать x → прибавить y → записать z
```

Одна строка C++ не обязана соответствовать одной инструкции.

## Почему процессор не знает `while`

C++:

```cpp
while (x > 0)
    --x;
```

Низкоуровневая идея:

```text
check:
    сравнить x с 0
    если x <= 0 → end
    уменьшить x
    перейти к check
end:
```

`while` — конструкция языка. Процессор видит сравнения, изменения состояния и переходы.

### 1. Расставь этапы

```text
процесс, объектный файл, загрузчик, ассемблер,
исполняемый файл, процессор, компоновщик
```

<details>
<summary>Ответ</summary>

```text
ассемблер → объектный файл → компоновщик → исполняемый файл → загрузчик → процесс → процессор
```

</details>

### 2. Файл или состояние

К какой категории относится каждое понятие: `main.o`, исполняемый `main`, процесс с PID 1234, `eax`?

<details>
<summary>Ответ</summary>

`main.o` и `main` — файлы; процесс с PID — состояние запуска; `eax` — часть состояния процессора этого процесса.

</details>

### 3. Почему `.o` может не запускаться

Назови две причины.

<details>
<summary>Ответ</summary>

Объектный файл может содержать неразрешённые символы и записи перемещения; он ещё не является связанным исполняемым файлом.

</details>

### 4. Разложи выражение

```cpp

```

Запиши шаги «прочитать → вычислить → записать».

## Типовые ошибки

| Ошибка | Почему мешает |
|---|---|
| считать `.o` готовой программой | объектный файл может требовать компоновки |
| считать файл и процесс одним объектом | один файл можно запустить несколько раз, создав разные процессы |
| говорить, что CPU исполняет C++ | процессор исполняет машинные инструкции |
| путать компоновщик и загрузчик | первый создаёт файл, второй создаёт состояние процесса |
| заучивать названия без входа и выхода этапа | невозможно восстановить цепочку при ошибке |
