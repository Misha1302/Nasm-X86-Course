# Как решать задачи на NASM

Эта страница — алгоритм решения, когда условие уже есть, но переход от C++ к состоянию машины пока неочевиден.

Для вызовов функций не используй таблицы очистки по памяти. Вычисляй область вызова по [канонической формуле выравнивания](/patterns/libc_alignment), а правила регистров проверяй по [CDECL](/c_abi).

## 1. Перепиши условие как наблюдаемый результат

Выпиши:

```text
что дано;
что требуется получить;
какой тип и размер у каждого значения;
какие крайние случаи допустимы.
```

Не начинай с инструкций, пока не ясен числовой или адресный результат.

## 2. Напиши C++-идею

Например:

```cpp
answer = (a & mask) | (b & ~mask);
```

Или:

```cpp
for (int i=0; i<n; ++i)
    sum += a[i];
```

Высокоуровневая идея нужна как эталон, но не должна скрывать переполнение, адреса и размеры.

## 3. Выдели состояние машины

Составь таблицу:

| Объект | Где хранится | Размер | Когда меняется |
|---|---|---:|---|
| `a` | память | 4 | ввод |
| текущий результат | `eax` | 4 | арифметика |
| индекс | `ecx` | 4 | шаг цикла |
| остаток | `edx` | 4 | `div/idiv` |

Это предотвращает случайное переиспользование регистра с важным значением.

## 4. Запиши инвариант

Примеры:

- перед каждой итерацией `ecx` является индексом следующего элемента;
- после `cdq` пара `edx:eax` является знаковым расширением делимого;
- перед внешним `call` выполняется `esp % 16 == 0`;
- после вызова `esp` возвращается к состоянию до подготовки области;
- глубина x87 после законченного выражения соответствует ожидаемой.

Без инварианта сложно отличить локальную описку от неверной модели.

## 5. Переведи вычисление в NASM без ввода и вывода

Сначала напиши только ядро:

```asm
mov eax, [a]
and eax, [mask]

mov edx, [mask]
not edx
and edx, [b]

or eax, edx
```

Проверь его вручную на маленьких числах. Только после этого добавляй библиотечные вызовы.

## 6. Добавь ввод и вывод через одну формулу

Пусть перед подготовкой доказано:

```text
esp % 16 == 0
```

### Один адрес и строка формата

```asm
sub esp, 8
push x
push fmtIn
call scanf
add esp, 16
```

### Одно значение и строка формата

```asm
sub esp, 8
push eax
push fmtOut
call printf
add esp, 16
```

### Два адреса и строка формата

```asm
sub esp, 4
push b
push a
push fmt2
call scanf
add esp, 16
```

Общее правило:

```text
argument_bytes = сумма размеров аргументов
padding = (16 - argument_bytes % 16) % 16
cleanup = padding + argument_bytes
```

Очищается вся подготовленная область. Адрес возврата в неё не входит: его снимает `ret`.

## 7. Протрассируй состояния

Для арифметики выписывай регистры после каждой существенной инструкции.

Для обычного стека:

```text
esp до подготовки
esp после padding
esp после каждого push
esp перед call
esp после cleanup
```

Для x87 отдельно выписывай `st(0..)`, глубину и обычный `esp`.

## 8. Проверь типовые границы

Минимальный набор:

- ноль;
- единица;
- отрицательное значение, если допустимо;
- максимальное значение типа;
- минимальное знаковое значение;
- пустой диапазон или нулевая длина;
- деление без остатка и с остатком;
- маски `0` и `FFFFFFFFh`;
- одинаковые и разные операнды для некоммутативной операции.

## 9. Найди контрпример своей формуле

Спроси:

- может ли промежуточная сумма переполниться;
- не спутаны ли адрес и значение;
- не используется ли знак переполненной разности;
- не остался ли старый мусор в верхней части регистра;
- не изменил ли `call` регистры `eax/ecx/edx`;
- не нарушен ли порядок `fsubp` или `fdivp`.

## 10. Используй ключи по ступеням

1. закончи собственную попытку;
2. открой краткий ключ;
3. найди первую строку расхождения;
4. при тупике открой [пошаговый разбор](/transfer_walkthroughs);
5. закрой страницу и реши новый вариант.

## Перед сдачей

- [ ] результат задачи сформулирован точно;
- [ ] размеры и знаковость выписаны;
- [ ] регистры имеют определённые роли;
- [ ] инвариант записан;
- [ ] ядро проверено без ввода/вывода;
- [ ] область каждого вызова вычислена;
- [ ] обычный стек и x87 протрассированы отдельно;
- [ ] проверены крайние случаи;
- [ ] найден хотя бы один контрпример типовой ошибке.
