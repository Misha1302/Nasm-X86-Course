---

## За 30 секунд

- Стек IA-32 растёт к меньшим адресам.
- `esp` хранит адрес вершины стека.
- `push` уменьшает `esp` на 4 и записывает значение.
- `pop` читает значение и увеличивает `esp` на 4.
- `call` кладёт адрес возврата и переходит к функции.
- `ret` снимает адрес возврата и переходит по нему.
- Баланс стека означает, что в контрольной точке `esp` имеет ожидаемое значение.

## Главная модель

Стек — область памяти с правилом:

```text
последним положили → первым сняли
```

В IA-32 вершина находится по адресу `esp`, а рост идёт к меньшим адресам.

```text
большие адреса
+------------------+
| более старые данные |
+------------------+
| вершина           | <- esp
+------------------+
меньшие адреса
```

Центральный инвариант:

> В каждой точке, где код ожидает определённую структуру стека, `esp` должен указывать именно на её вершину.

---

## `push`

```asm
push eax
```

Учебная модель:

```text
esp = esp - 4
[esp] = eax
```

Пусть:

```text
esp = 0x1000
eax = 123
```

После `push eax`:

```text
esp = 0x0FFC
[0x0FFC] = 123
```

Значение записывается после уменьшения `esp`.

---

## `pop`

```asm
pop ebx
```

Учебная модель:

```text
ebx = [esp]
esp = esp + 4
```

Если перед командой:

```text
esp = 0x0FFC
[0x0FFC] = 123
```

то после:

```text
ebx = 123
esp = 0x1000
```

`pop` не обязан физически стирать старые байты. Он меняет границу активной части стека.

---

## Разобранный пример `push`/`pop`

Начальное состояние:

```text
esp = 0x1000
```

Код:

```asm
push 10
push 20
pop eax
push 30
pop ebx
pop ecx
```

Трассировка:

| После шага | `esp` | Вершина | Регистры |
|---|---:|---|---|
| начало | `0x1000` | — | — |
| `push 10` | `0x0FFC` | `10` | — |
| `push 20` | `0x0FF8` | `20` | — |
| `pop eax` | `0x0FFC` | `10` | `eax=20` |
| `push 30` | `0x0FF8` | `30` | `eax=20` |
| `pop ebx` | `0x0FFC` | `10` | `ebx=30` |
| `pop ecx` | `0x1000` | — | `ecx=10` |

Конечный `esp` совпал с начальным: временные данные сбалансированы.

---

## `call`: переход с адресом возврата

```asm
call f
```

Учебная модель:

```text
push адрес_следующей_инструкции
перейти к f
```

Пусть перед вызовом:

```text
esp = 0x0FF8
```

Сразу внутри `f`:

```text
esp = 0x0FF4
[esp] = адрес возврата
```

Адрес возврата находится ближе к вершине, чем аргументы, которые вызывающая функция положила раньше.

---

## `ret`: возврат по адресу на вершине

```asm
ret
```

Учебная модель:

```text
цель = [esp]
esp = esp + 4
перейти к цели
```

Следовательно, перед `ret` вершина обязана содержать адрес возврата. Если `esp` указывает на локальное число, аргумент или мусор, `ret` попытается использовать это число как адрес кода.

---

## Аргументы и адрес возврата

Пусть:

```text
esp = 0x1000
```

Вызывающая функция выполняет:

```asm
push 10
push 20
call f
```

Состояние сразу внутри `f`:

```text
0x0FF4  адрес возврата <- esp
0x0FF8  20
0x0FFC  10
```

После `ret`:

```text
esp = 0x0FF8
```

Аргументы всё ещё лежат в области вызывающей функции. Если они больше не нужны:

```asm
add esp, 8
```

и `esp` снова станет `0x1000`.

Здесь не было дополнительных выравнивающих байтов. Если они были подготовлены, как в вызовах libc из Дня 06, вызывающая функция удаляет **и их, и аргументы**.

---

## Связь с Днём 06

Рассмотрим вызов с двумя аргументами после выровненного начала:

```asm
sub esp, 8
push value
push fmt
call printf
add esp, 16
```

До `call` вызывающая функция уменьшила `esp` на:

```text
8 байт выравнивания + 8 байт аргументов = 16 байт
```

Сам `call` временно кладёт ещё 4 байта адреса возврата. `ret` снимает именно эти 4 байта. После возврата остаётся область, которую подготовила вызывающая функция, поэтому она выполняет:

```asm
add esp, 16
```

Нельзя заменить эту очистку на `add esp,8`: тогда выравнивающие байты останутся частью активного стека.

---

## Баланс стека

Баланс — это не требование «число `push` равно числу `pop`» на каждой строке. Важно, чтобы в выбранной контрольной точке `esp` вернулся к ожидаемому адресу.

Допустимо:

```asm
push eax
push ebx
add esp, 8
```

если значения не нужны.

Допустимо:

```asm
sub esp, 16
; временная область
add esp, 16
```

Ошибка:

```asm
sub esp, 16
; временная область
add esp, 12
ret
```

Вершина остаётся смещённой на 4 байта, поэтому `ret` прочитает не тот адрес.

---

## Рекурсия

Каждый `call` кладёт свой адрес возврата. Поэтому вложенные вызовы естественно образуют стек:

```text
fact(5)
fact(4)
fact(3)
fact(2)
fact(1)
```

После завершения самого глубокого вызова `ret` возвращает управление ровно на один уровень вверх.

Полные кадры каждого вызова появятся в следующей главе.

## Практика

### 1. Трассировка `esp`

Начальное состояние:

```text
esp = 0x2000
```

Код:

```asm
push 1
push 2
pop eax
```

Выпиши `esp` после каждой инструкции и итоговый `eax`.

<details>
<summary>Ответ</summary>

```text
push 1  → esp=0x1FFC
push 2  → esp=0x1FF8
pop eax → eax=2, esp=0x1FFC
```

</details>

### 2. Вызов с аргументами

Начальное `esp=0x1000`:

```asm
push 10
push 20
call f
```

Нарисуй три занятых адреса сразу внутри `f`.

<details>
<summary>Ответ</summary>

```text
0x0FF4 — адрес возврата
0x0FF8 — 20
0x0FFC — 10
```

</details>

### 3. Найди ошибку

```asm
sub esp, 8
push eax
push fmt
call printf
add esp, 8
```

Почему очистка неверна?

<details>
<summary>Ответ</summary>

Вызывающая функция подготовила 16 байт: 8 байт выравнивания и 8 байт аргументов. После `ret` нужно удалить все 16 байт.

</details>

### 4. Что снимет `ret`

Перед `ret`:

```text
esp -> [123]
       [адрес возврата]
```

Что произойдёт?

<details>
<summary>Ответ</summary>

`ret` воспримет `123` как адрес перехода. Сначала нужно восстановить `esp`, чтобы вершиной стал настоящий адрес возврата.

</details>

## Типовые ошибки

| Ошибка | Почему неверно |
|---|---|
| рисовать рост стека к большим адресам | `push` уменьшает `esp` |
| считать первым аргументом значение на вершине внутри функции | на вершине сразу после `call` лежит адрес возврата |
| считать `call` обычным `jmp` | `call` дополнительно сохраняет адрес возврата |
| удалять только аргументы при наличии выравнивания | `esp` не возвращается к исходному состоянию |
| делать лишний `pop` | можно снять адрес возврата или данные другого уровня |
| проверять баланс только количеством инструкций | значение `esp` может изменяться и через `add/sub` |
