# Стандарт учебных глав и самостоятельного контура

Эта страница фиксирует обязательные контракты курса. Глава объясняет модель; самостоятельный контур проверяет перенос, диагностику, исправление и удержание навыка.

## Основная учебная цепочка

```text
глава → TR-XX → зеркальный ключ → исправление/вариант → spaced recall → checkpoint
```

Наличие текста, ответов или большого количества задач само по себе не доказывает самостоятельность курса.

## Обязательная структура `day_XX.md`

```md
# День XX. Название

## Входные знания
- проверяемые действия;
- точный маршрут возврата.

## За 30 секунд
- 4–7 главных тезисов.

## Минимум после главы
- наблюдаемые результаты;
- явные non-goals.

## Главная схема или таблица состояния

## Базовый шаблон

## Подробно разобранный пример

## Почему это работает

## Типовые ошибки

## Практика
- минимум два разных наблюдаемых действия.

## Чеклист
- минимум три действия;
- без самостоятельного «понимать».

## Следующий шаг
- точная ссылка на `/transfer_workbook#tr-XX`;
- точная ссылка на `/transfer_keys#key-tr-XX`;
- инструкция по журналу ошибок и решению о переходе.
```

`Следующий шаг` является частью главы, а не необязательной навигацией. Ученик, открывший прямую ссылку на `day_XX.md`, должен увидеть полный следующий action без возврата на главную страницу.

## Наблюдаемые цели

Плохо:

```text
понимать CDECL
знать флаги
разобраться с x87
```

Хорошо:

```text
нарисовать frame и подписать [ebp+4], [ebp+8], [ebp-4]
для заданного add определить CF/OF и объяснить две интерпретации
протрассировать st(0..), сохранить qword и восстановить esp
```

Чеклист обязан проверять действие, а не самооценку ученика.

## Входные знания

Prerequisite — это действие, а не название темы.

Плохо:

```text
знать память
```

Хорошо:

```text
без подсказки отличить address метки от value по адресу и написать одну загрузку и запись
```

Checkpoint или transfer не может требовать инструкцию, формулу или модель, введённую только в будущей главе.

## Модель состояния

| Тема | Обязательное первое представление |
|---|---|
| инструкции | registers и изменяемый destination |
| memory | addresses, bytes и width |
| flags | producer → flags → consumer |
| control flow | labels, edges, back-edge |
| stack | addresses, `esp`, return address |
| CDECL | frame и ownership caller/callee |
| x87 | depth и `st(0..)` после каждого шага |
| object model | machine facts → ABI hypothesis |

Для некоммутативной операции trace должен позволять отличить правильный порядок от обратного числовым контрпримером.

## Практика внутри и вне главы

Полный курс закрывает пять разных действий:

```text
trace
заполнить пропуски
написать с нуля
найти баг
перенести на новую форму
```

- внутри главы достаточно минимум двух подходящих форм;
- transfer всегда находится в [рабочей тетради](/transfer_workbook);
- ближайший checkpoint проверяет смешанное воспроизведение;
- direct repetition разобранного примера не считается transfer.

## Контракт `TR-XX`

Для каждого дня существуют ровно два зеркальных объекта:

```text
TR-XX в transfer_workbook.md
TR-XX в transfer_keys.md
```

ID, порядок и количество должны совпадать механически.

Transfer меняет хотя бы один существенный признак:

- числа или boundary case;
- направление C ↔ NASM;
- форму control flow;
- data layout;
- комбинацию навыков;
- correct example → bug review.

Transfer не вводит новую теорию. Если задача требует отсутствующего понятия, нужно либо сначала обучить ему, либо сузить задачу.

## Контракт transfer-ключа

Каждый `TR-XX` key содержит:

- обязательный результат;
- явное поле `Инвариант`;
- типовую ошибку или неправильную модель;
- минимальный контрпример;
- точный маршрут повторения.

Если задача просит два варианта, точное число или trace, ключ обязан отвечать в той же полноте.

## Контракт checkpoints

Каждое checkpoint-задание имеет стабильный ID `CPN-NAME`.

Checkpoint объявляет:

- список независимых IDs;
- максимум `2 × количество ID`;
- проходной балл не ниже 80%;
- критические IDs;
- точные главы повторения.

Шкала:

- `2` — полный правильный ответ с инвариантом;
- `1` — правильная центральная модель и одна локальная ошибка;
- `0` — модель неверна или обязательный элемент отсутствует.

Переход разрешён только при достижении порога и отсутствии нуля по критическому ID.

## Контракт checkpoint-ключа

`checkpoint_keys.md` зеркально содержит каждый ID из `checkpoints.md` и для него фиксирует:

- ожидаемый результат;
- инвариант;
- типовую ошибку;
- контрпример;
- маршрут повторения;
- новый вариант после результата `1`.

Фраза «реши дополнительный вариант» недопустима без фактического варианта в ключе.

## Spaced repetition

Нужно различать:

- same-session retrieval — проверка в конце текущего занятия;
- spaced recall — возврат на следующий день или позже.

Базовый график:

| Когда | Действие |
|---|---|
| следующий день | один trace или вопрос без конспекта |
| через 3–4 дня | смешанное задание |
| через 7 дней | объяснение модели и bug review |

## AI-наставник

AI — дополнительный interface, не источник истины.

Prompt pack обязан:

- принимать отдельные `<task>`, `<chapter>`, `<answer>`;
- задавать один вопрос за сообщение;
- не раскрывать полное решение до законченных попыток;
- не проверять материал вне присланной главы;
- после первой ошибки дать одну подсказку;
- после второй сменить representation;
- после третьей вернуть к prerequisite mini-task;
- отделять machine fact от high-level hypothesis;
- не смешивать IA-32 и x86-64.

Канонические страницы:

- [AI-наставник](/ai_tutor_prompts);
- [протокол AI-eval](/ai_tutor_eval);
- `evals/ai_tutor_cases.json`.

Наличие prompt text даёт статус `STRUCTURALLY_VALID`. Статус `BEHAVIORALLY_VERIFIED` требует сохранённых provider/model runs с provenance. До этого ChatGPT, DeepSeek и другие models считаются непроверенными для данного revision.

## Generated artifacts

`docs/textbook.md` и `docs/course_migration.md` генерируются командой:

```bash
python3 scripts/generate_course_docs.py
```

Они намеренно не являются canonical source files и игнорируются Git. VitePress build создаёт их до проверки и публикации.

`textbook.md` обязан включать:

- самостоятельный маршрут;
- все 25 глав;
- отдельный маршрут Дня 10;
- transfer tasks и keys;
- checkpoints и rubrics;
- AI prompts и eval-status.

Название «полный самостоятельный учебник» допустимо только при наличии всех этих source markers в generated output.

## Definition of done для главы

Глава готова, если:

- шесть обязательных level-2 блоков существуют и идут в правильном порядке;
- prerequisite операционален;
- есть state model и worked example;
- есть минимум две practice forms;
- checklist содержит минимум три наблюдаемых действия;
- `Следующий шаг` ведёт к точному `TR-XX` и `key-TR-XX`;
- ближайший checkpoint покрывает её центральные навыки;
- links, anchors и технические примеры проходят validator.

## Definition of done для самостоятельного курса

- 25 task IDs зеркально совпадают с 25 transfer-key IDs;
- все transfer keys диагностичны;
- 6 checkpoints имеют вычислимый scoring и критические IDs;
- checkpoint tasks и keys зеркальны;
- после каждого `1` существует новый вариант;
- все 25 глав имеют `Следующий шаг`;
- День 10 разбит на sessions;
- есть spaced-recall и error ledger;
- AI provider claims не превышают имеющиеся evidence;
- generated standalone textbook включает все учебные слои;
- documentation build, validator и executable examples проходят CI.
