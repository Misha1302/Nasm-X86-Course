# Стандарт учебных глав и самостоятельного контура

Эта страница фиксирует требования, которые не дают курсу превратиться в набор конспектов. Глава должна объяснять модель, а внешний самостоятельный контур — проверять перенос, удержание и исправление ошибок.

## Три режима использования главы

| Режим | Наблюдаемый результат |
|---|---|
| Первое чтение | ученик строит минимальную модель и проходит worked example |
| Решение задачи | ученик быстро находит паттерн, инвариант и типовую ошибку |
| Повторение | ученик восстанавливает правило и состояние без полного перечитывания |

Главная последовательность главы:

```text
правило → схема состояния → шаблон → пример → ошибка → практика
```

Главная последовательность курса:

```text
глава → transfer → ключ/диагностика → отложенное повторение → checkpoint
```

## Обязательная структура `day_XX.md`

```md
# День XX. Название

## Входные знания
- конкретные действия;
- кликабельный маршрут возврата.

## За 30 секунд
- 4–7 главных тезисов.

## Минимум после главы
Ты должен уметь:
- наблюдаемое действие;

Можно пока не заучивать:
- явные non-goals.

## Главная схема

## Базовый шаблон

## Сквозной или подробно разобранный пример

## Почему это работает

## Типовые ошибки

## Практика
- минимум два разных действия.

## Чеклист
- только наблюдаемые действия.
```

## Что проверяется внутри главы, а что снаружи

Не нужно механически помещать четыре одинаковых упражнения в каждую главу.

Внутри главы достаточно минимум двух форм практики, подходящих теме. Но полный курс обязан закрыть пять независимых действий:

```text
trace
заполнить пропуски
написать с нуля
найти баг
перенести на новую форму
```

- первые четыре могут распределяться между главой и checkpoint;
- `transfer` всегда находится в [рабочей тетради](/transfer_workbook);
- ответы на transfer отделены в [ключи](/transfer_keys);
- checkpoint оценивает навыки отдельно, а не скрывает их в одном балле.

## Правило наблюдаемых целей

Плохо:

```text
понимать CDECL
знать флаги
разобраться с x87
```

Хорошо:

```text
нарисовать frame и подписать [ebp+8], [ebp+4], [ebp-4]
для заданного add определить CF/OF и объяснить интерпретацию
протрассировать st(0..), сохранить qword и восстановить esp
```

Чеклист не должен использовать «понимаю», если рядом нельзя назвать проверяемое действие.

## Правило входных знаний

Prerequisite — не название темы, а действие.

Плохо:

```text
знать память
```

Хорошо:

```text
без подсказки отличить адрес метки от значения по адресу и написать одну загрузку/запись
```

Если prerequisite не выполнен, должна быть точная ссылка на главу или checkpoint, который закрывает пробел.

## Правило визуального состояния

Для низкоуровневой темы сначала показывается состояние, затем формализация:

| Тема | Первая модель |
|---|---|
| инструкции | регистры и изменяемый destination |
| память | адреса и байты |
| флаги | операция → текущие flags → consumer |
| control flow | метки и переходы |
| стек | адреса, `esp`, return address |
| CDECL | frame layout и ответственность caller/callee |
| x87 | глубина и `st(0..)` после каждого шага |
| object model | object → offsets → vptr/table/indirect call |

## Правило технического паттерна

Каждый важный паттерн имеет четыре слоя:

1. C/C++-смысл;
2. low-level shape;
3. NASM-код;
4. типовой контрпример или ошибка.

Например:

```cpp
answer = a + b;
```

```text
load a → add b → preserve/print result
```

```asm
mov eax, [a]
add eax, [b]
```

Ошибка:

```asm
mov eax, a ; адрес вместо значения
```

## Правило спирального повторения

Если ранняя глава использует рабочий ритуал, поздняя обязана назвать новый закрываемый вопрос.

| Раньше | Позже |
|---|---|
| `push` аргументов и `add esp,N` | точный CDECL и frame layout |
| адресная формула массива | offsets структур и object layout |
| floating-point числа | x87 как механизм вычисления |

Повтор без новой причинной модели не считается спиральным обучением.

## Правило transfer

Transfer-задача обязана менять хотя бы один существенный признак:

- числа и границы;
- направление перевода C ↔ NASM;
- форму control flow;
- расположение данных;
- комбинацию двух ранее изученных навыков;
- ошибочный вариант вместо правильного примера.

Прямое воспроизведение `(a+b)*c` после разбора `(a+b)*c` — практика памяти, но не transfer.

## Правило ключей

Ключ должен содержать:

- обязательные свойства ответа;
- критический инвариант;
- типовую неправильную модель;
- минимальный контрпример;
- маршрут повторения.

Один готовый листинг без диагностики недостаточен для самостоятельного курса.

## Правило checkpoints

Checkpoint:

- проверяет только уже пройденный материал;
- оценивает навыки отдельно;
- имеет прозрачную рубрику `0/1/2`;
- объявляет критические навыки;
- содержит transfer;
- имеет отдельный ключ;
- блокирует переход при нуле по центральному инварианту.

Нельзя проверять `x/[x]` до главы, где эта модель введена, или объединять несвязанные FP/x87/safety навыки в один непрозрачный балл.

## Правило AI-наставника

AI — дополнительный интерфейс, а не владелец фактов курса. Готовый prompt pack обязан:

- не выдавать решение до законченной попытки;
- задавать один вопрос за раз;
- опираться на присланный текст главы и наблюдаемое состояние;
- называть нарушенный инвариант;
- отделять подтверждённый смысл от гипотезы;
- не смешивать IA-32 и x86-64;
- поддерживать режимы обучения, зачёта, диагностики и code review.

Каноническая страница: [AI-наставник](/ai_tutor_prompts).

## Definition of done для главы

Глава готова, если:

- обязательные level-2 разделы существуют и идут в правильном порядке;
- prerequisite кликабелен и операционален;
- есть схема состояния или точная таблица;
- есть хотя бы один подробно разобранный пример;
- есть типовые ошибки;
- есть минимум два наблюдаемых задания;
- чеклист содержит минимум три действия;
- соответствующее transfer-задание и ключ существуют;
- глава покрыта ближайшим checkpoint;
- ссылки и примеры проходят автоматическую проверку.

Definition of done для самостоятельного курса:

- все 25 дней имеют transfer и ключ;
- существуют 6 checkpoints и отдельные рубрики;
- День 10 разбит на сессии;
- есть интервальное повторение и журнал ошибок;
- есть model-agnostic prompt pack;
- документация собирается, ссылки разрешаются, примеры и валидаторы проходят.
