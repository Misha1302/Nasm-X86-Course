# Правила устройства курса

Этот документ фиксирует требования к главам, новым задачам, контрольным точкам, ИИ-наставнику и автоматически создаваемым страницам.

## Общий учебный цикл

```text
глава → новая задача → диагностический ключ → исправление → новый вариант
                                 ↓
                          контрольная точка
                                 ↓
                         отложенное повторение
```

Документация и проверяющие скрипты должны поддерживать именно этот цикл.

## Обязательные разделы главы

Каждая глава `day_XX.md` содержит:

1. `## Входные знания`;
2. `## За 30 секунд`;
3. `## Минимум после главы`;
4. объяснение новой модели;
5. разобранный пример;
6. `## Практика`;
7. `## Чеклист`;
8. `## Следующий шаг`.

Заголовки должны находиться вне блоков кода. В главе должен быть ровно один заголовок первого уровня.

## Входные знания

Входные знания должны проверяться действием. Плохо:

```text
знать стек
```

Хорошо:

```text
нарисовать кадр стека и подписать [ebp+4], [ebp+8], [ebp-4]
```

Если ученик не выполняет действие, раздел указывает точную страницу для возврата.

## Модель состояния

Глава должна явно отвечать на вопросы:

- какие объекты существуют;
- где они хранятся;
- какая инструкция меняет состояние;
- какой инвариант должен сохраняться;
- какая ошибка нарушает этот инвариант.

Примеры объектов:

| Тема | Объекты состояния |
|---|---|
| регистры | `eax`, `ax`, `ah`, `al` |
| память | адреса, байты и размеры |
| флаги | `ZF`, `SF`, `CF`, `OF` и последняя изменившая их инструкция |
| стек | адреса, `esp`, адрес возврата |
| CDECL | кадр стека и ответственность вызывающей и вызываемой функций |
| x87 | `st(0..7)` и глубина стека |
| объекты C++ | факты машинного кода и гипотеза об ABI |

## Объяснение

Сначала вводится короткая модель, затем один минимальный разобранный пример. Новое правило не должно впервые появляться в контрольной точке или ключе.

Если тема зависит от среды, укажи поддерживаемую среду и способ её проверить. Если расположение зависит от ABI, это должно быть сказано прямо.

## Практика

Практика внутри главы закрепляет только что разобранный материал. Ответы можно хранить в `<details>`, но самостоятельный маршрут должен предлагать отдельную тетрадь без встроенных ответов.

Прямое повторение примера не считается новой задачей. Новая задача меняет хотя бы один существенный признак:

- числа;
- форму кода;
- направление рассуждения;
- расположение данных;
- граничный случай;
- вид ошибки.

Новая задача не вводит теорию, которой ещё не было в главе.

## Следующий шаг

Раздел содержит точные ссылки:

- на `/transfer_workbook#tr-XX`;
- на `/transfer_keys#key-tr-XX`;
- при необходимости — на ближайшую контрольную точку.

Порядок действий:

1. решить задачу без ключа;
2. сверить результат;
3. записать нарушенный инвариант;
4. решить новый вариант;
5. решить, можно ли идти дальше.

## Контракт новой задачи

У каждой задачи есть постоянный номер `TR-XX`. Тот же номер должен существовать в рабочей тетради и в файле ключей.

Ключ содержит:

- обязательный результат;
- центральный инвариант;
- типовую ошибку;
- контрпример;
- материал для повторения.

Отпечаток условия связывает ключ с текущей версией задачи. Изменение условия без обновления ключа должно отклоняться проверкой.

## Контрольные точки

Каждое задание имеет постоянный номер `CPN-NAME`.

Контрольная точка объявляет:

- максимальный балл;
- проходной балл не ниже 80%;
- критические номера;
- правило перехода дальше.

Ключ зеркально содержит каждый номер задания и новый вариант после ошибки.

### Оценивание 2 / 1 / 0

- `2` — все обязательные элементы верны, итоговые состояния и числа правильны, центральный инвариант объяснён;
- `1` — центральный инвариант верен, но есть одна локальная некритическая ошибка;
- `0` — неверно итоговое состояние, направление операндов, знаковость, адрес и значение, баланс стека либо центральный инвариант.

Несколько независимых ошибок нельзя сворачивать в одну «мелкую неточность».

## Отложенное повторение

Курс различает:

- проверку в той же сессии;
- повторение на следующий день;
- повторение через 3–4 дня;
- повторение через неделю.

Проверка сразу после объяснения не считается интервальным повторением.

## ИИ-наставник

ИИ — дополнительный интерфейс, а не источник истины. Источник истины:

1. точное условие;
2. канонический материал курса;
3. наблюдаемое состояние программы;
4. результат сборки и запуска;
5. явные правила IA-32, NASM и CDECL.

Набор инструкций обязан:

- задавать один вопрос за сообщение;
- не показывать решение до законченной попытки;
- после первой ошибки давать одну подсказку;
- после второй менять способ объяснения;
- после третьей возвращать к недостающему навыку;
- отделять факт машинного кода от гипотезы;
- не смешивать IA-32 и x86-64;
- не называть конкретную модель проверенной без сохранённых запусков.

Поведение модели проверяется по [сценариям](/ai_tutor_eval). До реальных запусков состояние остаётся `NOT_RUN`.

## Автоматически создаваемые страницы

Основные источники хранятся в отдельных файлах. Скрипт создаёт:

- `docs/textbook.md`;
- `docs/course_migration.md`;
- `docs/closed_book_workbook.md`.

Эти файлы не редактируются вручную и не хранятся в Git. Сборка должна заново создать их из точного упорядоченного списка источников.

Показатель `6/6` подтверждает только наличие шести обязательных разделов. Он не доказывает предметную правильность или качество обучения.

## Критерии завершения главы

Глава готова, если:

- входные знания проверяются конкретным действием;
- новая модель и инвариант объяснены до практики;
- есть разобранный пример;
- практика не требует будущего материала;
- новая задача и ключ имеют одинаковый номер;
- ближайшая контрольная точка проверяет центральные навыки;
- ссылки, якоря и примеры проходят проверяющий скрипт.

## Критерии завершения самостоятельного курса

Курс готов, если:

- 25 номеров задач зеркально совпадают с 25 номерами ключей;
- все ключи диагностичны;
- шесть контрольных точек имеют вычислимые правила оценивания и критические номера;
- задания и ключи контрольных точек зеркальны;
- ИИ-наставник не заявляет больше, чем доказано;
- самодостаточный учебник содержит все учебные слои;
- сборка документации, проверяющий скрипт и исполняемые примеры проходят CI.
