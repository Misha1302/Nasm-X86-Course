# День 07. Почему для `add` нет `iadd`

> **Важно для вызовов libc.** Перед `call` должно выполняться `esp % 16 == 0`. Выравнивающие байты и аргументы вместе должны занимать число байт, кратное 16. Подробности: [C ABI / CDECL](/c_abi) и [выравнивание стека](/patterns/libc_alignment).

## Зачем этот день

В x86 есть пары:

```text
mul  / imul
div  / idiv
```

То есть беззнаковое и знаковое умножение, беззнаковое и знаковое деление.

Но нет пары:

```text
add / iadd
sub / isub
```

На первый взгляд странно. В C++ же есть `int` и `unsigned int`. Почему процессору не нужны разные команды сложения?

Сегодня разберём главное: **знаковая и беззнаковая интерпретации часто читают одни и те же биты по-разному**.

---

## Главная мысль

`add` складывает битовые векторы по модулю `2^w`, где `w` — размер операнда.

Для знаковой и беззнаковой интерпретаций сохранённые биты результата одинаковы.

Разница появляется в интерпретации:

- беззнаковая арифметика смотрит на `CF`;
- знаковая арифметика смотрит на `OF`.

---

## Самый короткий пример

Возьмём 8 бит.

```text
  11111111
+ 00000001
-----------
1 00000000
  ^^^^^^^^ stored result
```

В 8-битный результат сохраняется только:

```text
00000000
```

Теперь читаем это двумя способами.

### Как беззнаковое число

```text
11111111 = 255
00000001 = 1
255 + 1 = 256
256 mod 256 = 0
```

Результат `0`, был перенос за пределы 8 бит. Это важно для `CF`.

### Как знаковое число

```text
11111111 = -1
00000001 = 1
-1 + 1 = 0
```

Результат тоже `0`, и знакового переполнения здесь нет.

Биты результата одинаковые. Поэтому отдельная команда `iadd` не нужна.

---

## Что делает `add`

```asm
add eax, ebx
```

Это значит:

```cpp
eax = eax + ebx;
```

Важно: результат пишется в первый операнд.

До:

```text
eax = 10
ebx = 3
```

После:

```text
eax = 13
ebx = 3
```

`ebx` не меняется.

---

## Команды дня

| Команда | Пример | C++-смысл |
|---|---|---|
| `add` | `add eax, ebx` | `eax += ebx` |
| `sub` | `sub eax, 10` | `eax -= 10` |
| `inc` | `inc eax` | `eax++` |
| `dec` | `dec eax` | `eax--` |
| `neg` | `neg eax` | `eax = -eax` |

Пример:

```asm
mov eax, [a]
add eax, [b]
sub eax, 10
inc eax
dec eax
neg eax
```

Последняя команда:

```asm
neg eax
```

делает:

```text
eax = 0 - eax
```

---

## `inc` и `dec`

```asm
inc eax
```

почти как:

```asm
add eax, 1
```

```asm
dec eax
```

почти как:

```asm
sub eax, 1
```

Но есть тонкость: `inc/dec` не меняют `CF`, а `add/sub` меняют. Для первых задач это редко критично, но на уровне флагов это важно помнить.

Если не уверен, используй `add/sub`: они проще для рассуждений о флагах.

---

## `neg`: как получить минус

```asm
neg eax
```

Если:

```text
eax = 5
```

после `neg`:

```text
eax = -5
```

На уровне битов это дополнительный код:

```text
-x = ~x + 1
```

Например в 8 битах:

```text
5      = 00000101
~5     = 11111010
~5 + 1 = 11111011 = -5
```

---

## Флаги: пока только главное

После арифметики процессор обновляет флаги.

| Флаг | Смысл |
|---|---|
| `CF` | перенос или заём в беззнаковой арифметике |
| `OF` | переполнение в знаковой арифметике |
| `ZF` | результат равен нулю |
| `SF` | старший бит результата |

### `CF`: перенос в беззнаковой арифметике

8-битно:

```text
255 + 1 -> 0, CF = 1
```

Потому что беззнаковый результат не поместился в 8 бит.

### `OF`: знаковое переполнение

Диапазон 8-битного знакового числа:

```text
-128..127
```

```text
127 + 1 -> -128 по битам, OF = 1
```

Битовый результат существует, но как результат знаковой арифметики он неверен.

---

## Почему для деления есть `div/idiv`

Для сложения битовый результат совпадает.

Но для деления уже нет.

Один и тот же набор битов:

```text
0xFFFFFFFF
```

может означать:

```text
unsigned: 4294967295
signed:   -1
```

Теперь делим на 3:

```text
4294967295 / 3 = 1431655765
-1 / 3 = 0    ; в C-подобном целочисленном делении к нулю
```

Это совсем разные результаты. Поэтому у деления есть разные команды:

```asm
div   ; unsigned
idiv  ; signed
```

Умножение тоже имеет знаковую и беззнаковую формы, особенно когда нужен полный расширенный результат.

## Маленькая программа: `a - b`

```asm
section .data
    fmtIn db "%d", 0
    fmtOut db "%d", 10, 0

section .bss
    a resd 1
    b resd 1

section .text
    extern scanf
    extern printf
    global main

main:
    push ebp
    mov ebp, esp
    and esp, -16
    sub esp, 8       ; padding: 8 + 8 argument bytes = 16
    push a
    push fmtIn
    call scanf
    add esp, 16

    sub esp, 8       ; padding: 8 + 8 argument bytes = 16
    push b
    push fmtIn
    call scanf
    add esp, 16

    mov eax, [a]
    sub eax, [b]

    sub esp, 8       ; padding: 8 + 8 argument bytes = 16
    push eax
    push fmtOut
    call printf
    add esp, 16

    mov esp, ebp
    pop ebp
    xor eax, eax
    ret
```

Главные строки:

```asm
mov eax, [a]
sub eax, [b]
```

Это:

```cpp
answer = a - b;
```

## Практика
### 1. `127 + 1` в 8 битах

Какие биты получатся? Каково знаковое значение?

<details>
<summary>Ответ</summary>

```text
01111111 + 00000001 = 10000000
```

В 8-битной знаковой интерпретации это `-128`, хотя математический результат равен `128`. Значит, произошло знаковое переполнение: `OF = 1`.

</details>

### 2. `255 + 1` в 8 битах

Что получится?

<details>
<summary>Ответ</summary>

```text
11111111 + 00000001 = 1 00000000
```

Сохраняется `00000000`, а перенос фиксируется в `CF = 1`.

</details>

### 3. Почему нет `iadd`?

Скажи одной фразой.

<details>
<summary>Ответ</summary>

Потому что сохранённые биты суммы одинаковы; различается только трактовка флагов.

</details>

### 4. Что меняет `add eax, ebx`?

<details>
<summary>Ответ</summary>

Меняет `eax` и флаги. `ebx` не меняется.

</details>

### 5. Что делает `neg eax`?

<details>
<summary>Ответ</summary>

Делает `eax = -eax`, то есть `0 - eax`.

</details>

## Типовые ошибки

| Ошибка | Почему плохо |
|---|---|
| думать, что знаковое и беззнаковое числа имеют разные биты | различается только интерпретация |
| путать `CF` и `OF` | `CF` нужен для беззнаковой, `OF` — для знаковой арифметики |
| читать `add eax, ebx` как чистое выражение | это `eax += ebx`, `eax` меняется |
| забывать, что `inc/dec` имеют особенность с `CF` | иногда лучше использовать `add/sub` |
| считать `neg` магическим | это дополнительный код: `~x + 1` |
