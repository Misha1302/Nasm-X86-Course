# Как пройти курс самостоятельно

Самостоятельность здесь означает не отсутствие помощи, а отсутствие скрытых пробелов: для каждого шага известно, что проверить, куда вернуться и чем доказать исправление ошибки.

Перед стартом выполни [входную диагностику](/prerequisites). Незнакомые слова проверяй по [глоссарию](/glossary).

## Цикл одной главы

### 1. Проверить входные знания

Выполни действия из раздела `Входные знания`. Не отмечай пункт по ощущению.

### 2. Прочитать короткую модель

После первого чтения закрой текст и ответь:

```text
какие объекты существуют;
где они находятся;
что меняет каждая инструкция;
какое условие должно сохраниться.
```

Последнее условие называется **инвариантом**. Например: после законченного внешнего вызова `esp` должен вернуться к ожидаемому значению.

### 3. Протрассировать пример

Запиши начальное и конечное состояние регистров, памяти, флагов или стека. Если промежуточный шаг приходится угадывать, вернись к соответствующему абзацу.

### 4. Выполнить практику

Сначала реши задания без раскрытия `<details>`. Ответ считается готовым, если можно показать вычисления или состояние машины, а не только назвать итог.

### 5. Решить новую задачу

Перейди в [рабочую тетрадь](/transfer_workbook) к `TR-XX`. Не открывай [диагностический ключ](/transfer_keys), пока попытка не закончена.

### 6. Диагностировать ошибку

После сравнения запиши:

- первую строку, где твоя модель разошлась с машиной;
- нарушенный инвариант;
- минимальный контрпример;
- страницу для повторения.

### 7. Закрыть пробел новым вариантом

Исправленный старый ответ не доказывает, что модель изменилась. Реши новый вариант с другими числами, формой кода или направлением рассуждения.

## Решение о переходе дальше

Переходи к следующей главе, если без подсказки можешь:

1. воспроизвести главную схему;
2. протрассировать минимальный пример;
3. решить `TR-XX`;
4. объяснить центральный инвариант;
5. разрушить типовую ошибку контрпримером.

Если верен только итог, но неверна трассировка, тема не закрыта.

## Интервальное повторение

Проверка сразу после чтения измеряет кратковременное узнавание. Курс использует четыре момента:

| Когда | Что сделать |
|---|---|
| В той же сессии | практика и `TR-XX` |
| На следующий день | воспроизвести схему и решить короткий вариант |
| Через 3–4 дня | смешать тему с одной соседней |
| Через неделю | решить задание без подсказки и справочника |

Повторение занимает 5–15 минут. Если появляется прежняя ошибка, снова записывается инвариант и новый контрпример.

## Контрольные точки

После каждого блока пройди [контрольную точку](/checkpoints) целиком без глав и ключей. Затем используй [критерии оценивания и варианты](/checkpoint_keys).

Переход разрешён только когда:

- набран проходной балл;
- ни одно критическое задание не получило `0`;
- задания с баллом `1` закрыты новым вариантом.

## Примеры границы 2 / 1 / 0

### Пример A

Ученик правильно вычислил `eax`, но написал, что `mov al, 0` изменил весь регистр.

```text
Балл: 0
Причина: центральная модель перекрывающихся регистров неверна.
```

### Пример B

Состояния регистров верны, но в одном шестнадцатеричном числе допущена локальная описка, которая не влияет на объяснение.

```text
Балл: 1
Причина: модель верна, есть одна локальная ошибка.
```

### Пример C

Итог, промежуточные состояния и инвариант верны.

```text
Балл: 2
```

Красивый текст не компенсирует неверное состояние машины. Верное число без обязательного механизма не получает `2`.

## Журнал ошибок

| Дата | ID | Моя первая неверная строка | Инвариант | Контрпример | Что повторил | Новый вариант закрыт |
|---|---|---|---|---|---|---|
| | | | | | | |

Записывай не «невнимательность», а переносимое правило. Например:

```text
Неверно: после idiv делимым был только eax.
Инвариант: 32-битный idiv делит пару edx:eax.
Контрпример: одинаковый eax при edx=0 и edx=FFFFFFFF задаёт разные делимые.
```

## День 10

Не проходи День 10 одной сессией. Используй [отдельный маршрут](/day_10_learning_path) и переходи дальше только после мини-проверки каждого занятия.

[ИИ-наставник](/ai_tutor_prompts) может задавать вопросы и давать подсказки, но каноническими источниками остаются условие, материал курса и наблюдаемое состояние программы. Сценарии проверки находятся на странице [Проверка ИИ-наставника](/ai_tutor_eval).
