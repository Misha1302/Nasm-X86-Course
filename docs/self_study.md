# Как пройти курс самостоятельно

Эта страница — основной маршрут без преподавателя. Главы объясняют материал, [рабочая тетрадь](/transfer_workbook) проверяет перенос на новые задачи, [диагностические ключи](/transfer_keys) помогают найти сломанную модель, а [контрольные точки](/checkpoints) решают, можно ли идти дальше.

## Что считается самостоятельным прохождением

Глава закрыта не после чтения, а когда ты без подсказки можешь:

1. восстановить главную модель на бумаге;
2. решить соответствующую задачу `TR-XX`;
3. проверить себя по зеркальному ключу с тем же ID;
4. назвать нарушенный инвариант и минимальный контрпример;
5. через день выполнить короткое воспроизведение без перечитывания главы.

Фраза «вроде понятно» не является результатом.

## Цикл одной главы

### Шаг 1. Входной тест — 3 минуты

Открой `Входные знания` и попробуй выполнить перечисленные действия. Если одно не получается, перейди по указанной ссылке назад. Не начинай новую тему на сломанной модели.

### Шаг 2. Первое чтение — 15–35 минут

1. Прочитай `За 30 секунд`.
2. Нарисуй главную схему состояния.
3. Разбери worked example руками.
4. Закрой объяснение и перескажи механизм своими словами.
5. Выполни практику главы.

Не открывай ответы до законченной попытки. Для режима без технической возможности случайно раскрыть `<details>` используй [closed-book workbook](/closed_book_workbook).

### Шаг 3. Следующий шаг — 10–25 минут

В конце каждого `day_XX.md` находится блок `Следующий шаг` с двумя точными ссылками:

- `TR-XX` в [рабочей тетради](/transfer_workbook);
- `TR-XX` в [диагностических ключах](/transfer_keys).

Задача специально отличается от примера главы. Сначала реши её полностью, затем проверь обязательный результат, инвариант, типовую ошибку, контрпример и маршрут повторения.

### Шаг 4. Решение о переходе

| Результат | Что делать |
|---|---|
| Решение верно и каждый шаг объяснён | перейти к следующей главе |
| Одна локальная ошибка, модель верна | исправить и решить новый вариант |
| Нарушен центральный инвариант | вернуться к указанному prerequisite |
| Решение появилось только после просмотра ключа | повторить новый вариант на следующий день |

Центральные инварианты курса: `x/[x]`, размер операнда, signed/unsigned, владелец flags, `edx:eax`, границы массива, баланс `esp`, CDECL, глубина x87-стека и размер variadic-аргумента.

## Контрольные точки

После блоков проходи [контрольные точки](/checkpoints):

| После | Контрольная точка |
|---|---|
| Дня 04 | Checkpoint 1 — инструкции, регистры, размеры |
| Дня 10 | Checkpoint 2 — память, libc, деление, биты |
| Дня 15 | Checkpoint 3 — flags, control flow, jump table, адресация |
| Дня 19 | Checkpoint 4 — stack, CDECL, reverse, структуры |
| Дня 23 | Checkpoint 5 — startup, safety, floating point, x87 |
| Дня 24 | Checkpoint 6 — C++ object model |

Каждое задание имеет стабильный `CP`-ID и оценивается отдельно:

- `2` — полный правильный ответ с инвариантом;
- `1` — центральная модель верна, есть одна локальная ошибка;
- `0` — модель неверна или обязательный элемент отсутствует.

У checkpoint есть явные максимум, проходной балл и критические ID. Переход разрешён только при достижении порога и отсутствии нуля по критическому ID. После `1` реши дополнительный вариант из [зеркальных ключей](/checkpoint_keys); после `0` сначала повтори prerequisite.

## Интервальное повторение

После каждой главы запланируй три коротких возврата:

| Когда | Что сделать |
|---|---|
| На следующий день | один вопрос из чеклиста и один trace без конспекта |
| Через 3–4 дня | смешанное задание из прошлой главы |
| Через 7 дней | объяснить модель вслух и исправить ошибочный listing |

Проверка в конце одной и той же сессии — retrieval practice, но не настоящее spaced repetition.

## Журнал ошибок

Копируй одну строку после каждой существенной ошибки:

| Дата | ID | Мой ответ | Нарушенный инвариант | Минимальный контрпример | Что повторить | Вариант закрыт |
|---|---|---|---|---|---|---|
| | | | | | | |

Плохая запись: `ошибся в стеке`.

Хорошая запись: `CP4-STACK: после call считал [esp] первым аргументом; забыл return address; контрпример — push b, push a, call sum; повторить День 16; вариант закрыть завтра`.

## День 10 — пять отдельных занятий

Не пытайся пройти весь branchless-блок за один подход. Используй [маршрут Дня 10](/day_10_learning_path): `10A` masked merge, `10B` маска `0/-1`, `10C` ceil/division, `10D` задачи 01-14/01-15, `10E` challenge 01-16.

## Финальная готовность

Перед [mock exam](/day_25):

1. все шесть checkpoints закрыты без нулей по критическим ID;
2. минимум 20 из 25 `TR-XX` решены до просмотра ключа;
3. последние ошибки имеют выполненный новый вариант;
4. можешь собрать и отладить программу в одной из [поддерживаемых сред](/support_matrix).

## Обучение вместе с нейросетью

Курс остаётся самостоятельным, но его можно проходить с [AI-наставником](/ai_tutor_prompts). Промпты поддерживают guided learning, strict exam, confusion recovery, solution review и compact mode для небольшого context window.

Конкретная модель не считается проверенной по одному названию. Текущий evidence status и 10 поведенческих кейсов находятся на странице [Проверка AI-наставника](/ai_tutor_eval). Пока live ChatGPT/DeepSeek runs не сохранены, статус — `STRUCTURALLY_VALID`, но не `BEHAVIORALLY_VERIFIED`.

Нейросеть не является источником истины. Канонические источники — условие, глава, реально собранный код, состояние машины и ключи.
