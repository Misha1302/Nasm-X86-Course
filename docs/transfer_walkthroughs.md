## TR-13: `continue`, `break` и шаг цикла

### Направляющий вопрос

Куда должен вести `continue` в цикле `for`: сразу к проверке или сначала к изменению счётчика?

### Эталонная форма управления

Исходный код:

```cpp
for (int i=0; i<n; ++i) {
    if (a[i] < 0) continue;
    if (a[i] == 0) break;
    sum += a[i];
}
```

Блоки:

```text
init → check → load → negative?
                  ├─ yes → step
                  └─ no  → zero?
                            ├─ yes → end
                            └─ no  → add → step
step → check
```

Один из вариантов NASM:

```asm
xor ecx, ecx              ; i = 0

.check:
    cmp ecx, [n]
    jae .end

    mov eax, [a + 4*ecx]
    test eax, eax
    js .step               ; continue
    jz .end                ; break

    add [sum], eax

.step:
    inc ecx
    jmp .check

.end:
```

### Где обычно появляется первая ошибка

Если отрицательный первый элемент приводит к бесконечному циклу, проверь путь `continue`: счётчик обязан пройти через `.step`.

### Новый вариант

Измени условие: пропускать чётные элементы, завершаться на отрицательном, остальные прибавлять.

## TR-17: полная функция и кадр

### Направляющий вопрос

`[ebp+16]` хранит данные результата или адрес, по которому нужно записать результат?

### Требуемая функция

```c
int store_sum(int a, int b, int* out);
```

Карта после пролога:

```text
[ebp+16]  out
[ebp+12]  b
[ebp+8]   a
[ebp+4]   return address
[ebp]     old ebp
```

Полный вариант:

```asm
store_sum:
    push ebp
    mov ebp, esp
    push ebx

    mov eax, [ebp+8]
    add eax, [ebp+12]

    mov ebx, [ebp+16]
    mov [ebx], eax

    pop ebx
    mov esp, ebp
    pop ebp
    ret
```

Пошаговое состояние:

| Шаг | `eax` | `ebx` | Память |
|---|---|---|---|
| загрузка `a` | `a` | старое значение | без изменений |
| сложение `b` | `a+b` | старое значение | без изменений |
| загрузка `out` | `a+b` | адрес результата | без изменений |
| запись | `a+b` | адрес результата | `*out=a+b` |

### Где обычно появляется первая ошибка

- `mov [ebp+16],eax` перезаписывает сам аргумент-указатель;
- отсутствие `pop ebx` нарушает контракт;
- `ret` до восстановления кадра использует неверную вершину.

### Новый вариант

Напиши `int store_diff(int a,int b,int* out)` с теми же правилами сохранения.

## TR-23: x87 и два независимых стека

### Направляющий вопрос

После каждой инструкции отдельно записывай:

1. содержимое `st(0..)`;
2. глубину x87;
3. изменение обычного `esp`, если оно было.

### Выражение

```text
(a-b)/(c+d)
```

Последовательность:

```asm
fld qword [a]
fld qword [b]
fsubp st1, st0
fld qword [c]
fld qword [d]
faddp st1, st0
fdivp st1, st0
```

Трассировка x87:

| После инструкции | `st(0)` | `st(1)` | `st(2)` | Глубина |
|---|---|---|---|---:|
| `fld a` | `a` | — | — | 1 |
| `fld b` | `b` | `a` | — | 2 |
| `fsubp` | `a-b` | — | — | 1 |
| `fld c` | `c` | `a-b` | — | 2 |
| `fld d` | `d` | `c` | `a-b` | 3 |
| `faddp` | `c+d` | `a-b` | — | 2 |
| `fdivp` | `(a-b)/(c+d)` | — | — | 1 |

Передача в `printf` из выровненного участка:

```asm
sub esp, 12
fstp qword [esp]
push fmt
call printf
add esp, 16
```

После `fstp` глубина x87 возвращается к нулю. Обычный стек восстановлен после `add esp,16`.

### Проверка числами

```text
a=10, b=4, c=1, d=2
result = 6/3 = 2
```

### Где обычно появляется первая ошибка

- обратный порядок `fsubp` или `fdivp`;
- лишнее значение в x87;
- `dword` вместо `qword` для `%f`;
- очистка 12 вместо 16 байт.

### Новый вариант

Протрассируй `(a+b)/(c-d)` на несимметричных числах.
