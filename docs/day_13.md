## За 30 секунд

- Процессор не знает `if`, `while` и `for`: он видит метки, проверки и переходы.
- Условие обычно строится как переход мимо тела или переход к нужной ветке.

## Зачем этот день

В C++ у тебя есть красивые конструкции:

```cpp
if
while
for
do while
break
continue
```

В asm их нет.

И это не значит, что asm “бедный”. Просто процессору достаточно более простых вещей:

```text
метка
условный переход
безусловный переход
```

Сегодня мы учимся видеть за C++-конструкциями обычную GOTO-форму и не терять при переводе тип данных.

---

## Главная мысль

Управляющие конструкции C/C++ раскладываются в:

```asm
cmp / test
jcc
jmp
labels
```

То есть:

```text
условие -> флаги -> переход -> метка
```

Но форма CFG не определяет семантику операции над данными. Отдельно нужно сохранить signedness, размер и смысл каждого шага.

---

## 1. Метки и `jmp`

Метка — это имя адреса в коде.

```asm
.loop:
    ; some code
    jmp .loop
```

`jmp` — безусловный переход.

```asm
jmp .end
```

значит:

```text
следующая инструкция будет по адресу .end
```

В C++ это ближе всего к:

```cpp
goto end;
```

---

## 2. Простой `if`

C++:

```cpp
if (x == 0) {
    y = 1;
}
```

Схема на ассемблере:

```asm
mov eax, [x]
test eax, eax
jne .skip

mov dword [y], 1

.skip:
```

Почему `jne .skip`?

Мы хотим выполнить тело только если `x == 0`.

Значит, если `x != 0`, надо перепрыгнуть через тело.

```text
if not condition -> jump over body
body
skip:
```

Это очень частая форма.

---

## 3. `if/else`

C++:

```cpp
if (x > y) {
    result = x - y;
} else {
    result = y - x;
}
```

Схема на ассемблере:

```asm
mov eax, [x]
cmp eax, [y]
jle .else

.then:
    mov eax, [x]
    sub eax, [y]
    mov [result], eax
    jmp .end

.else:
    mov eax, [y]
    sub eax, [x]
    mov [result], eax

.end:
```

Главный трюк:

```asm
jmp .end
```

после then-ветки.

Если его забыть, выполнение “провалится” в else, и else тоже выполнится.

---

### Почему иногда прыгают по обратному условию

В C++:

```cpp
if (x > y) {
    then_body;
}
```

В asm часто пишут:

```asm
cmp x, y
jle .skip
; then_body
.skip:
```

То есть если условие не выполнено, прыгаем через тело.

Это нормально. Не пытайся искать дословное `jg`, если в коде может быть `jle`.

---

## 4. `while`

Для логического сдвига зададим беззнаковый тип явно:

```cpp
uint32_t x;
while (x != 0) {
    x >>= 1;
}
```

Схема на ассемблере:

```asm
.loop:
    test eax, eax
    je .end

    shr eax, 1
    jmp .loop

.end:
```

Структура:

```text
.loop:
    проверить условие
    если условие ложное -> .end
    тело
    jmp .loop
.end:
```

Здесь `uint32_t` и `shr` согласованы: сверху добавляются нули, и любое ненулевое значение максимум через 32 шага станет нулём.

Нельзя без оговорки заменить `uint32_t` на `int32_t`. Для отрицательного signed-значения `x >>= 1` имеет другой языковой контракт, а `sar` может сохранять единицы сверху и не привести `-1` к нулю.

---

## 5. `do while`

C++:

```cpp
uint32_t x;
do {
    x >>= 1;
} while (x != 0);
```

Схема на ассемблере:

```asm
.loop:
    shr eax, 1
    test eax, eax
    jne .loop
```

Отличие от `while`:

```text
while    -> сначала проверка, потом тело
do while -> сначала тело, потом проверка
```

Поэтому `do while` всегда выполняет тело хотя бы один раз.

---

## 6. `for`

C++:

```cpp
for (int i = 0; i < n; ++i) {
    sum += i;
}
```

GOTO-форма:

```cpp
i = 0;
goto check;

loop:
    sum += i;
    ++i;

check:
    if (i < n) goto loop;
```

Схема на ассемблере:

```asm
xor ecx, ecx        ; i = 0
xor eax, eax        ; sum = 0

.check:
    cmp ecx, [n]
    jge .end

    add eax, ecx
    inc ecx
    jmp .check

.end:
```

Здесь:

```text
ecx = i
eax = sum
```

---

## 7. `break` и `continue`

C++:

```cpp
while (...) {
    if (bad) break;
    if (skip) continue;
    body;
}
```

ASM-идея:

```asm
.loop:
    ; check loop condition
    je .end

    ; if bad -> break
    cmp ...
    je .end

    ; if skip -> continue
    cmp ...
    je .loop

    ; body
    jmp .loop

.end:
```

`break` — это `jmp` на конец цикла.

`continue` — это `jmp` на проверку или следующую итерацию.

## 8. Popcount-пример

Задача: посчитать количество единичных битов 32-битного беззнакового числа.

C++:

```cpp
uint32_t x;
unsigned result = 0;
while (x != 0) {
    result += x & 1u;
    x >>= 1;
}
```

ASM:

```asm
xor ecx, ecx        ; result = 0

.loop:
    test edx, edx   ; x == 0?
    je .end

    mov eax, edx
    and eax, 1
    add ecx, eax

    shr edx, 1
    jmp .loop

.end:
```

Роли регистров:

```text
edx = uint32_t x
ecx = result
eax = temporary x & 1
```

Разбор одной итерации:

```asm
mov eax, edx  ; скопировали битовый вектор x
and eax, 1    ; оставили младший бит
add ecx, eax  ; прибавили его к result
shr edx, 1    ; логический unsigned-сдвиг x >>= 1
```

Проверь крайние входы:

```text
x = 0x80000000 → result = 1
x = 0xFFFFFFFF → result = 32
```

Эти тесты ловят ошибку, когда код или объяснение случайно смешивает логический `shr` со знаковым значением.

## 9. Как читать чужой asm с циклами

Смотри не на конкретные имена меток, а на форму.

### Признак `while`

```asm
.loop:
    check
    jump_to_end_if_false
    body
    jmp .loop
.end:
```

### Признак `do while`

```asm
.loop:
    body
    check
    jump_to_loop_if_true
```

### Признак `if/else`

```asm
    check
    jump_to_else_if_false
.then:
    then_body
    jmp end
.else:
    else_body
.end:
```

Форма управления не сообщает, является ли значение signed или unsigned. Это восстанавливается по операциям, переходам и контексту типов.

## Практика

#### 1. Перепиши `if/else`

C++:

```cpp
if (x == 0)
    y = 1;
else
    y = 2;
```

Напиши GOTO-форму.

<details>
<summary>Один вариант</summary>

```asm
mov eax, [x]
test eax, eax
jne .else

mov dword [y], 1
jmp .end

.else:
mov dword [y], 2

.end:
```

</details>

#### 2. `while (x > 0) x--;`

<details>
<summary>Один вариант</summary>

```asm
.loop:
    cmp dword [x], 0
    jle .end
    dec dword [x]
    jmp .loop
.end:
```

</details>

#### 3. Сумма от 1 до n

Напиши идею цикла.

<details>
<summary>Один вариант</summary>

```asm
mov ecx, 1      ; i
xor eax, eax    ; sum

.loop:
    cmp ecx, [n]
    jg .end
    add eax, ecx
    inc ecx
    jmp .loop
.end:
```

</details>

#### 4. Узнай форму

```asm
.loop:
    shr eax, 1
    test eax, eax
    jne .loop
```

Это больше похоже на `while` или `do while`? Какой тип значения согласован с `shr`?

<details>
<summary>Ответ</summary>

На `do while`, потому что тело выполняется до проверки. Без дополнительного контекста безопасная C++-модель для этого шага — беззнаковый битовый вектор, например `uint32_t`.

</details>

#### 5. Контрпример signedness

Почему C++-фрагмент с `int32_t x = -1; while (x != 0) x >>= 1;` нельзя объявить эквивалентным приведённому циклу с `shr`?

<details>
<summary>Ответ</summary>

`shr` добавляет нули и быстро приводит `0xFFFFFFFF` к нулю. Знаковый правый сдвиг отрицательного значения имеет другой контракт; арифметическая машинная модель через `sar` для `-1` оставляет `-1`, поэтому цикл не завершается.

</details>

## 11. Типовые ошибки

| Ошибка | Почему плохо |
|---|---|
| забыть `jmp .end` после then-ветки | выполнение провалится в else |
| перепутать условие и обратное условие | тело выполнится не тогда |
| забыть `jmp .loop` в конце while | цикл выполнится один раз |
| поставить проверку не там | `while` превратится в `do while` или наоборот |
| портить регистр-счётчик внутри тела | цикл ломается |
| забыть обновление счётчика | бесконечный цикл |
| переводить signed `x >>= 1` через `shr` без контракта | меняется семантика отрицательных входов |
| использовать `sar` в цикле «до нуля» для `-1` | значение остаётся `-1`, цикл не завершается |
