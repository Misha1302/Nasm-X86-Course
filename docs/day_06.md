Перед началом выполни три действия:

- для `x dd 17` объясни разницу `x` и `[x]`;
- переведи `mov eax,[a]; sub eax,[b]` в C-подобную запись;
- назови размер одного `dword`.

Если один из пунктов не получается, вернись к [Дню 05](/day_05).

## За 30 секунд

- `scanf` получает адрес места, куда запишет значение.
- `printf` получает само значение.
- В используемом CDECL аргументы кладутся справа налево.
- Один `push` в IA-32 уменьшает `esp` на 4 байта.
- Перед внешним `call` в принятом шаблоне выполняется `esp % 16 == 0`.
- После вызова вызывающая функция удаляет **всю область вызова**: выравнивающие байты и аргументы.
- `eax`, `ecx`, `edx` после внешнего вызова могут измениться.

## Минимум после главы

После главы ты должен уметь:

- записать аргументы `scanf` и `printf` в правильном порядке;
- отличить адрес от значения при вводе и выводе;
- посчитать размер аргументов и выравнивающих байтов;
- показать изменение `esp` до внешнего вызова и после очистки;
- не использовать значение из `eax/ecx/edx`, рассчитывая, что libc его сохранила.

Полная механика `call`, `ret` и кадра функции будет разобрана в [Дне 16](/day_16) и [Дне 17](/day_17). Здесь вводится только минимальная и достаточная модель **области одного внешнего вызова**.

## Минимальная модель области вызова

Для этой главы достаточно четырёх правил.

### Правило 1. `esp` указывает на вершину обычного стека

```asm
push eax
```

в IA-32 выполняет учебную модель:

```text
esp = esp - 4
[esp] = eax
```

### Правило 2. Аргументы кладутся справа налево

C:

```c
printf("%d\n", x);
```

Логические аргументы:

```text
первый: адрес строки формата
второй: значение x
```

На стек они кладутся в обратном порядке:

```asm
push dword [x]
push fmtOut
```

### Правило 3. Перед внешним вызовом нужен выровненный `esp`

В полном шаблоне этой главы тело `main` сначала приводит `esp` к границе 16 байт:

```asm
push ebp
mov ebp, esp
and esp, -16
```

Этот пролог пока рассматривается как инфраструктура. Запоминать его устройство не нужно; нужно уметь проверить область каждого вызова после строки `and esp,-16`.

Перед `call` используем условие:

```text
esp % 16 == 0
```

### Правило 4. После вызова удаляется вся подготовленная область

Если перед вызовом было:

```text
8 байт выравнивания + 8 байт аргументов
```

то после вызова нужно:

```asm
add esp, 16
```

Нельзя удалить только аргументы и оставить выравнивающие байты.

## Как считать область вызова

Пусть сразу перед подготовкой выполняется:

```text
esp % 16 == 0
```

### Два 32-битных аргумента

Аргументы занимают:

```text
2 × 4 = 8 байт
```

Чтобы суммарное изменение до `call` было кратно 16, добавляем 8 байт:

```asm
sub esp, 8
push secondArgument
push firstArgument
call function
add esp, 16
```

Таблица:

| Шаг | Изменение относительно начала | `esp % 16` |
|---|---:|---:|
| начало | `0` | `0` |
| `sub esp,8` | `-8` | `8` |
| первый `push` | `-12` | `4` |
| второй `push` | `-16` | `0` |
| перед `call` | `-16` | `0` |
| `add esp,16` после возврата | `0` | `0` |

### Три 32-битных аргумента

Аргументы занимают 12 байт. Добавляем 4 байта:

```asm
sub esp, 4
push thirdArgument
push secondArgument
push firstArgument
call function
add esp, 16
```

Общее правило:

```text
padding + bytes_of_arguments = ближайшее положительное кратное 16
```

В примерах главы область вызова всегда удаляется одним `add esp, total`.

## `scanf`: передаём адрес

C:

```c
scanf("%d", &x);
```

NASM:

```asm
sub esp, 8
push x
push fmtIn
call scanf
add esp, 16
```

Почему `push x`?

`scanf` должен получить адрес байтов, куда запишет число.

Неверно:

```asm
push dword [x]
```

Это передало бы текущее значение `x` как будто оно является адресом.

---

## `printf`: передаём значение

C:

```c
printf("%d\n", x);
```

NASM:

```asm
sub esp, 8
push dword [x]
push fmtOut
call printf
add esp, 16
```

Почему `[x]`?

Функции нужно число для печати, а не адрес переменной.

Если результат уже находится в регистре:

```asm
sub esp, 8
push eax
push fmtOut
call printf
add esp, 16
```

После возврата старое значение `eax` считать сохранённым нельзя.

## Полный разобранный пример

Программа читает два числа и печатает `a-b`.

```asm
section .data
    fmtIn  db "%d", 0
    fmtOut db "%d", 10, 0

section .bss
    a resd 1
    b resd 1

section .text
    extern scanf
    extern printf
    global main

main:
    push ebp
    mov ebp, esp
    and esp, -16

    ; scanf("%d", &a)
    sub esp, 8
    push a
    push fmtIn
    call scanf
    add esp, 16

    ; scanf("%d", &b)
    sub esp, 8
    push b
    push fmtIn
    call scanf
    add esp, 16

    ; eax = a - b
    mov eax, [a]
    sub eax, [b]

    ; printf("%d\n", eax)
    sub esp, 8
    push eax
    push fmtOut
    call printf
    add esp, 16

    mov esp, ebp
    pop ebp
    xor eax, eax
    ret
```

### Что здесь является учебной целью

Нужно объяснить:

- почему `scanf` получает `a` и `b` без скобок;
- почему `printf` получает `eax` как значение;
- почему аргументы идут справа налево;
- почему каждый вызов занимает 16 байт;
- почему после каждого вызова `esp` возвращается к состоянию перед подготовкой.

### Что пока является инфраструктурой

До Дней 16–17 не требуется самостоятельно выводить:

```asm
push ebp
mov ebp, esp
and esp, -16
...
mov esp, ebp
pop ebp
ret
```

Но инфраструктура не должна быть магической: в поздних главах каждая строка получит точную модель.

Центральный инвариант этой главы:

> Перед внешним `call` выполняется условие выравнивания, а после возврата `esp` восстанавливается удалением всей подготовленной области вызова.

## Регистры после внешнего вызова

По используемому соглашению функция libc может изменить:

```text
eax, ecx, edx
```

Пример ошибки:

```asm
mov eax, [answer]

sub esp, 8
push eax
push fmtOut
call printf
add esp, 16

add eax, 1        ; нельзя рассчитывать на старый answer
```

Если значение нужно после вызова, сохрани его в памяти или в регистре, который по соглашению обязан сохраняться и который ты корректно восстановишь. Полные правила регистров будут в Дне 17.

## Практика

### 1. Восстанови `scanf`

Исходное состояние перед подготовкой: `esp % 16 == 0`.

```asm
sub esp, ___
push ___
push ___
call scanf
add esp, ___
```

Нужно реализовать:

```c
scanf("%d", &x);
```

<details>
<summary>Ответ</summary>

```asm
sub esp, 8
push x
push fmtIn
call scanf
add esp, 16
```

</details>

### 2. Три аргумента

Восстанови:

```c
scanf("%d%d", &a, &b);
```

<details>
<summary>Ответ</summary>

```asm
sub esp, 4
push b
push a
push fmt2
call scanf
add esp, 16
```

</details>

### 3. Найди две ошибки

```asm
sub esp, 8
push dword [x]
push fmtIn
call scanf
add esp, 8
```

<details>
<summary>Ответ</summary>

Первая ошибка: `scanf` нужен адрес `x`, а не значение `[x]`.

Вторая ошибка: подготовлено 16 байт, поэтому после возврата нужно `add esp,16`, а не `8`.

</details>

### 4. Состояние `esp`

Пусть перед подготовкой `esp = 0x1000`. Выпиши `esp` после `sub esp,8`, после каждого из двух `push` и после `add esp,16`.

<details>
<summary>Ответ</summary>

```text
0x1000 → 0x0FF8 → 0x0FF4 → 0x0FF0 → 0x1000
```

</details>

## Типовые ошибки

| Ошибка | Почему неверно |
|---|---|
| передать `[x]` в `scanf` | значение ошибочно используется как адрес |
| передать `x` в `printf("%d")` | печатается адрес, а не число |
| удалить только байты аргументов | выравнивающие байты остаются и `esp` не восстанавливается |
| перепутать порядок `push` | первый аргумент должен оказаться ближе к вершине перед вызовом |
| продолжить использовать `eax/ecx/edx` как до вызова | внешняя функция имеет право их изменить |
| копировать шаблон без таблицы `esp` | изменение числа аргументов сразу ломает ритуально запомненный код |
