# Диагностические ключи к рабочей тетради

Открывай соответствующий ID только после законченной попытки. Каждый ключ содержит обязательный результат, центральный инвариант, типовую неверную модель, контрпример и маршрут повторения.

<a id="key-tr-01"></a>
## TR-01
<!-- task-sha256: 047f58f7aa0b7e0535e11b7f656912234c1331590474d64bd68b10eb56cf413c -->

- **Обязательный результат:** исходный текст → ассемблер → объектный файл → компоновщик → исполняемый файл → загрузчик → процесс → выполнение процессором.
- **Инвариант:** инструменты сборки создают файлы программы; загрузчик создаёт состояние процесса; процессор выполняет уже загруженные инструкции.
- **Типовая ошибка:** считать объектный файл готовой запускаемой программой.
- **Контрпример:** объектный файл может содержать неразрешённые символы и записи перемещения.
- **Повторение:** [День 01](/day_01), [День 02](/day_02).

<a id="key-tr-02"></a>
## TR-02
<!-- task-sha256: ba647b38d864ee8c9349579994a951345dfcd340ea3e3d84f0e0d54f46e42676 -->

- **Обязательный результат:** проверить `file main.o`, наличие `gcc -m32`, 32-битных библиотек и возможность собрать минимальный 32-битный `main` на C.
- **Инвариант:** успешная работа NASM доказывает лишь создание `.o`, но не наличие совместимых компоновщика и среды выполнения.
- **Типовая ошибка:** переписывать ассемблерный код, когда на самом деле отсутствуют 32-битные библиотеки.
- **Контрпример:** даже пустой объектный файл ELF32 не компонуется без 32-битных библиотек.
- **Повторение:** [День 02](/day_02), [матрица сред](/support_matrix).

<a id="key-tr-03"></a>
## TR-03
<!-- task-sha256: 698dbb9b3eebec124e06ccd18d5b561622056053362fdd8a685fb1d7575e610b -->

- **Обязательный результат:** `eax=5`, `ebx=14`; приёмник результата у `sub` — `eax`, у последней `add` — `ebx`; актуальные `eflags` оставила последняя `add`.
- **Инвариант:** флаги принадлежат последней флагоизменяющей инструкции, а не всей последовательности.
- **Типовая ошибка:** считать, что `cmp` обязателен для появления флагов или что `mov` изменил их.
- **Контрпример:** удалить последнюю `add` — владельцем станет `sub`.
- **Повторение:** [День 03](/day_03). Точные `CF/OF` изучаются в [Дне 11](/day_11).

<a id="key-tr-04"></a>
## TR-04
<!-- task-sha256: 9d52061f0d23d97f8bfc0131fefccd13fdf62c8ff999a26df2b67f6c4901cf40 -->

- **Обязательный результат:** `eax=0x81AB1080`, `ax=0x1080`, `ah=0x10`, `al=0x80`; `al` равен `128` без знака и `-128` со знаком.
- **Инвариант:** `ah` и `al` перекрывают младшие байты `eax`; знаковая интерпретация меняет смысл, но не биты.
- **Типовая ошибка:** обнулить старшие биты `eax`.
- **Контрпример:** представить `eax` как четыре байта `81 AB CD EF` и заменить два младших.
- **Повторение:** [День 04](/day_04).

<a id="key-tr-05"></a>
## TR-05
<!-- task-sha256: 8df2eb079bec104794781043584daf8828087300156ce26ed798df0cfb11902c -->

- **Обязательный результат:** `eax` и `ecx` получают адрес `x`; `ebx` получает `17`; `mov [x],ebx` записывает значение; `lea` вычисляет адрес и не читает данные по нему.
- **Инвариант:** скобки в операнде памяти означают разыменование, а в `lea` описывают только вычисление адреса.
- **Типовая ошибка:** считать `x` и `[x]` эквивалентными.
- **Контрпример:** изменение содержимого `x` меняет `mov ebx,[x]`, но не адрес, полученный `lea`.
- **Повторение:** [День 05](/day_05).

<a id="key-tr-06"></a>
## TR-06
<!-- task-sha256: 38439a18579206933fb5aff2b56b8d1eae8d3007c9fde579b57eb6dca6912fdf -->

- **Обязательный результат:** перед подготовкой каждого вызова выполняется `esp % 16 == 0`; для `scanf`: `sub esp,4`, затем `b`, `a`, `fmt`, `call`, `add esp,16`; для `printf`: `sub esp,8`, затем значение и `fmt`, `call`, `add esp,16`.
- **Инвариант:** `scanf` получает адреса; перед внешним `call` выполняется `esp % 16 == 0`; вызывающая функция удаляет выравнивающие байты и аргументы; `eax`, `ecx`, `edx` могут измениться.
- **Типовая ошибка:** сохранить результат в `eax`, вызвать `printf`, а затем ожидать прежний `eax`.
- **Контрпример:** функция libc имеет право изменить `eax`, `ecx` и `edx`.
- **Повторение:** [День 06](/day_06), [CDECL](/c_abi).

<a id="key-tr-07"></a>
## TR-07
<!-- task-sha256: beb2d62ea28bba0e18870281a4e71d5ad2a1349afdc2c00aa87748773931d5c3 -->

- **Обязательный результат:** `7Fh+02h=81h`: беззнаковое значение `129`, знаковое `-127`, `CF=0`, `OF=1`; `FFh+02h=01h`: результат `1`, перенос `CF=1`, знаковое переполнение `OF=0`.
- **Инвариант:** `CF` описывает перенос при беззнаковой арифметике, `OF` — переполнение при знаковой.
- **Типовая ошибка:** считать `CF` и `OF` одинаковыми.
- **Контрпример:** два примера специально включают только один из флагов.
- **Повторение:** [День 07](/day_07), [День 11](/day_11).

<a id="key-tr-08"></a>
## TR-08
<!-- task-sha256: e7ee37cc0385f5e8e9c7ea9de845d2d8f197cbf92f0597b043fc80abb9bb5831 -->

- **Обязательный результат:** `movzx eax,byte [x]` даёт `160`; `movsx eax,byte [x]` даёт `-96`.
- **Инвариант:** расширение обязано определить все 32 бита результата.
- **Типовая ошибка:** `mov al,[x]` при неизвестных старших 24 битах.
- **Контрпример:** начальное `eax=FFFFFFFFh` после `mov al,A0h` остаётся `FFFFFFA0h`.
- **Повторение:** [День 08](/day_08).

<a id="key-tr-09"></a>
## TR-09
<!-- task-sha256: adfa34f15ec2975d01f9918ada974eb2bc5b959fdeda8d806f7fdcb3e668f805 -->

- **Обязательный результат:** знаковое деление `mov eax,-20; cdq; idiv 6` через регистр даёт частное `-3` и остаток `-2`. Беззнаковое `0xFFFFFFEC / 6` после `xor edx,edx; div` даёт частное `715827879` и остаток `2`.
- **Инвариант:** знаковое и беззнаковое деление по-разному подготавливают старшую половину `edx:eax` и по-разному трактуют те же биты.
- **Типовая ошибка:** говорить только «получится большое число» без вычисления или использовать `cdq` перед беззнаковым `div`.
- **Контрпример:** `FFFFFFFF:FFFFFFEC` и `00000000:FFFFFFEC` — разные 64-битные делимые.
- **Повторение:** [День 09](/day_09).

<a id="key-tr-10"></a>
## TR-10
<!-- task-sha256: a375746bf4d9bfd54633ebdeca7f7f8b5d316bed1166a8113b0a21cc65a95bd5 -->

- **Обязательный результат:** допустима схема `diff=a-b; mask=арифметический_сдвиг(diff,31); result=b+(diff&mask)` при явном условии, что знаковая разность `a-b` представима.
- **Инвариант:** знак переполненной разности не доказывает отношение `a<b`.
- **Типовая ошибка:** объявить решение корректным на всей `int32_t`-области.
- **Контрпример:** `a=INT32_MIN`, `b=1`.
- **Повторение:** [День 10](/day_10), [сессия 10B](/day_10_learning_path#сессия-10b-маска-0-1-и-выбор-без-ветвлений).

<a id="key-tr-11"></a>
## TR-11
<!-- task-sha256: e535d16c4bf15358e46e06f7069d69c7e6f4ec4c67455056b3534da425c6ae0c -->

- **Обязательный результат:** в первой последовательности актуальные флаги оставляет `sub edx,edx`: `mov` их не меняет, а `sub` перезаписывает результат `cmp`. Во второй последовательности флаги оставляет `test eax,eax`, потому что `lea` их не меняет.
- **Инвариант:** переход читает состояние флагов, оставленное последней командой, которая их меняет.
- **Типовая ошибка:** выбирать ближайшую визуально инструкцию независимо от семантики.
- **Контрпример:** заменить `lea` на `add` — владелец изменится.
- **Повторение:** [День 11](/day_11).

<a id="key-tr-12"></a>
## TR-12
<!-- task-sha256: 96c3c9ca8b4e839801a69ed779831b68ed19d6e5fb71ed11156a5b8f9dccb90a -->

- **Обязательный результат:** три последовательные проверки с выходом по ложному условию: `test x,x; je`, беззнаковое `cmp y,15; ja`, `test x,8; je`, затем запись `answer=1`.
- **Инвариант:** каждый `jcc` должен читать нужные флаги до того, как другая команда их изменит; `y` сравнивается без знака.
- **Типовая ошибка:** использовать знаковый `jg` или вставить арифметическую команду между сравнением и `jcc`.
- **Контрпример:** значение `y=FFFFFFFFh` даёт разные результаты при знаковой и беззнаковой интерпретации.
- **Повторение:** [День 12](/day_12).

<a id="key-tr-13"></a>
## TR-13
<!-- task-sha256: 249070f4df1040372eccbc248bcbc6594caa7fa9324431097f15d7feb155e5c8 -->

- **Обязательный результат:** отдельные блоки проверки, тела, шага и выхода; отрицательный элемент ведёт к шагу, ноль — к выходу, обычный путь добавляет значение и также идёт к шагу.
- **Инвариант:** `continue` в цикле `for` проходит через шаг изменения счётчика.
- **Типовая ошибка:** направить `continue` сразу на `check` и получить бесконечный цикл.
- **Контрпример:** первый элемент отрицательный при `i=0`.
- **Повторение:** [День 13](/day_13).

<a id="key-tr-14"></a>
## TR-14
<!-- task-sha256: b76aac2aafdb7f06d17874fde5e46b3d19786b5a65d38c8bc8a9b8b26c38d76a -->

- **Обязательный результат:** исходные значения `5..11`; соответствие: `5→A`, `6→B`, `7→B`, `8→D`, `9→default`, `10→F`, `11→A`; объединены ветки `6/7` и `5/11`.
- **Инвариант:** исходное значение равно `нормализованный индекс + 5`.
- **Типовая ошибка:** назвать диапазон `0..6`.
- **Контрпример:** подставить исходный `eax=5` перед `sub`.
- **Повторение:** [День 14](/day_14).

## TR-15
<!-- task-sha256: 8f341ad7a286cec04c0799c07e549801c815d28c2dd2a5c59e3898be69cdbd5c -->

- **Обязательный результат:** адрес `base + 2*(i*7+j)`; например `imul eax,eax,7; add eax,ecx; movsx eax,word [edx+2*eax]`, где `base` — базовый адрес.
- **Инвариант:** индекс строки умножается на число столбцов, после чего общий индекс умножается на размер элемента.
- **Типовая ошибка:** использовать 4 вместо 2 или `i*4+j`.
- **Контрпример:** соседние `short` отличаются на 2 байта.
- **Повторение:** [День 15](/day_15).

## TR-16
<!-- task-sha256: 75dc844471e35ba59ec20d2ef7297a8c2ac461efb82657cf4bc823e5354deb9e -->

- **Обязательный результат:** `0x0FFC=10`, `0x0FF8=20`; после `call` `esp=0x0FF4`, а `[esp]` содержит адрес возврата; после `ret` `esp=0x0FF8`; после `add esp,8` — `0x1000`.
- **Инвариант:** стек растёт к меньшим адресам; `call` кладёт адрес возврата; аргументы удаляет вызывающая функция.
- **Типовая ошибка:** считать, что внутри вызываемой функции первый аргумент лежит на самой вершине стека.
- **Контрпример:** `ret` обязан снять именно адрес возврата.
- **Повторение:** [День 16](/day_16).

## TR-17
<!-- task-sha256: e7fe2f34c44d53c5892dfa03136a037e694f3a64e60ca9b4c27011f70a3676a4 -->

- **Обязательный результат:** кадр стека, аргументы `[ebp+8/12/16]`, сохранение `ebx`, разыменование `out`, результат в `eax`, симметричный эпилог.
- **Инвариант:** сохраняемый регистр и состояние кадра стека восстанавливаются на всех путях.
- **Типовая ошибка:** записать сумму в `[ebp+16]` вместо памяти по указателю.
- **Контрпример:** `[ebp+16]` содержит сам адрес `out`.
- **Повторение:** [День 17](/day_17).

<a id="key-tr-18"></a>
## TR-18
<!-- task-sha256: 396879a0170a2735572e56f074eefc0d00453ebd41000cf55d427317dd4ca653 -->

- **Обязательные факты:** первый аргумент используется как указатель; читается беззнаковый байт; вторая 32-битная ячейка складывается с байтом, расширенным нулями; результат возвращается в `eax`.
- **Две допустимые реконструкции:** `int f(const unsigned char* p,int x)` и `uint32_t g(const uint8_t* data,uint32_t addend)`. Имена условны; команда `add` не доказывает знаковость второго аргумента и результата.
- **Инвариант:** один листинг может соответствовать нескольким высокоуровневым типам с одинаковой машинной семантикой.
- **Типовая ошибка:** дать одно объявление как единственно возможное.
- **Контрпример:** знаковое и беззнаковое сложение используют одну команду `add`.
- **Повторение:** [День 18](/day_18).

<a id="key-tr-19"></a>
## TR-19
<!-- task-sha256: fe72ca25c173247083580dc0be5e4a8c2633b6760293dbfe09861c48308fe88d -->

- **Обязательный результат:** типичное расположение полей: `tag@0`, выравнивающие байты `1..3`, `value@4`, `flags@8`, выравнивающие байты `10..11`, `next@12`, `sizeof=16`; доступ: `mov eax,[p]; mov eax,[eax+12]`.
- **Инвариант:** требования выравнивания создают промежутки; указатель IA-32 занимает 4 байта.
- **Типовая ошибка:** сложить размеры полей без учёта выравнивающих байтов и получить 11.
- **Контрпример:** поле `int value` обычно требует выравнивания по 4 байтам.
- **Повторение:** [День 19](/day_19). Упаковка структуры и ABI могут изменить расположение полей.

## TR-20
<!-- task-sha256: d474d75efa3ffc054994f3819c11c34813922c110229936d345aadf07d6a0ea5 -->

- **Контрпример:** самостоятельный ELF-файл может иметь `_start` и не иметь `main`.
- **Повторение:** [День 20](/day_20).

## TR-22
<!-- task-sha256: d2042805f014d0534a17102773cca85668251075f0e7fc15e2e0e836dd905250 -->

- **Обязательный результат:** `6.625=110.101₂=1.10101₂·2²`; `0.125=1/8=0.001₂` имеет конечную запись; `0.2=1/5` периодична в двоичной системе; из-за округления результаты разных последовательностей операций могут не совпасть точно.

<a id="key-tr-23"></a>
## TR-23
<!-- task-sha256: 4a7aa5c3cf20bd72eac8c8584132be2d89372b14882c5540c68292b306c024b5 -->

- **Обязательный результат:** корректный порядок, например `fld a; fld b; fsubp st1,st0; fld c; fld d; faddp st1,st0; fdivp st1,st0`; затем в выровненном теле функции: `sub esp,12; fstp qword [esp]; push fmt; call printf; add esp,16`.
- **Инвариант:** `fld` добавляет значение в стек; команды с суффиксом `p` снимают один элемент; `sub` и `div` зависят от порядка; `%f` получает `double`.
- **Типовая ошибка:** получить `(c+d)/(a-b)` или оставить лишние значения в стеке x87.
- **Контрпример:** числа `a=10,b=4,c=1,d=2` различают порядок.
- **Повторение:** [День 23](/day_23).

<a id="key-tr-24"></a>
## TR-24
<!-- task-sha256: 4e22ada70f36c0e3006a3c1ceafbafd41eaa2bfbad0145b7c40d64513b20df4c -->

- **Обязательные факты:** значение, похожее на аргумент, загружается в `ecx`; выполняются чтения `[ecx]` и `[ecx+4]`; адрес вызываемой функции читается из `[eax+8]`.
- **Инвариант:** форма косвенного вызова является фактом; трактовка `this/vptr/виртуальный вызов` остаётся гипотезой, зависящей от ABI.
- **Гипотеза:** `ecx=this`, `[ecx]=vptr`, `[ecx+4]=поле`, `[eax+8]=ячейка виртуального метода`.
- **Зависит от ABI:** место скрытого `this`, расположение полей, наличие `vptr` и нумерация ячеек.
- **Типовая ошибка:** назвать виртуальный вызов доказанным фактом.
- **Контрпример:** таблица обратных вызовов имеет ту же форму косвенного вызова.
- **Повторение:** [День 24](/day_24).

## TR-25

- **Обязательные результаты:** `scanf` получает адрес `x`; `-13/5` даёт частное `-2` и остаток `-3`; для знакового `x>=y` используется `jge` после `cmp x,y`; в кадре стека адрес возврата лежит по `[ebp+4]`, первый аргумент — по `[ebp+8]`, локальная переменная — ниже `ebp`; `%f` получает 8-байтный `double` и 4-байтный указатель на строку формата; в выровненном теле добавляются 4 выравнивающих байта, общий объём очистки равен 16.
- **Инвариант:** смешанная задача проверяет независимые центральные модели, одна сильная тема не компенсирует ноль в другой.
- **Типовая ошибка:** оценить только число правильных ответов и не выбрать слабый инвариант.
- **Контрпример:** идеальные ответы по целым числам не исправляют нарушенный баланс стека.
