# Диагностические ключи задач переноса

Ключ показывает обязательный результат, инвариант, типовую ошибку, контрпример и маршрут повторения.

<a id="key-tr-01"></a>
## TR-01
<!-- task-sha256: b71752f22202ae51d2c06cc78cf174024030ad113052fae4bfd6d530f255eff1 -->

- **Обязательный результат:** исходник → ассемблер → объектный файл → компоновщик → исполняемый файл → загрузчик → процесс → процессор.
- **Инвариант:** каждый этап получает конкретный вход и создаёт следующий объект.
- **Типовая ошибка:** считать `.o` уже запускаемой программой.
- **Контрпример:** объектный файл может содержать неразрешённый внешний символ.
- **Повторение:** [Дни 01–02](/day_01).

<a id="key-tr-02"></a>
## TR-02
<!-- task-sha256: 752e085fdd66837575ec796777d8b20e3cdd53406e206adf504406e1a7918b67 -->

- **Обязательный результат:** проверить `file main.o`, `gcc -m32` на минимальном C, наличие multilib/32-bit libc.
- **Инвариант:** успешный NASM доказывает синтаксис и объект, но не совместимость линковки.
- **Типовая ошибка:** менять asm до проверки среды.
- **Контрпример:** минимальный C также не линкуется с `-m32`.
- **Повторение:** [День 02](/day_02), [среды](/support_matrix).

<a id="key-tr-03"></a>
## TR-03
<!-- task-sha256: abb111e2d3fc02e22357c110d798406f908742453966bf64a999f24bdb25c2b0 -->

- **Обязательный результат:** `eax=5`, `ebx=14`; актуальные флаги оставляет `add ebx,eax`.
- **Инвариант:** арифметический результат записывается в первый операнд.
- **Типовая ошибка:** считать `mov ebx,eax` связью регистров.
- **Контрпример:** последующее изменение `eax` не меняет копию.
- **Повторение:** [День 03](/day_03).

<a id="key-tr-04"></a>
## TR-04
<!-- task-sha256: 7ab7284a3080fff03ad746938bb91f72044e7f8a043b8f0ae88864d2f9d0f445 -->

- **Обязательный результат:** `eax=81AB1080h`, `ax=1080h`, `ah=10h`, `al=80h`; `al=128/-128`.
- **Инвариант:** `ah` и `al` меняют только свои байты.
- **Типовая ошибка:** переставить порядок байтов.
- **Контрпример:** выписать полный регистр по байтам.
- **Повторение:** [День 04](/day_04).

<a id="key-tr-05"></a>
## TR-05
<!-- task-sha256: 3ba9307e196281ad9cced483e5fa41eba3b98aa2a527d3c37d43f388cea8094b -->

- **Обязательный результат:** `eax/ecx` получают адрес, `ebx` — значение; `lea` не читает память.
- **Инвариант:** скобки в `lea` описывают адресное выражение, а не чтение.
- **Типовая ошибка:** считать `x` значением переменной.
- **Контрпример:** адрес и хранимое число обычно различны.
- **Повторение:** [День 05](/day_05).

<a id="key-tr-06"></a>
## TR-06
<!-- task-sha256: 2a181f823ff3d65ca82d45577d9e80afc29e41b5f953a1235317a3637cf6a74f -->

- **Обязательный результат:** для трёх аргументов `scanf` — `argument_bytes=12,padding=4,cleanup=16`; для двух аргументов `printf` — `8,8,16`; внешняя функция может изменить `eax/ecx/edx`.
- **Инвариант:** перед `call` область кратна 16, после возврата удаляется вся область.
- **Типовая ошибка:** удалить только аргументы.
- **Контрпример:** оставшийся padding смещает `esp`.
- **Повторение:** [День 06](/day_06), [выравнивание](/patterns/libc_alignment).

<a id="key-tr-07"></a>
## TR-07
<!-- task-sha256: ef1085ddc6013ccaf622d54e729523abd8d5a7a7c2f8533601e1b148519fc56c -->

- **Обязательный результат:** `7F+02=81`, `CF=0,OF=1`; `FF+02=01`, `CF=1,OF=0`.
- **Инвариант:** `CF` и `OF` отвечают разным интерпретациям.
- **Типовая ошибка:** считать любой выход за диапазон одним переполнением.
- **Контрпример:** два примера дают разные пары флагов.
- **Повторение:** [День 07](/day_07).

<a id="key-tr-08"></a>
## TR-08
<!-- task-sha256: 8e0626e472b5727c75c25af6d7e86b5692088c365bb22b4573e6d4c12bf4b3c9 -->

- **Обязательный результат:** `movzx eax,byte [x]` → 160; `movsx eax,byte [x]` → -96.
- **Инвариант:** расширение определяет старшие биты результата.
- **Типовая ошибка:** использовать `mov al` при неизвестном `eax`.
- **Контрпример:** разные старшие 24 бита дают разные полные числа.
- **Повторение:** [День 08](/day_08).

<a id="key-tr-09"></a>
## TR-09
<!-- task-sha256: 4b9b67a1524e9b4a85e99c9c9358da51169daaeefdb9b5eec2c89744959db6e0 -->

- **Обязательный результат:** `-20/6` → `-3`, остаток `-2`; беззнаковое `FFFFFFECh=4294967276`, частное `715827879`, остаток `2`.
- **Инвариант:** `idiv` требует `cdq`, `div` для 32-битного делимого — нулевой `edx`.
- **Типовая ошибка:** смешать знаковую подготовку.
- **Контрпример:** одинаковый `eax` с разным `edx` задаёт другое делимое.
- **Повторение:** [День 09](/day_09).

<a id="key-tr-10"></a>
## TR-10
<!-- task-sha256: 27e69513a77e646d6b5761687b5b2eaa8cd6346b40b9a4910bf81a8b7640b469 -->

- **Обязательный результат:** корректный выбор через маску знака разности только при доказанном отсутствии знакового переполнения.
- **Инвариант:** знак переполненной разности не доказывает отношение.
- **Типовая ошибка:** применять шаблон ко всем `int32_t`.
- **Контрпример:** `INT32_MIN-1` переполняется.
- **Повторение:** [Сессия 10B](/day_10_learning_path).

<a id="key-tr-11"></a>
## TR-11
<!-- task-sha256: 135a4bc0c70f1533dbb4516b2d19d06fb7ff25e05a6e8b478985de403dd69023 -->

- **Обязательный результат:** в первой последовательности флаги `sub`; во второй — `test`, потому что `lea` их не меняет.
- **Инвариант:** `jcc` читает последнего владельца флагов.
- **Типовая ошибка:** искать ближайший `cmp`.
- **Контрпример:** арифметика между `cmp` и `jcc` меняет решение.
- **Повторение:** [День 11](/day_11).

<a id="key-tr-12"></a>
## TR-12
<!-- task-sha256: d6a447fa1d60dce1501f31b4326cc6df189a7bfe0f06c9c58ce1cef8b07c6a4e -->

- **Обязательный результат:** три проверки с коротким замыканием; для `(unsigned)y<=15` использовать беззнаковое отношение; бит проверить через `test`.
- **Инвариант:** каждый переход непосредственно потребляет флаги своей проверки.
- **Типовая ошибка:** вставить арифметику между проверкой и `jcc`.
- **Контрпример:** флаги станут принадлежать другой инструкции.
- **Повторение:** [День 12](/day_12).

<a id="key-tr-13"></a>
## TR-13
<!-- task-sha256: 68bf5a7198d32388544891f7f51f874beaee1c5fc537f2881478d44993bbd344 -->

- **Обязательный результат:** `continue` идёт на метку шага, `break` — на конец; после шага управление возвращается к проверке.
- **Инвариант:** каждый продолжающий путь выполняет `++i` ровно один раз.
- **Типовая ошибка:** `continue` на проверку до шага.
- **Контрпример:** отрицательный элемент вызывает бесконечный цикл.
- **Повторение:** [День 13](/day_13), [разбор](/transfer_walkthroughs#tr-13).

<a id="key-tr-14"></a>
## TR-14
<!-- task-sha256: b1e0b0028efd9ce595a63b64d1e3b4dad1682c419d59ad3edfc0c8485a71bc8a -->

- **Обязательный результат:** индексы 0..6 соответствуют исходным 5..11; метки A для 5/11, B для 6/7 и т.д.
- **Инвариант:** таблица индексируется нормализованным беззнаковым диапазоном.
- **Типовая ошибка:** забыть обратное `+5`.
- **Контрпример:** индекс 0 означает исходное 5.
- **Повторение:** [День 14](/day_14).

<a id="key-tr-15"></a>
## TR-15
<!-- task-sha256: 35dacca54a740020754feec99663b2bc24a3d0bbd87c93acdfed8a52d404d2b4 -->

- **Обязательный результат:** адрес `base+2*(i*7+j)`, загрузка `movsx ... word`.
- **Инвариант:** сначала линейный индекс, затем размер элемента.
- **Типовая ошибка:** множитель 4 вместо 2.
- **Контрпример:** соседние `short` отличаются на два байта.
- **Повторение:** [День 15](/day_15).

<a id="key-tr-16"></a>
## TR-16
<!-- task-sha256: 562c227cdbbb5ad6e75ca733844cba4516d9043e83e9225e902c552cb9f25b23 -->

- **Обязательный результат:** после pushes `0FF8h=20,0FFCh=10`; внутри `f` `esp=0FF4h` и адрес возврата на вершине; после `ret` `esp=0FF8h`.
- **Инвариант:** это абстрактная механика `call/ret`, не ABI-шаблон; `ret` сам снимает адрес возврата.
- **Типовая ошибка:** считать вершину первым аргументом или добавлять адрес возврата в cleanup.
- **Контрпример:** `ret` обязан прочитать именно вершину.
- **Повторение:** [День 16](/day_16).

<a id="key-tr-17"></a>
## TR-17
<!-- task-sha256: 55b2185be7499c24877a9ac09ae2425bb257ddcdcfd73dd3ebdd8e632fab0080 -->

- **Обязательный результат:** аргументы `[ebp+8/12/16]`, сохранение `ebx`, запись через указатель, сумма в `eax`, симметричный эпилог.
- **Инвариант:** сохраняемый регистр и кадр восстанавливаются на всех путях.
- **Типовая ошибка:** записать в ячейку аргумента вместо памяти по `out`.
- **Контрпример:** `[ebp+16]` содержит адрес.
- **Повторение:** [День 17](/day_17), [разбор](/transfer_walkthroughs#tr-17).

<a id="key-tr-18"></a>
## TR-18
<!-- task-sha256: c86e045df46bd58d4ade5109df207062d7dd4d68833cf13b308d8e9fe2b79852 -->

- **Обязательный результат:** доказаны указатель, беззнаковый байт, сложение с 32-битной ячейкой и возврат в `eax`; допустимы минимум два объявления.
- **Инвариант:** машинная семантика допускает несколько высокоуровневых типов.
- **Типовая ошибка:** выдать одно объявление за точное.
- **Контрпример:** `add` одинаков для знаковой и беззнаковой интерпретации.
- **Повторение:** [День 18](/day_18).

<a id="key-tr-19"></a>
## TR-19
<!-- task-sha256: de976dbc1ace93849115bab481c80c7782cff6b5a11e4a3bd3c6dae94b6f4aea -->

- **Обязательный результат:** типично `tag@0`, padding 1..3, `value@4`, `flags@8`, padding 10..11, `next@12`, `sizeof=16`.
- **Инвариант:** выравнивание создаёт промежутки.
- **Типовая ошибка:** сложить только размеры полей.
- **Контрпример:** `int` обычно требует адрес, кратный 4.
- **Повторение:** [День 19](/day_19).

<a id="key-tr-20"></a>
## TR-20
<!-- task-sha256: c12cb1b9ccfdb345120b1a0df88466b4560c2510a39573cde506015e6c7d4b67 -->

- **Обязательный результат:** `global` экспортирует символ; entry point хранится в ELF; смотреть `readelf -h`; путь через `_start` к `main`.
- **Инвариант:** видимость и точка входа — разные свойства.
- **Типовая ошибка:** считать `main` первым кодом процесса.
- **Контрпример:** ELF без `main` с собственным `_start`.
- **Повторение:** [День 20](/day_20).

<a id="key-tr-21"></a>
## TR-21
<!-- task-sha256: dce3b148a92aec00e22ee5ed3db1491f676ff1be3534d36b692f01e72ab8a5b6 -->

- **Обязательный результат:** возможная, не гарантированная схема; канарейка обнаруживает часть перезаписей, NX запрещает исполнение данных.
- **Инвариант:** защита не делает выход за границы корректным.
- **Типовая ошибка:** считать расположение объектов фиксированным стандартом C++.
- **Контрпример:** оптимизатор меняет или удаляет локальные объекты.
- **Повторение:** [День 21](/day_21).

<a id="key-tr-22"></a>
## TR-22
<!-- task-sha256: 2aa8ada0646296d40492f80a20e886a9d0fc5b6328ec7a885fdcadd371115f6a -->

- **Обязательный результат:** `6.625=110.101₂=1.10101₂·2²`; `0.125` конечно, `0.2` периодично.
- **Инвариант:** конечный двоичный знаменатель после сокращения — степень двойки.
- **Типовая ошибка:** судить по числу десятичных знаков.
- **Контрпример:** `0.125` имеет три знака, но точно представимо.
- **Повторение:** [День 22](/day_22).

<a id="key-tr-23"></a>
## TR-23
<!-- task-sha256: b3bfdcc5211433eaec057e6cdfbd1caaa84bd5bd786df9e94e4798942bc87ed5 -->

- **Обязательный результат:** `fld a; fld b; fsubp st1,st0; fld c; fld d; faddp st1,st0; fdivp st1,st0`; затем `sub esp,12; fstp qword [esp]; push fmt; call printf; add esp,16`.
- **Инвариант:** направление некоммутативных операций, глубина x87 и область обычного стека независимы.
- **Типовая ошибка:** обратная дробь или лишнее значение x87.
- **Контрпример:** `10,4,1,2` даёт 2 только в правильном порядке.
- **Повторение:** [День 23](/day_23), [разбор](/transfer_walkthroughs#tr-23).

<a id="key-tr-24"></a>
## TR-24
<!-- task-sha256: 89bf8408a3f463595e0fe4a5a162cb4ce885ba42b14a81b01c7140488318eb16 -->

- **Обязательный результат:** доказаны чтения и косвенный вызов; `this/vptr/vtable` — совместимая гипотеза, зависящая от ABI.
- **Инвариант:** косвенный адрес не доказывает высокоуровневое назначение.
- **Типовая ошибка:** назвать третий виртуальный метод фактом.
- **Контрпример:** ручная таблица callback-ов.
- **Повторение:** [День 24](/day_24).

<a id="key-tr-25"></a>
## TR-25
<!-- task-sha256: 4cc1e5f9b0f930225db0633684f4180ef02c7862cf827a44014e32bb0b401fd6 -->

- **Обязательный результат:** адрес для `scanf`; `-13/5 → -2,-3`; знаковый `jge`; корректный кадр; `%f` через `qword`, padding и cleanup 16.
- **Инвариант:** каждый из пяти пунктов проверяет отдельную критическую модель; сумма не компенсирует ноль.
- **Типовая ошибка:** считать готовность средней оценкой.
- **Контрпример:** верные четыре пункта не исправляют сломанный стек.
- **Повторение:** [контрольные точки](/checkpoints), затем [финал](/final_exam).
