# Ключи к рабочей тетради

Открывай соответствующий раздел только после законченной попытки. Ключ содержит не единственный допустимый текст, а обязательные свойства правильного решения.

## День 01

Порядок: source → assembler → object file → linker → executable → loader → process → CPU execution. Критическая ошибка: считать object file запускаемой программой или считать CPU участником сборки.

## День 02

Проверки: объект действительно ELF32 (`file main.o`), линковка использует `gcc -m32`, установлены multilib/32-bit libc. Минимальный контроль — собрать пустой 32-битный C `main`. Ошибка исходника NASM отделяется успешным созданием корректного `.o`.

## День 03

Итог: `eax=5`, `ebx=14`. `sub` меняет `eax`, `add` меняет `ebx`; последняя `add` задаёт актуальные арифметические флаги. Важна не попытка угадать все флаги без ширины/значений, а указание владельца текущего состояния.

## День 04

После замен байтов: `eax=0x81AB1080`, `ax=0x1080`, `ah=0x10`, `al=0x80`. `al` как unsigned — `128`, как signed 8-bit — `-128`. Критическая ошибка: считать `ah/al` независимыми регистрами.

## День 05

`eax` и `ecx` получают адрес `x`; `ebx` получает `17`; последняя строка записывает прежнее значение `ebx` обратно. `lea` не читает память. Критическая ошибка: считать скобки синтаксическим украшением.

## День 06

Аргументы справа налево:

```asm
push b
push a
push fmt2
call scanf
add esp, 12

mov eax, [a]
sub eax, [b]
push eax
push fmtOut
call printf
add esp, 8
```

После вызова не полагаться на `eax/ecx/edx`. При необходимости сохранить результат до `printf`.

## День 07

`0x7F+2=0x81`: signed overflow (`127+2` не помещается), `OF=1`, unsigned carry нет, `CF=0`. `0xFF+2=0x01` с выходным carry: `CF=1`; signed `-1+2=1`, поэтому `OF=0`.

## День 08

```asm
movzx eax, byte [x] ; 160
movsx eax, byte [x] ; -96
```

`mov al,[x]` меняет только младшие 8 бит и оставляет неизвестные старшие 24 бита.

## День 09

```asm
mov eax, -20
cdq
mov ecx, 6
idiv ecx
```

`eax=-3`, `edx=-2`: деление округляется к нулю, остаток имеет знак делимого. Unsigned-интерпретация `0xFFFFFFEC` даёт совсем другое большое положительное делимое и требует `xor edx,edx; div`.

## День 10

Один учебный вариант:

```asm
mov eax, [a]
sub eax, [b]      ; diff = a-b
mov ecx, eax
sar ecx, 31       ; mask = -1, если diff отрицательна
and eax, ecx      ; diff или 0
add eax, [b]      ; b+diff = a либо b
```

Это корректно только когда signed-разность `a-b` представима в 32 битах. Контрпример границы: `a=INT32_MIN`, `b=1`; разность переполняется и её знак больше не доказывает `a<b`. Ответ должен явно назвать это ограничение, полную маску `0/-1` и тесты равенства/разных знаков/границ. Для полной signed-области нужен другой доказанный способ, например маска из корректного signed-сравнения.

## День 11

В первой последовательности актуальные флаги принадлежат `sub edx,edx`, не `cmp`; `mov` их не менял, но `sub` перезаписал. Во второй `lea` не меняет флаги, поэтому они всё ещё принадлежат `test eax,eax`.

## День 12

Один вариант:

```asm
mov eax, [x]
test eax, eax
je .skip
cmp dword [y], 15
ja .skip
test eax, 8
je .skip
mov dword [answer], 1
.skip:
```

Критические места: `y` сравнивается unsigned; `test eax,8` проверяет бит; переходы идут по ложному условию.

## День 13

У корректного решения отдельная метка шага:

```asm
xor ecx, ecx
xor eax, eax
.check:
cmp ecx, [n]
jge .end
mov edx, [a+4*ecx]
test edx, edx
js .step
je .end
add eax, edx
.step:
inc ecx
jmp .check
.end:
```

`continue` обязан вести к шагу, а не напрямую к проверке, иначе `i` не изменится.

## День 14

Исходные cases `5..11`. Таблица:

| index | case | label |
|---:|---:|---|
| 0 | 5 | `.A` |
| 1 | 6 | `.B` |
| 2 | 7 | `.B` |
| 3 | 8 | `.D` |
| 4 | 9 | `.default` |
| 5 | 10 | `.F` |
| 6 | 11 | `.A` |

Объединены `6/7` и `5/11`; case 9 ведёт как default.

## День 15

Формула: `base + 2*(i*7+j)`. Один вариант:

```asm
imul eax, eax, 7
add eax, ecx
movsx eax, word [edx+2*eax]
```

Критические ошибки: множитель 2, row-major `i*7+j`, signed-загрузка `movsx`.

## День 16

До вызова: `0x0FFC=10`, `0x0FF8=20`. `call` кладёт return address по `0x0FF4`, поэтому внутри `f` `esp=0x0FF4`; первый аргумент caller-а находится выше return address. После `ret` `esp=0x0FF8`; `add esp,8` возвращает `0x1000`.

## День 17

Функция должна иметь пролог/эпилог, читать аргументы по `[ebp+8/12/16]`, сохранить и восстановить `ebx`, разыменовать `out`, вернуть сумму в `eax`. Например:

```asm
push ebp
mov ebp, esp
push ebx
mov ebx, [ebp+8]
add ebx, [ebp+12]
mov edx, [ebp+16]
mov [edx], ebx
mov eax, ebx
pop ebx
pop ebp
ret
```

## День 18

Подтверждено: первый аргумент используется как pointer; читается unsigned byte; к нему прибавляется второй 32-bit slot; результат возвращается в `eax`. Возможный C: `int f(const unsigned char* p, int x) { return *p+x; }`. Signedness второго аргумента арифметикой `add` не доказана.

## День 19

Типичный IA-32 layout: `tag@0`, padding `1..3`, `value@4`, `flags@8`, padding `10..11`, `next@12`, размер `16`. Доступ:

```asm
mov eax, [p]
mov eax, [eax+12]
```

Точные правила зависят от ABI/packing; ответ должен назвать это ограничение.

## День 20

`global main` экспортирует символ для runtime, но ELF entry point обычно `_start`. Проверить можно через `readelf -h`/`objdump`. Путь: loader → entry `_start` → C runtime → `main` → `exit`.

## День 21

Canary обнаруживает часть перезаписей перед возвратом; NX запрещает исполнение страниц данных; ASLR меняет адреса. Ни одна защита не делает out-of-bounds допустимым. Точный порядок объектов во frame не гарантируется исходным C.

## День 22

`6.625 = 110.101₂ = 1.10101₂ * 2²`. Фиксированный абсолютный `eps` зависит от масштаба: для больших чисел он может быть слишком строгим, для малых — слишком грубым. Полный численный критерий зависит от задачи.

## День 23

Один вариант:

```asm
fld qword [a]
fld qword [b]
fsubp st1, st0
fld qword [c]
fld qword [d]
faddp st1, st0
fdivp st1, st0
sub esp, 8
fstp qword [esp]
push fmt
call printf
add esp, 12
```

Нужно проверить порядок некоммутативных операций и возврат ожидаемой глубины x87-стека.

## День 24

Подтверждено: `[ebp+8]` загружается как pointer-like value в `ecx`; `[ecx]` и `[ecx+4]` — чтения по offsets; `call [eax+8]` — indirect call через таблицу/структуру указателей. Гипотеза: `ecx=this`, `[ecx]=vptr`, `[ecx+4]=поле`, `[eax+8]=virtual slot`. ABI и точный layout не доказаны одним листингом.

## День 25

Правильная проверка должна обнаружить:

- для `scanf` нужен адрес `x`;
- `-13/5` даёт quotient `-2`, remainder `-3`;
- signed `x>=y` — `jge` после `cmp x,y`;
- первый аргумент классического frame — `[ebp+8]`, локальная — ниже `ebp`;
- `%f` принимает `double`, на IA-32 CDECL нужно положить 8 байт значения плюс pointer формата и затем очистить 12 байт.
