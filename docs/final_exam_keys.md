# Ключ и рубрика финального экзамена

Открывай эту страницу только после законченной попытки на [экзамене](/final_exam).

## Итоговый контракт

Зачёт получен только одновременно при выполнении условий:

```text
total >= 80
A >= 12
B >= 12
C >= 16
D >= 13
E >= 9
каждое критическое задание > 0
```

Критические задания: `A1`, `A2`, `B1`, `C1`, `C3`, `D1`, `E2`.

Для задания на 5 баллов: `5` — полный ответ, `2` — одна локальная ошибка при верной модели, `0` — нарушен центральный инвариант.

Для задания на 7 баллов: `7`, `3`, `0`. Для задания на 8 баллов: `8`, `4`, `0`.

## Блок A

### A1

Ожидаемый фрагмент при исходном `esp % 16 == 0`:

```asm
sub esp, 4
push b
push a
push fmtIn2
call scanf
add esp, 16
```

Здесь `argument_bytes=12`, `padding=4`, `cleanup=16`. `scanf` получает адреса `a` и `b`, а не значения `[a]` и `[b]`.

**Инвариант:** непосредственно перед `call` подготовленная область кратна 16, после возврата удаляется вся область.

### A2

Один допустимый каркас:

```asm
mov eax, [a]
xor edx, edx
div dword [b]
test edx, edx
jz .done
inc eax
.done:
```

Если запрещены переходы, остаток превращается в `0/1` разрешённым условием задачи. Частное находится в `eax`, остаток — в `edx`.

**Инвариант:** результат равен `q + (r != 0)` без промежуточной переполняющейся суммы.

### A3

```text
items = N*M*K
boxes = items/D + (items%D != 0)
blocked = boxes/3 + (boxes%3 != 0)
dayAnswer = boxes - blocked
```

Ночная маска равна `-1` при `X<6`, иначе `0`; ответ выбирается по словам. Нужно проверить переполнение `N*M*K` и любой сокращённой формулы округления через сумму.

**Инвариант:** коробка 0 задерживается днём, поэтому количество кратных трём равно `ceil(boxes/3)`.

### A4

```text
det = (x2-x1)*(y3-y1) - (x3-x1)*(y2-y1)
absDet = битовый модуль det
integerPart = absDet / 2
fractionDigit = (absDet % 2) * 5
```

```cpp
uint32_t ux = static_cast<uint32_t>(det);
uint32_t mask = 0u - (ux >> 31);
uint32_t absDet = (ux ^ mask) - mask;
```

Для `INT32_MIN` модуль не помещается в положительный `int32_t`, поэтому результат хранится в беззнаковом или более широком типе.

## Блок B

### B1

Перед `idiv`: `edx:eax=FFFFFFFF:FFFFFFF3`. После деления: `eax=-2`, `edx=-3`.

**Инвариант:** `idiv` округляет частное к нулю; остаток имеет знак делимого.

### B2

```text
eax = 0x80FF7F90
ax  = 0x7F90
ah  = 0x7F
al  = 0x90
al unsigned = 144
al signed   = -112
```

### B3

`jl` истинно, потому что знаково `-1 < 1`. `ja` также истинно, потому что беззнаково `4294967295 > 1`.

**Инвариант:** `cmp` оставляет один набор флагов, а разные `jcc` интерпретируют его по разным отношениям.

### B4

`lea` вычисляет выражение адреса и не читает память. `mov` читает 4 байта по вычисленному адресу. Тип массива и смысл смещения без контекста не доказаны.

## Блок C

### C1

```text
[ebp+12] аргумент 2
[ebp+8]  аргумент 1
[ebp+4]  адрес возврата
[ebp]    сохранённый ebp
[ebp-4]  локальная 1
[ebp-8]  локальная 2
```

### C2

```asm
sum:
    push ebp
    mov ebp, esp
    mov eax, [ebp+8]
    add eax, [ebp+12]
    mov esp, ebp
    pop ebp
    ret
```

### C3

```asm
; до подготовки: esp % 16 == 0
sub esp, 8
push dword [b]
push dword [a]
call sum
add esp, 16
```

```text
argument_bytes = 8
padding = 8
перед call: уменьшение на 16, значит esp % 16 == 0
cleanup = 16
```

**Инвариант:** `call`/`ret` сами обрабатывают адрес возврата; вызывающая сторона удаляет padding и аргументы.

## Блок D

### D1

Факты: читаются два 32-битных аргумента, их биты складываются, результат возвращается в `eax`. Допустимая гипотеза: `int f(int a,int b){ return a+b; }`. Знаковость самой командой `add` не доказана.

### D2

Факты: первый аргумент используется как адрес, второй записывается по этому адресу. Допустимая гипотеза: `void f(int* p,int x){ *p=x; }`. Точный тип и владение памятью не доказаны.

### D3

Факты: первый аргумент используется как адрес, читается один байт, выполняется знаковое расширение до 32 бит. Допустимая гипотеза: `int f(const signed char* p){ return *p; }`.

## Блок E

### E1

Канарейка обнаруживает часть перезаписей перед возвратом. NX запрещает исполнение на страницах данных. Выход за границы остаётся неопределённым поведением: он может повредить служебные данные, пройти незамеченным или завершить программу.

### E2

```asm
fld qword [a]
fld qword [b]
fsubp st1, st0      ; st(0)=a-b
fld qword [c]
fdivp st1, st0      ; st(0)=(a-b)/c

sub esp, 12
fstp qword [esp]
push fmt
call printf
add esp, 16
```

Трассировка глубины: `1 → 2 → 1 → 2 → 1 → 0`. `%f` получает 8-байтный `double`; `argument_bytes=12`, `padding=4`, `cleanup=16`.

### E3

Факты: `ecx` получает 32-битное значение; по нему читается ещё одно значение; цель вызова читается из памяти по адресу `eax+8`. Гипотеза: `ecx` — `this`, `[ecx]` — `vptr`, `[eax+8]` — третья 4-байтная ячейка таблицы. Виртуальность и конкретный ABI не доказаны одним листингом.

## Решение по результату

- Все условия выполнены: зафиксируй ошибки и реши один смешанный вариант через сутки.
- Общая сумма выполнена, но провален блок или критическое задание: зачёта нет; используй [маршрут восстановления](/final_remediation).
- Общая сумма ниже 80: начни с первой непройденной контрольной точки, а не с повторного чтения ответов.
