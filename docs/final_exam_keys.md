# Ключ и рубрика финального экзамена

Открывай страницу только после законченной попытки на [экзамене](/final_exam).

## Итоговый контракт

Решение принимает `scripts/assessment_contract.json` через `scripts/assessment_engine.py`. Одновременно нужны общий порог, минимумы блоков, critical rules, evidence каждого mandatory atomic skill и новый вариант после частичной ошибки.

```text
total >= 80
A >= 12
B >= 12
C >= 16
D >= 13
E >= 9
mandatory atomic skills: evidence >= minimum
```

Критические задания: `A1`, `A2`, `B1`, `C1`, `C3`, `D1`, `E2`. Нули `A4`, `C2`, `E1` и `E3` также блокируют готовность как отсутствующее обязательное evidence.

## Блок A

### A1

При исходном `esp%16==0` для трёх аргументов:

```asm
sub esp, 4
push b
push a
push fmtIn2
call scanf
add esp, 16
```

`argument_bytes=12`, `padding=4`, `cleanup=16`; передаются адреса `a` и `b`, не `[a]`/`[b]`.

### A2

После `div` частное находится в `eax`, остаток — в `edx`. Для запрета условных механизмов:

```asm
mov ecx, edx
neg ecx
or ecx, edx
shr ecx, 31
add eax, ecx
```

Это не создаёт потенциально переполняющуюся предварительную сумму. Доказательство и шесть boundary cases обязательны.

### A3

```text
items = N*M*K
boxes = ceil(items/D)
blocked = ceil(boxes/3)
dayAnswer = boxes - blocked
```

Ночная маска — полноразрядная; проверяются переполнения произведения и промежуточных моделей.

### A4

```text
integerPart = bitMagnitude(det) / 2
fractionDigit = (bitMagnitude(det) % 2) * 5
```

Для `INT32_MIN` результат модуля не помещается в положительный `int32_t`: нужен беззнаковый/более широкий контракт либо предусловие.

## Блок B

### B1
Перед `idiv`: `edx:eax=FFFFFFFF:FFFFFFF3`; после: `eax=-2`, `edx=-3`. `cdq` не защищает `INT32_MIN/-1`: частное `2147483648` не помещается в `eax`, возникает divide exception.

### B2
`eax=0x80FF7F90`, `ax=0x7F90`, `ah=0x7F`, `al=0x90`; `al` — `144` unsigned и `-112` signed.

### B3
`jl` и `ja` могут одновременно быть истинными: один набор флагов интерпретируется как знаковое и беззнаковое отношение.

### B4
`lea` вычисляет эффективный адрес; `mov` читает память. Тип массива без контекста не доказан.

## Блок C

### C1

```text
[ebp+12] аргумент 2
[ebp+8]  аргумент 1
[ebp+4]  адрес возврата
[ebp]    сохранённый ebp
[ebp-4]  локальная 1
[ebp-8]  локальная 2
```

### C2

```asm
sum:
    push ebp
    mov ebp, esp
    mov eax, [ebp+8]
    add eax, [ebp+12]
    mov esp, ebp
    pop ebp
    ret
```

Любой изменённый `ebx/esi/edi` должен быть восстановлен на каждом возврате.

### C3

Для данного в экзамене состояния `esp%16==0`:

```asm
sub esp, 8
push dword [b]
push dword [a]
call sum
add esp, 16
```

```text
argument_bytes = 8
padding = 8
перед call: уменьшение на 16, значит esp%16==0
cleanup = 16
```

Ключ другого варианта обязан заново вычислять padding из исходного `esp` и числа аргументов. Фиксированные константы без этих входов не принимаются. Этот ответ хранится только в ключе, а не на `day_25`.

## Блок D

### D1
Факты: два 32-битных аргумента читаются и складываются; знаковость не доказана. Допустимая гипотеза — функция сложения.

### D2
Факты: один аргумент используется как адрес, другой записывается по нему. Точный тип и владение не доказаны.

### D3
Факты: читается байт и знаково расширяется. Конкретный исходный тип остаётся гипотезой.

## Блок E

### E1
Канарейка обнаруживает часть повреждений перед возвратом; NX запрещает исполнение на страницах данных; выход за границы остаётся UB и может не завершить процесс немедленно.

### E2
Порядок `fsubp`/`fdivp` доказывается трассировкой `st(0..)` и числовым oracle. `%f` получает 8-байтный `double`; padding/cleanup считаются из фактического состояния стека.

### E3
Загрузки и косвенный `call` — факты. `this/vptr/slot` — ABI-зависимая гипотеза, не доказанная одним листингом.

## Решение по результату

- Любой mandatory skill без evidence: `FAIL`, независимо от суммы.
- Частичное evidence: новый структурно отличный вариант.
- Полная готовность: `CP1+CP2+CP3+CP4+CP5+CP6+FINAL`.
