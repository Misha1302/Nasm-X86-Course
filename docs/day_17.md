## За 30 секунд

- `ebp` даёт стабильную точку отсчёта внутри кадра функции.
- После классического пролога первый аргумент лежит по `[ebp+8]`.
- Локальные данные обычно лежат ниже `ebp`.
- CDECL передаёт аргументы справа налево и возвращает `int` через `eax`.
- Вызывающая функция удаляет всю подготовленную область вызова.
- `eax`, `ecx`, `edx` можно испортить; `ebx`, `esi`, `edi`, `ebp` нужно восстановить.

После главы ты должен уметь:

- написать собственную CDECL-функцию;
- вызвать её из выровненного участка без угадывания размера очистки;
- сохранить обязательные регистры на всех путях возврата.

## Главная модель

Кадр функции — часть обычного стека, принадлежащая одному вызову.

После:

```asm
push ebp
mov ebp, esp
sub esp, 8
```

типичная карта:

```text
большие адреса
+------------------+
| argument 3       | [ebp+16]
+------------------+
| argument 2       | [ebp+12]
+------------------+
| argument 1       | [ebp+8]
+------------------+
| return address   | [ebp+4]
+------------------+
| old ebp          | [ebp]
+------------------+
| local 1          | [ebp-4]
+------------------+
| local 2          | [ebp-8]
+------------------+
малые адреса
```

Центральный инвариант:

> Пока функция использует смещения от `ebp`, сам `ebp` остаётся стабильной базой кадра, а перед `ret` восстанавливаются старый кадр и вершина стека.

---

## Пролог

```asm
push ebp
mov ebp, esp
sub esp, N
```

Пошагово:

1. `push ebp` сохраняет базу вызывающей функции;
2. `mov ebp,esp` фиксирует базу нового кадра;
3. `sub esp,N` выделяет место под локальные данные.

Например:

```asm
sub esp, 8
```

даёт две 4-байтные локальные ячейки `[ebp-4]` и `[ebp-8]`.

## Эпилог

```asm
mov esp, ebp
pop ebp
ret
```

`mov esp,ebp` удаляет локальную область, `pop ebp` возвращает старую базу, `ret` снимает адрес возврата.

Короткая форма:

```asm
leave
ret
```

где `leave` эквивалентна `mov esp,ebp; pop ebp`.

---

## Почему первый аргумент — `[ebp+8]`

Сразу после `call` на вершине лежит адрес возврата. Пролог затем кладёт старый `ebp` ещё на 4 байта ниже:

```text
[ebp]    = старый ebp
[ebp+4]  = адрес возврата
[ebp+8]  = первый аргумент
```

Padding места вызова располагается выше аргументов и поэтому не меняет эти смещения.

---

## Разобранный пример: `sum`

C:

```c
int sum(int a, int b) {
    return a + b;
}
```

NASM:

```asm
sum:
    push ebp
    mov ebp, esp

    mov eax, [ebp+8]
    add eax, [ebp+12]

    mov esp, ebp
    pop ebp
    ret
```

Трассировка:

```text
[ebp+8]  → a
[ebp+12] → b
eax       → a+b
```

### Вызов из выровненного участка

Пусть перед подготовкой выполняется `esp % 16 == 0`.

```asm
sub esp, 8
push dword [b]
push dword [a]
call sum
add esp, 16
```

Проверка:

```text
8 байт padding + 8 байт аргументов = 16 байт
```

После `ret` вызывающая функция удаляет всю подготовленную область. Пример без padding здесь намеренно не используется: курс сохраняет одно правило для всех мест вызова.

## Локальные данные

C:

```c
int twice_after_increment(int x) {
    int y = x + 1;
    return y * 2;
}
```

NASM:

```asm
twice_after_increment:
    push ebp
    mov ebp, esp
    sub esp, 4

    mov eax, [ebp+8]
    add eax, 1
    mov [ebp-4], eax

    mov eax, [ebp-4]
    imul eax, 2

    mov esp, ebp
    pop ebp
    ret
```

`[ebp+8]` относится к аргументу, `[ebp-4]` — к локальной ячейке.

---

## Регистры, которые нужно сохранять

| Группа | Регистры | Кто отвечает |
|---|---|---|
| вызываемая функция может изменить | `eax`, `ecx`, `edx` | вызывающая сохраняет заранее, если значение нужно позже |
| вызываемая функция обязана восстановить | `ebx`, `esi`, `edi`, `ebp` | вызываемая функция |

Пример:

```asm
use_ebx:
    push ebp
    mov ebp, esp
    push ebx

    mov ebx, [ebp+8]
    ; работа

    pop ebx
    mov esp, ebp
    pop ebp
    ret
```

Сохранение и восстановление должны выполняться на каждом пути возврата.

---

## Полный пример: `store_sum`

C:

```c
int store_sum(int a, int b, int* out) {
    *out = a + b;
    return a + b;
}
```

NASM:

```asm
store_sum:
    push ebp
    mov ebp, esp
    push ebx

    mov eax, [ebp+8]
    add eax, [ebp+12]

    mov ebx, [ebp+16]
    mov [ebx], eax

    pop ebx
    mov esp, ebp
    pop ebp
    ret
```

Важно различать:

```text
[ebp+16] → сам указатель out
[[ebp+16]] → данные по адресу out
```

В NASM сначала указатель загружается в регистр, затем выполняется `mov [ebx],eax`.

---

## Рекурсия

Каждый вызов создаёт собственный кадр:

```text
fact(4): свой аргумент, адрес возврата и локальные данные
fact(3): другой кадр
fact(2): другой кадр
```

Поэтому рекурсивные вызовы не делят одну локальную ячейку `[ebp-4]`: у каждого вызова свой `ebp`.

## Практика

### 1. Карта кадра

После классического пролога подпиши:

```text
[ebp]
[ebp+4]
[ebp+8]
[ebp+12]
[ebp-4]
```

<details>
<summary>Ответ</summary>

Старый `ebp`, адрес возврата, первый аргумент, второй аргумент, первая локальная ячейка.

</details>

### 2. Вызов с тремя аргументами

Из состояния `esp % 16 == 0` напиши вызов `f(a,b,c)`.

<details>
<summary>Ответ</summary>

```asm
sub esp, 4
push dword [c]
push dword [b]
push dword [a]
call f
add esp, 16
```

</details>

### 3. Найди ошибку

```asm
bad:
    push ebp
    mov ebp, esp
    push ebx
    mov ebx, [ebp+8]
    mov eax, ebx
    mov esp, ebp
    pop ebp
    ret
```

<details>
<summary>Ответ</summary>

`ebx` не восстановлен. Перед `mov esp,ebp` нужно выполнить `pop ebx`.

</details>

### 4. Разыменование указателя

Почему `mov [ebp+16],eax` не реализует `*out = eax`?

<details>
<summary>Ответ</summary>

Команда перезапишет ячейку кадра, где хранится сам указатель. Нужно сначала загрузить указатель, затем писать по нему.

</details>

## Типовые ошибки

| Ошибка | Почему неверно |
|---|---|
| считать `[ebp+4]` первым аргументом | там адрес возврата |
| очищать только аргументы после выровненного вызова | padding останется в активном стеке |
| показывать вызов без исходного состояния `esp` | выравнивание невозможно доказать |
| использовать `ebx` без восстановления | нарушается контракт вызываемой функции |
| писать в `[ebp+16]` вместо памяти по указателю | изменяется аргумент-указатель, а не объект |
| выполнить `ret` до восстановления кадра | вершина может не содержать адрес возврата |
