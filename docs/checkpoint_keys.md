# Зеркальные ключи и рубрики контрольных точек

Сначала выполни checkpoint на странице [Контрольные точки](/checkpoints). Каждый раздел ниже имеет тот же стабильный ID, что и задание.

## Как поставить 0, 1 или 2

- **2** — все обязательные элементы присутствуют, объяснение опирается на инвариант;
- **1** — центральная модель верна, но есть ровно одна локальная ошибка;
- **0** — обязательная модель неверна или отсутствует.

После `1` реши указанный **вариант** без просмотра исходного ответа. После `0` сначала выполни **повторение**, затем исходное задание и вариант.

### Операциональная граница `2 / 1 / 0`

- **2:** присутствуют все элементы строки `Ожидается`, итоговые состояния/числа верны и объяснён центральный `Инвариант`.
- **1:** центральный invariant и все decision-critical states верны, но есть ровно одна локальная синтаксическая, терминологическая или некритическая omission.
- **0:** неверно хотя бы одно итоговое machine state, направление operand, address/value, signedness, stack balance/alignment либо отсутствует центральный invariant.
- **Составные задания:** два и более независимых пропуска не сворачиваются в одну «локальную ошибку»; это `0` либо отдельные sub-scores, если они явно перечислены.
- **Граница 1/0:** красивое объяснение не компенсирует неверный trace, а верное число без обязательного механизма не получает `2`.

## Checkpoint 1

**Максимум:** 12. **Проход:** 10. **Критические ID:** `CP1-REG`, `CP1-SIZE-R`, `CP1-SIZE-W`.

<a id="key-cp1-reg"></a>
### CP1-REG

- **Ожидается:** `eax=0x123456AC`, `ebx=0x12345678`, `ax=0x56AC`, `ah=0x56`, `al=0xAC`.
- **Инвариант:** `ax/ah/al` — перекрывающиеся части `eax`; `ebx` получил старую копию.
- **Типовая ошибка:** изменить `ebx` вместе с `eax`.
- **Контрпример:** `mov ebx,eax; mov al,0` меняет только `eax`.
- **Повторение:** [День 04 — перекрытие регистров](/day_04).
- **Вариант:** `eax=0xAABBCCDD; mov ebx,eax; mov ah,0x10; sub eax,1`. Выпиши те же пять значений.

<a id="key-cp1-size-r"></a>
### CP1-SIZE-R

- **Ожидается:** `mov al, byte [esi]`.
- **Инвариант:** размер destination определяет, какая часть регистра изменяется; инструкция не обязана определять старшие биты.
- **Обязательное объяснение:** читается 1 байт; старшие 24 бита `eax` не определяются этой инструкцией и сохраняют прежнее состояние.
- **Типовая ошибка:** написать `movzx`, который расширяет байт и относится к Дню 08.
- **Контрпример:** при `eax=0x12345678` и `[esi]=0xAA` итог `eax=0x123456AA`.
- **Повторение:** [День 04 — размеры операндов](/day_04).
- **Вариант:** загрузить 16 бит по адресу `esi` только в младшую часть `eax`.

<a id="key-cp1-size-w"></a>
### CP1-SIZE-W

- **Ожидается:** `mov word [edi], ax`.
- **Инвариант:** ширина memory write является частью семантики и границы соседних объектов.
- **Обязательное объяснение:** записываются 2 байта; `dword` записал бы 4 байта и мог повредить соседние данные.
- **Типовая ошибка:** считать размер только подсказкой для документации.
- **Контрпример:** два соседних `word` в памяти; запись `dword` затрагивает оба.
- **Повторение:** [День 04 — byte/word/dword](/day_04).
- **Вариант:** записать только младший байт `eax` по адресу `edi+3`.

<a id="key-cp1-signed"></a>
### CP1-SIGNED

- **Ожидается:** unsigned `4294967295`, signed `-1`; биты не меняются.
- **Инвариант:** signedness — интерпретация одной битовой картины.
- **Типовая ошибка:** считать, что преобразование меняет регистр.
- **Контрпример:** `0x80000000` означает `2147483648` или `-2147483648`.
- **Повторение:** [День 04 — биты одинаковые, смысл разный](/day_04).
- **Вариант:** дать две интерпретации `80000001h`.

<a id="key-cp1-zero"></a>
### CP1-ZERO

- **Ожидается:** `eax=0x12340000`; исправление — `xor eax,eax` или `mov eax,0`.
- **Инвариант:** запись в `ax` не затрагивает старшие 16 бит.
- **Типовая ошибка:** считать любое нулевое присваивание обнулением всего регистра.
- **Контрпример:** начальное `eax=FFFFFFFFh` после `mov ax,0` становится `FFFF0000h`.
- **Повторение:** [День 04](/day_04).
- **Вариант:** начальное `eax=89ABCDEFh`; выполнить `mov ah,0`. Найти результат.

<a id="key-cp1-transfer"></a>
### CP1-TRANSFER

- **Ожидается:** `eax=0x80FF7F90`, `al` unsigned `144`, signed `-112`.
- **Инвариант:** `ah` заменяет биты 8–15, `al` — 0–7.
- **Типовая ошибка:** получить `0x807F0090` или обнулить другие байты.
- **Контрпример:** выписать четыре байта `80 FF 10 20` и заменить только два младших.
- **Повторение:** [День 04 — пример руками](/day_04).
- **Вариант:** `eax=0x01020304; mov ah,0xFE; mov al,0x80`; дать полный результат и signed `al`.

## Checkpoint 2

**Максимум:** 12. **Проход:** 10. **Критические ID:** `CP2-DIV`, `CP2-SCANF`, `CP2-MASK`, `CP2-IDIV-BUG`.

### CP2-DIV

- **Ожидается:** до деления `edx:eax=FFFFFFFF:FFFFFFF9`; после `eax=-2`, `edx=-1`.
- **Инвариант:** `idiv` делит signed-пару `edx:eax`, округляет quotient к нулю; remainder имеет знак делимого.
- **Типовая ошибка:** считать делимым только `eax`.
- **Контрпример:** без `cdq` старшая половина меняет 64-битное значение.
- **Повторение:** [День 09](/day_09).
- **Вариант:** протрассировать `-20/6`.

### CP2-SCANF

- **Ожидается:** `sub esp,8; push x; push fmt; call scanf; add esp,16` при исходном `esp % 16 == 0`.
- **Инвариант:** `scanf` получает pointer на место записи; аргументы идут справа налево; перед `call` `esp % 16 == 0`; caller удаляет padding и arguments.
- **Типовая ошибка:** `push dword [x]`.
- **Контрпример:** значение `x=0` означает null pointer, а не адрес переменной.
- **Повторение:** [День 05](/day_05), [День 06](/day_06).
- **Вариант:** восстановить `scanf("%d%d", &a, &b)` и очистку стека.

### CP2-MASK

- **Ожидается:** загрузки `a`, `b`, `mask`, вычисление `(a&m)|(b&~m)`; допустим любой эквивалентный NASM-shape.
- **Инвариант:** каждый бит результата выбирается соответствующим битом маски.
- **Типовая ошибка:** использовать маску `0/1` для выбора целого слова.
- **Контрпример:** при `a=FFFFFFFFh`, `b=0`, `mask=1` выбирается только младший бит.
- **Повторение:** [День 10](/day_10).
- **Вариант:** вычислить руками результат для `a=AAh`, `b=55h`, `mask=F0h`.

### CP2-SIGNMASK-BUG

- **Ожидается:** `shr` даёт `0` или `1`; для полной маски нужен `sar edx,31` после копирования signed-значения.
- **Инвариант:** arithmetic shift копирует знаковый бит.
- **Типовая ошибка:** считать `1` эквивалентом `FFFFFFFFh`.
- **Контрпример:** masked selection с отрицательным `x` и `mask=1` меняет только один бит.
- **Повторение:** [День 10](/day_10).
- **Вариант:** получить `0/-1` по знаку `ecx`, не меняя `ecx`.

### CP2-IDIV-BUG

- **Ожидается:** `xor edx,edx` образует положительное `00000000:FFFFFFF9`; корректно — `cdq`.
- **Инвариант:** signed high half должна быть sign extension `eax`.
- **Типовая ошибка:** применять unsigned-подготовку ко всем делениям.
- **Контрпример:** `eax=-1`: `00000000:FFFFFFFF` — большое положительное число, а `FFFFFFFF:FFFFFFFF` — `-1`.
- **Повторение:** [День 09](/day_09).
- **Вариант:** объяснить выбор между `cdq` и `xor edx,edx` для `eax=80000000h`.

### CP2-CEIL

- **Ожидается:** unsigned `div`: сохранить quotient из `eax`, проверить `edx!=0`, прибавить 1 без формирования `a+b-1`.
- **Инвариант:** для `a>=0,b>0`, `ceil(a/b)=q+(r!=0)`.
- **Типовая ошибка:** безоговорочно использовать `(a+b-1)/b`.
- **Контрпример:** `a=UINT32_MAX`, `b=2` переполняет сумму.
- **Повторение:** [День 09](/day_09), [День 10C](/day_10_learning_path#сессия-10c-ceil-и-деление).
- **Вариант:** вычислить безопасно `ceil(14/5)` и `ceil(15/5)`.

## Checkpoint 3

**Максимум:** 12. **Проход:** 10. **Критические ID:** `CP3-CMP`, `CP3-TABLE`, `CP3-FLAGS`.

### CP3-CMP

- **Ожидается:** signed `-1<1`, поэтому `jl` истинно; unsigned `4294967295>1`, поэтому `ja` истинно.
- **Инвариант:** `cmp` оставляет одни флаги, разные `jcc` интерпретируют их по разным правилам.
- **Типовая ошибка:** объявить один из переходов невозможным.
- **Контрпример:** та же битовая пара имеет две числовые интерпретации.
- **Повторение:** [День 12](/day_12).
- **Вариант:** сравнить `80000000h` и `0` через signed `jl` и unsigned `ja`.

### CP3-BIT

- **Ожидается:** `test eax,1; jnz .odd` или `jne .odd`.
- **Инвариант:** младший бит равен 1 у нечётного числа.
- **Типовая ошибка:** `test eax,eax`, который проверяет ноль, а не нечётность.
- **Контрпример:** `eax=2` ненулевой, но чётный.
- **Повторение:** [День 12](/day_12).
- **Вариант:** проверить, установлен ли бит 5.

### CP3-TABLE

- **Ожидается:** `ja .default`; допустимые нормализованные индексы `0..3`; исходные значения ниже 10 после `sub` становятся большими unsigned.
- **Инвариант:** unsigned range check одним сравнением отбрасывает отрицательные нормализованные значения.
- **Типовая ошибка:** `jg`, которое не защищает от отрицательного индекса.
- **Контрпример:** исходный `eax=9` даёт `FFFFFFFFh`.
- **Повторение:** [День 14](/day_14).
- **Вариант:** нормализовать cases `20..26` и написать проверку.

### CP3-LOOP

- **Ожидается:** init/check/body/step/back-edge; адрес `base+4*i`; `sum` и `i` имеют отдельное состояние.
- **Инвариант:** каждый путь повторения проходит через step и затем check.
- **Типовая ошибка:** забыть `i++` либо масштаб 4.
- **Контрпример:** `n=1` показывает пропущенную первую/последнюю итерацию.
- **Повторение:** [День 13](/day_13), [День 15](/day_15).
- **Вариант:** написать цикл суммы `short a[i]` с signed-загрузкой.

### CP3-FLAGS

- **Ожидается:** актуальные флаги принадлежат `add`; исправления — перенести `add` до `cmp` или после условного перехода, либо повторить `cmp` после `add`.
- **Инвариант:** `jcc` читает последнее актуальное флагоизменяющее состояние.
- **Типовая ошибка:** считать флаги привязанными к ближайшему визуальному `cmp`.
- **Контрпример:** `add ecx,1` может установить другой `SF/OF/ZF`.
- **Повторение:** [День 11](/day_11), [День 12](/day_12).
- **Вариант:** найти владельца флагов в `cmp; lea; test; mov; jz`.

### CP3-TRANSFER

- **Ожидается:** исходные cases `4..9`, индексы `0..5`; исходный `eax=3` после `sub` становится `FFFFFFFFh`, поэтому unsigned `ja` ведёт в default.
- **Инвариант:** нормализация и unsigned bound check образуют единый контракт.
- **Типовая ошибка:** назвать cases `0..5`.
- **Контрпример:** восстановить исходное значение как `index+4`.
- **Повторение:** [День 14](/day_14).
- **Вариант:** для `sub eax,100; cmp eax,2; ja` восстановить cases и поведение `eax=99`.

## Checkpoint 4

**Максимум:** 10. **Проход:** 8. **Критические ID:** `CP4-STACK`, `CP4-FRAME`, `CP4-EBX`.

### CP4-STACK

- **Ожидается:** после `call` сверху return address, затем `a`, затем `b`; после пролога `[ebp]=old ebp`, `[ebp+4]=return`, `[ebp+8]=a`, `[ebp+12]=b`, `[ebp-4]=local`.
- **Инвариант:** `call` сам кладёт return address.
- **Типовая ошибка:** считать `[esp]` первым аргументом сразу после `call`.
- **Контрпример:** `ret` читает адрес именно с вершины.
- **Повторение:** [День 16](/day_16), [День 17](/day_17).
- **Вариант:** нарисовать frame с тремя аргументами и двумя локальными.

### CP4-FRAME

- **Ожидается:** `push ebp; mov ebp,esp; sub esp,4; ...; mov esp,ebp; pop ebp; ret`.
- **Инвариант:** эпилог восстанавливает `esp` и старый `ebp` симметрично прологу.
- **Типовая ошибка:** `pop ebp` до восстановления `esp` при локальных данных.
- **Контрпример:** локальная область оставляет `esp` ниже saved `ebp`.
- **Повторение:** [День 17](/day_17).
- **Вариант:** выделить 12 байт локальных данных и восстановить frame.

### CP4-STRUCT

- **Ожидается:** `mov ecx,[ebp+8]; mov eax,[ecx]; mov edx,[ecx+4]` или эквивалент.
- **Инвариант:** `[ebp+8]` содержит pointer, поля читаются после разыменования по offsets.
- **Типовая ошибка:** читать `[ebp+12]` как `next`.
- **Контрпример:** `[ebp+12]` был бы следующим аргументом функции.
- **Повторение:** [День 19](/day_19).
- **Вариант:** `struct Pair { short x; short y; int z; }`; загрузить `y` signed и `z`.

### CP4-EBX

- **Ожидается:** сохранить `ebx` при входе и восстановить на всех выходах, например `push ebx`/`pop ebx`.
- **Инвариант:** CDECL callee-saved состояние принадлежит caller-у.
- **Типовая ошибка:** восстановить только на одном `return` path.
- **Контрпример:** ранний выход обходит `pop ebx`.
- **Повторение:** [День 17](/day_17).
- **Вариант:** проверить функцию с двумя выходами, использующую `esi` и `ebx`.

### CP4-TRANSFER

- **Ожидается:** подтверждены два чтения по offsets `0` и `4` от одного base; допустима гипотеза о двух полях; не доказаны имена, тип исходной структуры, ownership и nullability.
- **Инвариант:** reverse engineering разделяет наблюдение и реконструкцию.
- **Типовая ошибка:** объявить точный C++-исходник.
- **Контрпример:** те же offsets подходят массиву, структуре, заголовку объекта или протоколу данных.
- **Повторение:** [День 18](/day_18), [День 19](/day_19).
- **Вариант:** классифицировать факты и гипотезы для чтений `[p+8]`, `[p+12]`, indirect `call [p]`.

## Checkpoint 5

**Максимум:** 16. **Проход:** 13. **Критические ID:** `CP5-X87`, `CP5-VARARGS`, `CP5-STARTUP`, `CP5-X87-TRANSFER`.

### CP5-FP-BINARY

- **Ожидается:** `5.75=101.11₂`, потому что `0.75=1/2+1/4`.
- **Инвариант:** веса дробных binary-позиций равны степеням 1/2.
- **Типовая ошибка:** читать `.75` как двоичные цифры `75`.
- **Контрпример:** двоичные позиции имеют веса `1/2,1/4,1/8`.
- **Повторение:** [День 22](/day_22).
- **Вариант:** перевести `6.625`.

### CP5-FP-REPR

- **Ожидается:** `1/10` имеет знаменатель с множителем 5, поэтому binary-разложение периодично и округляется до доступных битов.
- **Инвариант:** конечная binary fraction после сокращения имеет denominator степени 2.
- **Типовая ошибка:** считать причиной «маленький размер числа».
- **Контрпример:** `1/8` меньше, но представляется точно.
- **Повторение:** [День 22](/day_22).
- **Вариант:** объяснить точность `0.125` и приближённость `0.2`.

### CP5-X87

- **Ожидается:** после `fld a`: `st0=a`, depth 1; после `fld b`: `st0=b, st1=a`, depth 2; после `faddp`: `st0=a+b`, depth 1.
- **Инвариант:** `fld` pushes, `...p` вычисляет и pops один элемент.
- **Типовая ошибка:** сохранить порядок `st0=a,st1=b` после второго `fld`.
- **Контрпример:** новая загрузка всегда становится вершиной.
- **Повторение:** [День 23](/day_23).
- **Вариант:** протрассировать `fld a; fld b; fsubp st1,st0`.

### CP5-VARARGS

- **Ожидается:** `sub esp,12; fstp qword [esp]; push fmt; call printf; add esp,16` при исходном `esp % 16 == 0`.
- **Инвариант:** `%f` читает непрерывный 8-byte `double`; format pointer занимает 4 байта; padding лежит выше аргументов; перед `call` `esp % 16 == 0`.
- **Типовая ошибка:** сохранить `dword` или очистить только 8 байт.
- **Контрпример:** неправильная ширина сдвигает чтение следующих аргументов.
- **Повторение:** [День 23](/day_23).
- **Вариант:** передать два `%f` и вычислить общий объём очистки.

### CP5-STARTUP

- **Ожидается:** loader передаёт управление ELF entry `_start`; runtime подготавливает процесс и вызывает `main`; после возврата выполняется завершение/`exit`; `global main` только экспортирует символ.
- **Инвариант:** ELF entry point и exported symbol main являются разными контрактами.
- **Типовая ошибка:** `main` вызывает runtime или является обязательным entry.
- **Контрпример:** программа без libc может иметь собственный `_start` и не иметь `main`.
- **Повторение:** [День 20](/day_20).
- **Вариант:** объяснить различие symbol visibility и ELF entry point.

### CP5-SAFETY

- **Ожидается:** UB не задаёт обязательного немедленного падения; запись может попасть в доступную память, изменить saved state и проявиться позже.
- **Инвариант:** undefined behavior не обещает ни crash, ни продолжение; наблюдаемое отсутствие падения не доказывает корректность.
- **Типовая ошибка:** «если не упало, значит запись допустима».
- **Контрпример:** повреждённый return address используется только при `ret`.
- **Повторение:** [День 21](/day_21).
- **Вариант:** объяснить, почему canary может обнаружить ошибку только в эпилоге.

### CP5-NAN

- **Ожидается:** NaN unordered и не равен даже самому себе; нужна `isnan` или соответствующая проверка unordered-флагов.
- **Инвариант:** NaN создаёт unordered comparison и не ведёт себя как обычная константа.
- **Типовая ошибка:** считать `NaN` обычной константой.
- **Контрпример:** `x != x` истинно для NaN в обычной IEEE-модели.
- **Повторение:** [День 22](/day_22).
- **Вариант:** объяснить, почему `x < NaN` и `x > NaN` также не работают как обычные сравнения.

### CP5-X87-TRANSFER

- **Ожидается:** один корректный вариант:

```asm
fld qword [a]
fld qword [b]
fsubp st1, st0
fld qword [c]
fdivp st1, st0
```

После `fsubp`: `st0=a-b`; после загрузки `c`: `st0=c, st1=a-b`; после `fdivp`: `st0=(a-b)/c`. Для `10,4,3` результат `2`.
- **Инвариант:** порядок operand stack критичен для `sub/div`; итоговая глубина равна 1.
- **Типовая ошибка:** получить `c/(a-b)`.
- **Контрпример:** числовой тест отличает `2` от `0.5`.
- **Повторение:** [День 23](/day_23).
- **Вариант:** построить `(a+b)/(c-d)` и выписать глубину после каждого шага.

## Checkpoint 6

**Максимум:** 10. **Проход:** 8. **Критические ID:** `CP6-VCALL`, `CP6-ABI`, `CP6-CALLS`.

### CP6-THIS

- **Ожидается:** подтверждены чтения 32-битных значений по offsets 4 и 8 от base `ecx` и их сложение; имена полей и сам статус `ecx` как `this` условны.
- **Инвариант:** machine offsets доказывают обращения к памяти, но не high-level names или тип base pointer.
- **Типовая ошибка:** восстановить точный класс и имена.
- **Контрпример:** `ecx` может указывать на обычную структуру.
- **Повторение:** [День 24](/day_24).
- **Вариант:** классифицировать `movzx eax,byte [ecx+1]`.

### CP6-VCALL

- **Ожидается:** `mov eax,[ecx]`; third 4-byte slot имеет offset `8`.
- **Инвариант:** это возможный shape `object→vptr→slot`, а не доказательство virtual semantics без ABI-контекста.
- **Типовая ошибка:** использовать `[ebp+8]` как сам vptr без загрузки объекта.
- **Контрпример:** объектный pointer и таблица — разные уровни разыменования.
- **Повторение:** [День 24](/day_24).
- **Вариант:** записать shape для пятого slot.

### CP6-OBJECT

- **Ожидается:** объект содержит возможный `vptr` и поля; `vptr` указывает на таблицу function pointers; offset 4 показан внутри объекта, а не таблицы.
- **Инвариант:** object data, dispatch metadata и method code принадлежат разным слоям модели.
- **Типовая ошибка:** разместить методы непосредственно в каждом объекте.
- **Контрпример:** все объекты класса разделяют код методов.
- **Повторение:** [День 24](/day_24).
- **Вариант:** нарисовать два объекта одного класса и общую vtable.

### CP6-ABI

- **Ожидается:** доказан indirect call через pointer, прочитанный по адресу `eax+8`; virtual method, номер slot и `eax=vptr` — гипотезы.
- **Инвариант:** машинная форма не несёт полного высокоуровневого типа.
- **Типовая ошибка:** слово `call [reg+offset]` автоматически превращать в C++ virtual call.
- **Контрпример:** таблица callbacks имеет тот же shape.
- **Повторение:** [День 24](/day_24).
- **Вариант:** сравнить vtable-гипотезу и dispatch table для одного листинга.

### CP6-CALLS

- **Ожидается:** `call method` содержит direct target в кодировке/relocation; `call eax` берёт target из регистра; `call [eax+8]` читает target из памяти. Ни одна indirect-форма сама по себе не доказывает виртуальность.
- **Инвариант:** directness определяется местом хранения target address, а virtual semantics требует дополнительного ABI evidence.
- **Типовая ошибка:** считать `call eax` прямым из-за отсутствия скобок.
- **Контрпример:** register target вычислен во время исполнения.
- **Повторение:** [День 24](/day_24).
- **Вариант:** классифицировать `call dword [callback]` и перечислить допустимые высокоуровневые причины.
