# Зеркальные ключи и рубрики контрольных точек

## Как принимать решение по рубрике

Не выводи зачёт из одной суммы. Для каждого задания зафиксируй evidence по atomic skills, затем проверь общий порог, minimum каждого обязательного навыка, block minimums, critical rules и обязательный новый вариант после частичной ошибки. Исполняемая версия этого решения находится в `scripts/assessment_engine.py` и питается только из `scripts/assessment_contract.json`.
Сначала выполни [контрольную точку](/checkpoints). Оценка `1` требует нового варианта; `0` требует повторения, исходной задачи и нового варианта.

## Операциональная граница оценки

### Операциональная граница `2 / 1 / 0`

- **2:** верны все обязательные состояния и объяснён центральный инвариант.
- **1:** центральная модель верна, но есть ровно одна локальная ошибка.
- **0:** неверно итоговое состояние, перепутан адрес и значение, порядок операндов, знаковость, баланс стека или отсутствует обязательный механизм.
- **Составные задания:** две независимые ошибки не считаются одной локальной ошибкой.
- **Граница 1/0:** красивое объяснение не компенсирует неверную трассировку; верный итог без обязательного механизма не получает полный балл.

## Контрольная точка 1

**Максимум:** 12. **Проход:** 10. **Критические задания:** `CP1-REG`, `CP1-SIZE-R`, `CP1-SIZE-W`.

**Минимумы по измерениям:** регистры `≥4`, размеры памяти `≥3`, интерпретация `≥1`.

### CP1-REG

- **Ожидается:** `eax=123456ACh`, `ebx=12345678h`, `ax=56ACh`, `ah=56h`, `al=ACh`.
- **Инвариант:** `ax/ah/al` перекрывают части `eax`; `ebx` хранит старую копию.
- **Типовая ошибка:** менять `ebx` вместе с `eax`.
- **Контрпример:** после копирования запись в `al` не связана с `ebx`.
- **Повторение:** [День 04](/day_04).
- **Вариант:** `eax=AABBCCDDh; mov ebx,eax; mov ah,10h; sub eax,1`.

### CP1-SIZE-R

- **Ожидается:** `byte`; меняется только `al`, старшие 24 бита сохраняются.
- **Инвариант:** ширина приёмника определяет изменяемую часть регистра.
- **Типовая ошибка:** считать, что загрузка байта обнуляет `eax`.
- **Контрпример:** `eax=12345678h`, байт `AAh` → `123456AAh`.
- **Повторение:** [День 04](/day_04).
- **Вариант:** загрузить `word [esi]` только в `ax`.

### CP1-SIZE-W

- **Ожидается:** `word`; записываются 2 байта.
- **Инвариант:** размер записи определяет число затронутых соседних байтов.
- **Типовая ошибка:** использовать `dword` как необязательную подсказку.
- **Контрпример:** два соседних `word`, запись `dword` меняет оба.
- **Повторение:** [День 04](/day_04).
- **Вариант:** записать `al` по адресу `edi+3`.

### CP1-SIGNED

- **Ожидается:** `-1` и `4294967295`; биты не меняются.
- **Инвариант:** знаковость — интерпретация битов.
- **Типовая ошибка:** ожидать преобразования регистра.
- **Контрпример:** `80000000h` имеет два числовых смысла.
- **Повторение:** [День 04](/day_04).
- **Вариант:** интерпретировать `80000001h`.

### CP1-ZERO

- **Ожидается:** `eax=12340000h`; полное обнуление — `xor eax,eax` или `mov eax,0`.
- **Инвариант:** запись в `ax` не меняет старшие 16 бит.
- **Типовая ошибка:** считать частичный регистр полным.
- **Контрпример:** `FFFFFFFFh → FFFF0000h`.
- **Повторение:** [День 04](/day_04).
- **Вариант:** `eax=89ABCDEFh; mov ah,0`.

### CP1-TRANSFER

- **Ожидается:** `eax=80FF7F90h`, `al=144` или `-112`.
- **Инвариант:** меняются только байты `ah` и `al`.
- **Типовая ошибка:** переставлять байты в полном регистре.
- **Контрпример:** выписать четыре байта отдельно.
- **Повторение:** [День 04](/day_04).
- **Вариант:** `01020304h; mov ah,FEh; mov al,80h`.

## Контрольная точка 2

**Максимум:** 18. **Проход:** 15. **Критические задания:** `CP2-DIV`, `CP2-SCANF`, `CP2-MASK`, `CP2-IDIV-BUG`, `CP2-IDIV-OVERFLOW`, `CP2-GARDEN`, `CP2-AREA`.

**Минимумы по измерениям:** деление `≥5`, адрес и ABI `≥1`, маски `≥3`, прикладной перенос `≥2`.

### CP2-DIV

- **Ожидается:** до деления `FFFFFFFF:FFFFFFF9`, после `eax=-2`, `edx=-1`.
- **Инвариант:** `idiv` делит знаковую пару и округляет к нулю.
- **Типовая ошибка:** считать делимым только `eax`.
- **Контрпример:** другая старшая половина задаёт другое 64-битное число.
- **Повторение:** [День 09](/day_09).
- **Вариант:** `-20/6`.

### CP2-SCANF

- **Ожидается:** `sub esp,8; push x; push fmt; call scanf; add esp,16`.
- **Инвариант:** адрес передаётся справа налево; удаляются padding и аргументы.
- **Типовая ошибка:** `push dword [x]` или cleanup 8.
- **Контрпример:** значение 0 не является адресом переменной.
- **Повторение:** [День 06](/day_06).
- **Вариант:** `scanf("%d%d",&a,&b)` с `padding=4`.

### CP2-MASK

- **Ожидается:** `(a&m)|(b&~m)` любым эквивалентным кодом.
- **Инвариант:** каждый бит выбирается соответствующим битом маски.
- **Типовая ошибка:** использовать `0/1` для целого слова.
- **Контрпример:** `a=FFFFFFFFh,b=0,m=1` выбирает один бит.
- **Повторение:** [Сессия 10A](/day_10_learning_path).
- **Вариант:** `AAh,55h,F0h`.

### CP2-SIGNMASK-BUG

- **Ожидается:** `shr` даёт `0/1`; нужен `sar edx,31`.
- **Инвариант:** арифметический сдвиг размножает знаковый бит.
- **Типовая ошибка:** считать `1` полной маской.
- **Контрпример:** `and value,1` сохраняет только младший бит.
- **Повторение:** [Сессия 10B](/day_10_learning_path).
- **Вариант:** получить маску по знаку `ecx`, не меняя `ecx`.

### CP2-IDIV-BUG

- **Ожидается:** фактическое число положительное `00000000:FFFFFFF9`; исправление `cdq`.
- **Инвариант:** старшая половина — знаковое расширение `eax`.
- **Типовая ошибка:** всегда обнулять `edx`.
- **Контрпример:** `eax=-1` с двумя разными `edx`.
- **Повторение:** [День 09](/day_09).
- **Вариант:** выбрать подготовку для `div` и `idiv` при `80000000h`.

<a id="key-cp2-idiv-overflow"></a>
### CP2-IDIV-OVERFLOW

- **Ожидается:** математическое частное `2147483648` не помещается в `eax` как `int32_t`; `idiv` возбуждает `#DE`.
- **Инвариант:** корректное расширение делимого и ненулевой делитель не гарантируют представимость частного.
- **Типовая ошибка:** считать `cdq` полной защитой любого `idiv`.
- **Контрпример:** `INT32_MIN / -1` имеет корректные операнды, но непредставимый 32-битный результат.
- **Повторение:** [День 09](/day_09) и [справочник `idiv`](/instruction_reference).
- **Вариант:** объяснить поведение `INT32_MIN / 1`, `INT32_MIN / -1` и `INT32_MAX / -1`.

### CP2-CEIL

- **Ожидается:** `q=a/b`, `r=a%b`, результат `q+(r!=0)`.
- **Инвариант:** нет промежуточной суммы `a+b-1`.
- **Типовая ошибка:** безусловно применять формулу через сумму.
- **Контрпример:** `UINT32_MAX` и `b=2`.
- **Повторение:** [Сессия 10C](/day_10_learning_path).
- **Вариант:** `14/5` и `15/5`.

### CP2-GARDEN

- **Ожидается:** `boxes=4`, задержанные `0,3`, `blocked=2`, дневной ответ `2`.
- **Инвариант:** нумерация начинается с нуля; количество кратных трём равно `ceil(boxes/3)`.
- **Типовая ошибка:** использовать `boxes/3`.
- **Контрпример:** при одной коробке индекс 0 уже задерживается.
- **Повторение:** [Сессия 10D](/day_10_learning_path).
- **Вариант:** `items=31,D=6`.

### CP2-AREA

- **Ожидается:** `absDet=11`, `integerPart=5`, `fractionDigit=5`, вывод `5.5`.
- **Инвариант:** площадь равна `abs(det)/2`, остаток задаёт `.0` или `.5`.
- **Типовая ошибка:** хранить модуль `INT32_MIN` в положительном `int32_t`.
- **Контрпример:** `abs(-2147483648)` не помещается в `int32_t`.
- **Повторение:** [Сессия 10E](/day_10_learning_path).
- **Вариант:** `det=8` и `det=-9`.

## Контрольная точка 3

**Максимум:** 12. **Проход:** 10. **Критические задания:** `CP3-CMP`, `CP3-TABLE`, `CP3-LOOP`, `CP3-FLAGS`.

**Минимумы по измерениям:** сравнения `≥2`, поток управления `≥4`, владелец флагов `≥1`.

### CP3-CMP

- **Ожидается:** `jl` и `ja` истинны по разным интерпретациям.
- **Инвариант:** один набор флагов допускает разные числовые отношения.
- **Типовая ошибка:** считать переходы взаимоисключающими.
- **Контрпример:** `FFFFFFFFh` — `-1` или `4294967295`.
- **Повторение:** [День 12](/day_12).
- **Вариант:** `80000000h` против 0.

### CP3-BIT

- **Ожидается:** `test eax,1; jnz .odd`.
- **Инвариант:** нечётность задаёт младший бит.
- **Типовая ошибка:** `test eax,eax`.
- **Контрпример:** число 2 ненулевое, но чётное.
- **Повторение:** [День 12](/day_12).
- **Вариант:** проверить бит 5.

### CP3-TABLE

- **Ожидается:** `ja .default`.
- **Инвариант:** после беззнакового нормирования отрицательные индексы выглядят большими.
- **Типовая ошибка:** использовать знаковый `jg`.
- **Контрпример:** исходное 9 после `sub` даёт `FFFFFFFFh`.
- **Повторение:** [День 14](/day_14).
- **Вариант:** диапазон 4..9.

### CP3-LOOP

- **Ожидается:** отдельные метки проверки, тела и шага; адрес `base+4*i`.
- **Инвариант:** все пути `continue` проходят через шаг, а `break` идёт на конец.
- **Типовая ошибка:** перескакивать через `++i`.
- **Контрпример:** первый отрицательный элемент вызывает бесконечный цикл.
- **Повторение:** [День 13](/day_13), [День 15](/day_15).
- **Вариант:** суммировать только положительные элементы с `continue`.

### CP3-FLAGS

- **Ожидается:** `jl` читает флаги `add`; исправить перестановкой `add` до `cmp` или переносом `cmp` непосредственно перед `jl`.
- **Инвариант:** переход читает последнего владельца флагов.
- **Типовая ошибка:** считать `cmp` закреплённым до перехода.
- **Контрпример:** `add` меняет `SF/OF/ZF`.
- **Повторение:** [День 11](/day_11).
- **Вариант:** вставить `lea` вместо `add` и объяснить различие.

### CP3-TRANSFER

- **Ожидается:** исходный диапазон 4..9, индексы 0..5; исходное 3 уходит в default.
- **Инвариант:** нормирование и беззнаковая проверка защищают таблицу.
- **Типовая ошибка:** назвать диапазон 0..5.
- **Контрпример:** восстановить исходное значение как `index+4`.
- **Повторение:** [День 14](/day_14).
- **Вариант:** `sub eax,10; cmp eax,2`.

## Контрольная точка 4

**Максимум:** 10. **Проход:** 8. **Критические задания:** `CP4-STACK`, `CP4-FRAME`, `CP4-STRUCT`, `CP4-EBX`, `CP4-TRANSFER`.

**Минимумы по измерениям:** стек/CDECL `≥4`, данные и анализ `≥2`.

### CP4-STACK

- **Ожидается:** после pushes `0FF8h=20`, `0FFCh=10`; внутри `f` `esp=0FF4h` и на вершине адрес возврата; после `ret` `esp=0FF8h`.
- **Инвариант:** это абстрактная трассировка механики, а не готовый ABI-вызов.
- **Типовая ошибка:** добавлять адрес возврата в cleanup вызывающей стороны.
- **Контрпример:** `ret` уже снимает адрес возврата.
- **Повторение:** [День 16](/day_16).
- **Вариант:** один аргумент при `esp=2000h`.

### CP4-FRAME

- **Ожидается:** `ebp`, `esp`, `4`, `ebp`, `ebp`.
- **Инвариант:** эпилог восстанавливает значение `esp` и старый `ebp`.
- **Типовая ошибка:** `pop ebp` до освобождения локальной области.
- **Контрпример:** `esp` указывает на локальную переменную.
- **Повторение:** [День 17](/day_17).
- **Вариант:** две локальные переменные.

### CP4-STRUCT

- **Ожидается:** `mov eax,[ebp+8]; mov edx,[eax+4]; mov eax,[eax]` в допустимом порядке.
- **Инвариант:** сначала загружается указатель, затем поля по смещениям.
- **Типовая ошибка:** читать `[ebp+12]` как поле.
- **Контрпример:** `[ebp+12]` — следующий аргумент функции.
- **Повторение:** [День 19](/day_19).
- **Вариант:** `struct Pair{short a; short b;}`.

### CP4-EBX

- **Ожидается:** `push ebx` после установки кадра или до локальной области и симметричный `pop ebx` на каждом возврате.
- **Инвариант:** вызываемая функция сохраняет `ebx`.
- **Типовая ошибка:** восстановить только на одном пути.
- **Контрпример:** ранний `ret` оставляет изменённый `ebx`.
- **Повторение:** [День 17](/day_17).
- **Вариант:** сохранить `esi` при двух выходах.

### CP4-TRANSFER

- **Ожидается:** доказаны два чтения по смещениям 0 и 4; структура, имена и владение — гипотезы.
- **Инвариант:** машинная семантика уже высокоуровневой типизации.
- **Типовая ошибка:** объявить точный `Node` доказанным.
- **Контрпример:** те же чтения подходят массиву двух `int`.
- **Повторение:** [День 18](/day_18).
- **Вариант:** листинг с `[p+8]` и косвенным `call`.

## Контрольная точка 5

**Максимум:** 16. **Проход:** 13. **Критические задания:** `CP5-X87`, `CP5-VARARGS`, `CP5-STARTUP`, `CP5-SAFETY`, `CP5-X87-TRANSFER`.

**Минимумы по измерениям:** запуск `≥1`, безопасность `≥1`, представление чисел `≥3`, x87/ABI `≥4`.

### CP5-FP-BINARY

- **Ожидается:** `101.11₂`.
- **Инвариант:** `0.75=1/2+1/4`.
- **Типовая ошибка:** переносить десятичные цифры напрямую.
- **Контрпример:** умножение дробной части на 2.
- **Повторение:** [День 22](/day_22).
- **Вариант:** `6.625`.

### CP5-FP-REPR

- **Ожидается:** после сокращения знаменатель 10 содержит множитель 5, поэтому двоичная запись периодична.
- **Инвариант:** конечная двоичная дробь имеет знаменатель-степень двойки.
- **Типовая ошибка:** объяснять числом десятичных знаков.
- **Контрпример:** `0.125` конечно.
- **Повторение:** [День 22](/day_22).
- **Вариант:** сравнить `0.2` и `0.25`.

### CP5-X87

- **Ожидается:** `a` глубина1; `b,a` глубина2; `a+b` глубина1.
- **Инвариант:** `fld` добавляет, `faddp` уменьшает глубину на один.
- **Типовая ошибка:** считать `st(0)` постоянным физическим регистром.
- **Контрпример:** новая загрузка сдвигает логические позиции.
- **Повторение:** [День 23](/day_23).
- **Вариант:** `a*b+c`.

### CP5-VARARGS

- **Ожидается:** `sub esp,12; fstp qword [esp]; push fmt; call printf; add esp,16`.
- **Инвариант:** `%f` получает 8-байтный `double`; область вызова равна 16.
- **Типовая ошибка:** `dword` или cleanup 12.
- **Контрпример:** `printf` прочитает чужие четыре байта.
- **Повторение:** [День 23](/day_23).
- **Вариант:** передать два `double` и посчитать область.

### CP5-STARTUP

- **Ожидается:** загрузчик начинает с entry point `_start`; среда вызывает `main`; `global` только экспортирует символ.
- **Инвариант:** видимость символа и точка входа — разные свойства.
- **Типовая ошибка:** считать `main` первым кодом процесса.
- **Контрпример:** ELF может иметь `_start` без `main`.
- **Повторение:** [День 20](/day_20).
- **Вариант:** команда `readelf -h` и значение Entry point.

### CP5-SAFETY

- **Ожидается:** повреждение зависит от расположения; канарейка обнаруживает часть перезаписей, NX запрещает исполнение данных.
- **Инвариант:** защиты не делают UB корректным.
- **Типовая ошибка:** ожидать обязательного немедленного падения.
- **Контрпример:** запись может попасть в неиспользуемый padding.
- **Повторение:** [День 21](/day_21).
- **Вариант:** отделить ASLR от NX.

### CP5-NAN

- **Ожидается:** NaN не равен ничему, включая себя; нужна классификация/isnan или сравнение `x!=x` на уровне идеи.
- **Инвариант:** обычное равенство не распознаёт NaN.
- **Типовая ошибка:** хранить «константу NaN» для `==`.
- **Контрпример:** `NaN==NaN` ложно.
- **Повторение:** [День 22](/day_22).
- **Вариант:** объяснить поведение `x<x` при NaN.

### CP5-X87-TRANSFER

- **Ожидается:** `fld a; fld b; fsubp st1,st0; fld c; fdivp st1,st0`; результат `2`.
- **Инвариант:** направление `st1 op st0` и последующий pop.
- **Типовая ошибка:** получить `c/(a-b)`.
- **Контрпример:** числа 10,4,3 различают порядок.
- **Повторение:** [День 23](/day_23).
- **Вариант:** `(a+b)/(c-d)`.

## Контрольная точка 6

**Максимум:** 10. **Проход:** 8. **Критические задания:** `CP6-VCALL`, `CP6-ABI`, `CP6-CALLS`.

**Минимумы по измерениям:** объект и поля `≥2`, косвенные вызовы и границы доказательства `≥4`.

### CP6-THIS

- **Ожидается:** подтверждены чтения смещений 4 и 8 от адреса в `ecx`; имена полей условны.
- **Инвариант:** смещение не доказывает имя и тип.
- **Типовая ошибка:** восстановить точный класс.
- **Контрпример:** те же смещения у структуры без методов.
- **Повторение:** [День 24](/day_24).
- **Вариант:** чтение `[ecx+12]`.

### CP6-VCALL

- **Ожидается:** `[ecx]` и `8` как возможная форма.
- **Инвариант:** это гипотеза при выбранном ABI.
- **Типовая ошибка:** объявить виртуальность доказанной.
- **Контрпример:** таблица указателей на функции не обязана быть vtable.
- **Повторение:** [День 24](/day_24).
- **Вариант:** четвёртая 4-байтная ячейка.

### CP6-OBJECT

- **Ожидается:** отдельные стрелки объект→указатель→таблица→функция и поле `+4`.
- **Инвариант:** поле объекта и ячейка таблицы находятся в разных объектах памяти.
- **Типовая ошибка:** рисовать функцию прямо внутри объекта.
- **Контрпример:** несколько объектов используют одну таблицу.
- **Повторение:** [День 24](/day_24).
- **Вариант:** два объекта с общим vptr.

### CP6-ABI

- **Ожидается:** доказан косвенный вызов по адресу из памяти; виртуальный метод требует контекста ABI и объекта.
- **Инвариант:** форма адреса вызова не равна высокоуровневой причине.
- **Типовая ошибка:** путать возможную реконструкцию с фактом.
- **Контрпример:** ручная таблица callback-ов.
- **Повторение:** [День 24](/day_24).
- **Вариант:** `call [table+8]` без объекта.

### CP6-CALLS

- **Ожидается:** прямая цель в инструкции; цель в `eax`; цель прочитана из памяти `[eax+8]`. Ни одна форма сама по себе не доказывает виртуальность.
- **Инвариант:** машинная форма сообщает источник адреса, не его высокоуровневое назначение.
- **Типовая ошибка:** считать любой косвенный вызов виртуальным.
- **Контрпример:** указатель на обычную функцию.
- **Повторение:** [День 24](/day_24).
- **Вариант:** сравнить `jmp eax` и `call eax`.
