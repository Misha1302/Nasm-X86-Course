# Ключи и рубрики контрольных точек

Сначала выполни весь checkpoint на странице [Контрольные точки](/checkpoints). Не оценивай себя по совпадению формулировки: проверяй обязательные свойства ответа.

## Общая шкала

Каждый навык оценивается отдельно:

- **2** — ответ верен и объяснён инвариантом;
- **1** — основная модель верна, есть локальная вычислительная или синтаксическая ошибка;
- **0** — модель отсутствует либо нарушен центральный инвариант.

Переход разрешён при не менее 80% баллов и отсутствии нуля по критическому навыку. После результата `1` реши дополнительный вариант. После `0` вернись к указанной главе.

## Checkpoint 1

1. Trace: `eax=0x123456AC`, `ebx=0x12345678`, `ax=0x56AC`, `ah=0x56`, `al=0xAC`.
2. Размер: `movzx eax, byte [esi]`; `mov word [edi], ax`; нельзя считать `dword` эквивалентным `word`.
3. Signed/unsigned: `FFFFFFFFh` — `4294967295` или `-1`; биты одинаковы.
4. Баг: `mov ax,0` обнуляет только младшие 16 бит, старшая половина `eax` остаётся.

Критические навыки: перекрытие регистров и размер операнда. Повторять Дни 03–04.

## Checkpoint 2

1. Адрес/значение: `scanf` получает `x`, `printf("%d",x)` — `[x]`.
2. Деление `-7/3`: `eax=-2`, `edx=-1`, перед `idiv` нужен `cdq`.
3. Masked merge: полная маска, формула `(a&m)|(b&~m)`.
4. Безопасный ceil: либо доказать отсутствие overflow для `a+b-1`, либо использовать quotient + nonzero remainder.
5. Баги: `shr` не даёт `FFFFFFFFh` для отрицательного; `xor edx,edx` меняет signed dividend.

Критические навыки: `x/[x]`, `edx:eax`, полная маска. Повторять Дни 05, 09, 10.

## Checkpoint 3

1. Для `FFFFFFFFh` и `1`: signed `jl` истинно, unsigned `ja` истинно.
2. Нечётность: `test eax,1` + `jnz/jne`.
3. Jump table: после `sub eax,10`, исходное `12` даёт индекс `2`; диапазон проверяется unsigned `ja`.
4. Цикл: должен иметь init/check/body/step/back-edge и адрес `base+4*i` для `int`.
5. Баг флагов: `add` между `cmp` и `jl` перезаписывает флаги; перенести `add` либо повторить `cmp`.

Критические навыки: signed/unsigned `jcc`, владелец флагов, проверка индекса. Повторять Дни 11–15.

## Checkpoint 4

1. Стек: аргументы находятся выше return address; после пролога `[ebp]=old ebp`, `[ebp+4]=return`, `[ebp+8]=arg1`.
2. Пролог/эпилог: `push ebp; mov ebp,esp; sub esp,4; ...; mov esp,ebp; pop ebp; ret`.
3. `Node*`: загрузить pointer из `[ebp+8]`, затем `[p+0]` и `[p+4]`.
4. Reverse: offsets доказывают обращения к двум полям, но имена и точный исходник остаются гипотезой.
5. `ebx`: callee обязан восстановить его, например `push ebx`/`pop ebx` на всех путях.

Критические навыки: return address, баланс `esp`, callee-saved. Повторять Дни 16–19.

## Checkpoint 5

1. FP: `5.75=101.11₂`; `0.1` периодично в binary.
2. x87: после `fld a; fld b; faddp` вершина содержит `a+b`, глубина уменьшена на один.
3. `%f`: `sub esp,8; fstp qword [esp]; push fmt; call printf; add esp,12`.
4. Startup: loader → `_start` → runtime → `main` → `exit`.
5. Safety/NaN: UB не обязан сразу падать; NaN не равен даже самому себе, нужна специальная проверка.

Критические навыки: x87 depth, `qword`, направление startup. Повторять Дни 20–23.

## Checkpoint 6

1. Hidden `this`: адрес объекта передаётся методу скрыто; конкретное место зависит от ABI.
2. Layout: поля — фиксированные offsets, но точный layout и padding требуют ABI/компилятора.
3. Virtual call: `object → vptr → slot → indirect call`.
4. Direct/indirect: `call label` содержит известную цель; `call [reg+offset]` читает цель из состояния программы.
5. Осторожная реконструкция: по одному листингу допустимо говорить «может быть virtual call», если ABI-контекст не зафиксирован.

Критические навыки: отличить подтверждённый indirect call от гипотезы о vtable; не объявлять ABI-зависимый layout универсальным. Повторять День 24.
