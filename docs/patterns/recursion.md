# Паттерн: рекурсия в NASM

## Когда нужен

Когда условие требует:

- написать рекурсивную функцию;
- обработать последовательность в обратном порядке без массива;
- использовать стек вызовов как временное хранилище.

Рекурсия не отменяет CDECL: каждый вызов обязан сохранить контракт стека и регистров.

## Главная идея

Рекурсивная функция вызывает сама себя до базового случая:

```text
func -> func -> func -> base case
```

Каждый активный вызов имеет отдельный кадр:

```text
высокие адреса
[ebp+12]  argument 2
[ebp+8]   argument 1
[ebp+4]   return address
[ebp]     saved ebp
[ebp-4]   local value
низкие адреса
```

Поэтому `[ebp-4]` разных вызовов — разные ячейки, хотя смещение одинаковое.

## Базовый шаблон

```asm
func:
    push ebp
    mov ebp, esp
    sub esp, 4          ; одна локальная переменная

    ; проверить базовый случай
    ; при выполнении перейти в .done

    mov eax, [ebp+8]
    mov [ebp-4], eax    ; сохранить значение до рекурсивного вызова

    push dword ...
    call func
    add esp, 4

    mov eax, [ebp-4]    ; значение снова доступно

.done:
    mov esp, ebp
    pop ebp
    ret
```

Все ветви должны приходить к согласованному эпилогу или восстанавливать стек эквивалентным способом.

## Печать до и после рекурсии

```text
действие до call  -> прямой порядок
действие после call -> обратный порядок
```

Для входа:

```text
1 2 3 0
```

печать до вызова даст:

```text
1 2 3
```

а печать после возврата:

```text
3 2 1
```

Причина — раскрутка кадров в обратном порядке.

## Разворот части последовательности без массива

Один из типовых планов:

1. прочитать очередное значение;
2. при маркере конца выполнить базовый случай;
3. данные, нужные до рекурсии, обработать сразу;
4. данные, нужные после рекурсии, сохранить в текущем кадре;
5. вызвать функцию для следующей позиции;
6. после возврата использовать сохранённое значение.

Перед реализацией определи, кто владеет вводом и индексом позиции. Иначе разные уровни рекурсии могут читать не тот элемент.

## Что сохранять

После `call` нельзя рассчитывать на сохранность:

```text
eax, ecx, edx, EFLAGS
```

Если значение нужно после рекурсии, сохрани его в локальной ячейке или в callee-saved регистре (`ebx`, `esi`, `edi`) с восстановлением перед `ret`.

## Глубина и граница стека

Рекурсивная глубина обычно пропорциональна числу элементов. При `N = 100000` даже корректная логика может переполнить стек. До выбора рекурсии оцени:

```text
примерный размер кадра × максимальная глубина
```

Если условие требует рекурсию, ограничения должны делать такой расход допустимым; если не требует, итеративный алгоритм может быть безопаснее.

## Частые ошибки

| Ошибка | Почему плохо |
|---|---|
| отсутствует достижимый базовый случай | рекурсия не завершается |
| значение хранится только в `eax` | следующий вызов вправе изменить `eax` |
| очищено неверное число байт после `call` | нарушается баланс `esp` |
| `ebx/esi/edi` изменены без восстановления | нарушается CDECL |
| не все пути проходят через корректный эпилог | кадр восстанавливается несимметрично |
| глубина не сопоставлена с ограничением `N` | возможен stack overflow |
| следующий элемент читается после рекурсии | порядок ввода уже изменён |

## Мини-практика

Для функции:

```text
read x
if x == 0: return
print x
call self
```

выпиши вывод на входе `1 2 3 0`. Затем переставь `print x` после `call self` и нарисуй три активных кадра перед базовым случаем.
