# Паттерн: строки и файлы через libc

## Когда нужен

Когда в задаче есть:

- C-строки и подстроки;
- подсчёт различных строк;
- файлы `data.in`, `input.txt`, `output.txt`;
- запрет готовых макросов ввода-вывода.

Перед этим прочитай [канонический паттерн вызова libc и выравнивания](/patterns/libc_alignment).

## Нуль-терминированная строка

C-строка заканчивается байтом `0`:

```text
'a' 'b' 'c' 0
```

Для строки длины до `1000` нужен буфер минимум `1001` байт:

```asm
section .bss
    s1 resb 1001
    s2 resb 1001
```

Дополнительный запас допустим, но он не заменяет ограничение ширины при чтении.

## Ограниченный ввод слова

Небезопасный шаблон:

```c
scanf("%s", s);
```

не знает размер буфера. Для `resb 1001` используй ширину `1000`:

```asm
section .rodata
    fmtWord db "%1000s", 0

; ... подготовка выравнивания по каноническому паттерну
push s1
push fmtWord
call scanf
; ... очистка подготовленной области
```

Проверь, что `scanf` вернул `1`. Если условие разрешает пробелы внутри строки, `%s` вообще не подходит: нужен другой способ чтения.

## Основные функции

| Функция | Результат, который надо проверить |
|---|---|
| `scanf` / `fscanf` | число успешно прочитанных полей |
| `fopen` | указатель на `FILE` или `NULL` |
| `fclose` | код завершения закрытия |
| `fprintf` | число записанных символов или отрицательное значение |
| `strcmp` | отрицательное, ноль или положительное значение |
| `strstr` | указатель на найденную подстроку или `NULL` |
| `strlen` | длина без завершающего нуля |

## Адрес строки

```asm
section .bss
    s1 resb 1001
```

Метка `s1` обозначает адрес первого байта. Передавай:

```asm
push s1
```

а не:

```asm
push dword [s1]
```

Второй вариант интерпретирует первые четыре байта содержимого как число-адрес.

## Проверка подстроки

Для `strstr(haystack, needle)` аргументы CDECL кладутся справа налево:

```asm
push needle
push haystack
call strstr
; eax = pointer or 0
```

Ненулевой `eax` означает, что подстрока найдена. После вызова очисти всю подготовленную область стека по каноническому паттерну.

## Подсчёт различных строк

Если строк не больше `500`, а длина не больше `10`, можно хранить фиксированные слоты:

```asm
section .bss
    strings resb 500 * 16
```

```text
адрес strings[i] = strings + i * 16
```

Перед копированием докажи, что строка вместе с завершающим нулём помещается в слот. Алгоритм:

```text
unique_count = 0
for each input string s:
    found = false
    for i in 0..unique_count-1:
        if strcmp(s, strings[i]) == 0:
            found = true
            break
    if not found:
        copy bounded s to strings[unique_count]
        unique_count++
```

## Файловый ввод

```c
FILE *f = fopen("data.in", "r");
if (f == NULL) {
    /* обработать ошибку */
}
while (fscanf(f, "%u", &x) == 1) {
    ++count;
}
if (fclose(f) != 0) {
    /* обработать ошибку закрытия при необходимости */
}
```

На уровне NASM после `fopen` сначала проверь `eax`. Нельзя передавать `NULL` в `fscanf` и надеяться на корректное завершение.

## Частые ошибки

| Ошибка | Почему плохо |
|---|---|
| `resb 1000` для строки длины `1000` | нет места под завершающий ноль |
| `%s` без ограничения ширины | вход может переписать память за буфером |
| `push [s]` вместо `push s` | передаётся содержимое, а не адрес |
| сравнение адресов вместо `strcmp` | одинаковый текст может находиться в разных буферах |
| использование результата `fopen` без проверки | `NULL` попадёт в последующие libc-вызовы |
| игнорирование результата `fscanf` | цикл читает старое значение или не завершается корректно |
| несогласованная очистка/выравнивание стека | нарушается контракт вызова libc |

## Мини-практика

Для буфера `resb 65` выбери безопасный формат чтения одного слова и объясни, почему ширина должна быть `64`, а не `65`.

Для проверки «`b` является подстрокой `a`» порядок аргументов:

```asm
push b
push a
call strstr
```
