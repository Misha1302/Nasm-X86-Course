# Паттерн: маски для кода без ветвлений

## Когда нужен

Когда в условии написано:

```text
Запрещается использовать инструкции условной передачи данных и управления.
```

Сначала уточни точный запрет задачи. Обычно это означает:

- нельзя использовать `jcc` и `jmp` для выбора результата;
- нельзя использовать `cmovcc`;
- иногда отдельно запрещены `setcc`;
- разрешены арифметика, битовые операции, сдвиги и работа с флагами через обычные инструкции вроде `adc` и `sbb`.

Не считай набор разрешённых инструкций универсальным: опирайся на формулировку конкретной задачи.

## Главная идея

Обычный `if` выбирает одно из двух значений:

```cpp
answer = condition ? a : b;
```

В решении без ветвлений строят полноразрядную маску:

```text
mask = FFFFFFFFh, если надо выбрать a
mask = 00000000h, если надо выбрать b
```

Тогда:

```text
answer = (a & mask) | (b & ~mask)
```

| `mask` | `a & mask` | `b & ~mask` | результат |
|---|---|---|---|
| `FFFFFFFFh` | `a` | `0` | `a` |
| `00000000h` | `0` | `b` | `b` |

Маска должна быть именно `0` или `-1`. Значение `0/1` выбирает только младший бит.

## Базовый NASM-шаблон

```asm
; eax = a
; edx = b
; ecx = mask: 00000000h или FFFFFFFFh

and eax, ecx        ; eax = a & mask
not ecx             ; ecx = ~mask
and edx, ecx        ; edx = b & ~mask
or eax, edx         ; eax = result
```

Если исходная маска понадобится дальше, сначала сделай копию: `not ecx` изменяет её.

## Маска знака

Для 32-битного значения, интерпретируемого как знаковое:

```asm
mov edx, eax
sar edx, 31
```

После этого:

```text
если eax >= 0: edx = 00000000h
если eax <  0: edx = FFFFFFFFh
```

Здесь нужен `sar`: он размножает знаковый бит. `shr` даст для отрицательного числа `1`, а не `FFFFFFFFh`.

## Модуль без переходов

Формула над 32-битным дополнительным кодом:

```text
mask = x >> 31 с арифметическим сдвигом
result = (x ^ mask) - mask
```

NASM:

```asm
mov eax, [x]
mov edx, eax
sar edx, 31
xor eax, edx
sub eax, edx
```

| `x` | `mask` | `x ^ mask` | итог |
|---:|---:|---:|---:|
| `123` | `0` | `123` | `123` |
| `-123` | `-1` | `~x` | `123` |

::: warning Граница `INT32_MIN`
Для `x = 0x80000000` формула возвращает тот же битовый шаблон `0x80000000`. Математический модуль равен `2147483648` и не помещается в `int32_t`. До реализации зафиксируй, нужен ли знаковый результат, беззнаковая величина или отдельная обработка переполнения.
:::

## Объединение по маске

Если `c` уже является битовой маской:

```text
d = (a & c) | (b & ~c)
```

```asm
mov eax, [a]
and eax, [c]

mov edx, [c]
not edx
and edx, [b]

or eax, edx
```

Каждый бит результата выбирается независимо. Поэтому `c` здесь не обязана быть только `0` или `FFFFFFFFh`.

## Деление с округлением вверх

Для `a >= 0` и `b > 0` математически верно:

```text
ceil(a / b) = (a + b - 1) / b
```

Но выражение `a + b - 1` может переполнить 32 бита. Более надёжный безветвленный вариант использует частное и остаток:

```text
q = a / b
r = a % b
answer = q + (r != 0)
```

На IA-32 без `setcc`:

```asm
; eax = a, ebx = b, b > 0
xor edx, edx
div ebx             ; eax = q, edx = r
neg edx             ; CF = 1 тогда и только тогда, когда r != 0
adc eax, 0           ; eax = q + CF
```

Проверь отдельно `a = 0`, точное деление и ненулевой остаток. Деление на ноль остаётся ошибкой.

## Как решать задачу без ветвлений

1. Запиши обычный `if` и точную область допустимых входов.
2. Определи, выбирается целое значение, отдельные биты или количество.
3. Построй формулу и отметь её предпосылки по знаковости и переполнению.
4. Для выбора двух целых используй полноразрядную маску.
5. Проверь обе крайние маски: `0` и `FFFFFFFFh`.
6. Проверь границы типа: `0`, `1`, максимум, минимум и значения около переполнения.
7. Убедись, что итоговый листинг не содержит запрещённых условием инструкций.

## Частые ошибки

| Ошибка | Почему плохо |
|---|---|
| маска `0/1` вместо `0/-1` | выбирается один бит, а не всё число |
| `shr` вместо `sar` для маски знака | для отрицательного числа получится `1` |
| повторное использование маски после `not` | регистр уже содержит дополнение маски |
| молчаливое игнорирование `INT32_MIN` | математический модуль не помещается в `int32_t` |
| формула `(a+b-1)/b` без проверки диапазона | сумма может переполниться |
| смешение знаковой и беззнаковой интерпретации | битовая формула может быть верной, а смысл сравнения — нет |

## Мини-практика

Заполни пропуск:

```asm
; eax = x
mov edx, eax
___ edx, 31
xor eax, edx
sub eax, edx
```

Объясни контрпример для варианта с `shr` и отдельно разберите `x = 0x80000000`.
