# Паттерн: связность через массивы

## Когда нужен

Когда над перестановкой выполняется много операций:

- перенести непрерывный сегмент в начало;
- удалить или вставить отрезок;
- `N` и `M` достигают `100000`;
- физический сдвиг массива после каждой операции слишком дорог.

Наивная реализация может получить `O(NM)`. Представление через связи даёт `O(1)` на локальную перестройку и `O(N)` на финальный вывод.

## Представление

Для каждого значения храним соседей:

```text
next[value] = следующий элемент
prev[value] = предыдущий элемент
head        = первый элемент
```

Это двусвязный список, узлы которого индексируются значениями в массивах. Такое представление корректно только если значения уникальны и лежат в известном диапазоне.

## Начальное состояние

Для перестановки:

```text
1 2 3 4 5 6 7
```

```text
next[1] = 2
...
next[7] = 0

prev[1] = 0
...
prev[7] = 6

head = 1
```

`0` — sentinel «нет элемента», поэтому реальные значения не должны использовать индекс `0`.

## Перенос текущего сегмента `[b..c]` в начало

Предпосылка: `b` и `c` обозначают границы одного непрерывного сегмента в текущем порядке, причём `b` встречается не позже `c`.

```text
before = prev[b]
after  = next[c]
```

### 1. Сегмент уже в начале

Если `b == head`, операция ничего не меняет.

### 2. Отрезать сегмент

```text
next[before] = after
if after != 0:
    prev[after] = before
```

Здесь `before != 0`, потому что случай `b == head` уже обработан.

### 3. Вставить перед старым `head`

```text
old_head = head
prev[old_head] = c
next[c] = old_head
prev[b] = 0
head = b
```

## Инварианты списка

После каждой операции:

```text
prev[head] = 0
для каждого ребра next[x] = y != 0 выполнено prev[y] = x
из head достижимы ровно N различных элементов
последний элемент имеет next[last] = 0
```

Последние два свойства особенно важны: локально согласованные ссылки всё ещё могут образовать цикл или потерять часть элементов.

## NASM-адресация

```asm
section .bss
    next resd 100001
    prev resd 100001
```

```asm
mov eax, [next + 4*ecx]     ; eax = next[ecx]
mov [prev + 4*ecx], eax     ; prev[ecx] = eax
```

До обращения проверь, что индекс находится в диапазоне выделенных массивов.

## Сложность

Каждая корректная операция изменяет постоянное число ссылок: `O(1)`. Финальный проход от `head` занимает `O(N)`. Для отладки ограничь число шагов вывода значением `N`: если шагов стало больше, вероятен цикл.

## Частые ошибки

| Ошибка | Почему плохо |
|---|---|
| физически сдвигать массив | получается `O(NM)` |
| не обработать `b == head` | `before` равен sentinel и логика отрезания ломается |
| обновить только `next` или только `prev` | двусторонний инвариант нарушается |
| записать `prev[0]` как обычный узел | sentinel начинает выглядеть частью списка |
| считать `[b..c]` диапазоном значений, а не текущим сегментом | операция выполняется над другой последовательностью |
| выводить от `1`, а не от `head` | теряется текущий порядок |
| не проверять число посещённых узлов | цикл или потеря элементов остаются незамеченными |

## Мини-практика

Исходно:

```text
1 2 3 4 5 6 7
```

После переноса текущего сегмента от `4` до `6`:

```text
4 5 6 1 2 3 7
```

Выпиши все изменившиеся `next/prev`, затем проверь четыре инварианта списка.
