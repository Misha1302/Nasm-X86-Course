# Шаблон: вызов libc и 16-байтное выравнивание стека

## Когда нужен

Этот контракт нужен для **каждого** вызова функции, собранной современной 32-битной средой GNU/Linux, а не только для Spring-04. GCC ожидает 16-байтное выравнивание стека; старый код с 4-байтным выравниванием нельзя без проверки смешивать с системной libc.

## Инвариант места вызова

Непосредственно перед `call`:

```text
esp % 16 == 0
```

После возврата вызывающая функция обязана восстановить `esp` точно к состоянию до подготовки выравнивания и аргументов.

## Выровненное тело `main`

Для учебного `main`, который возвращается через `ret`, используем простой кадр стека:

```asm
main:
    push ebp
    mov ebp, esp
    and esp, -16

    ; body: esp % 16 == 0

    mov esp, ebp
    pop ebp
    xor eax, eax
    ret
```

`ebp` сохраняет исходную вершину кадра, поэтому эпилог восстанавливает адрес возврата независимо от того, сколько байт отбросил `and esp, -16`.

## Как вычислить выравнивающие байты

Если в начале тела функции выполняется `esp % 16 == 0`, то:

```text
padding = (16 - (argument_bytes % 16)) % 16
```

Выравнивающие байты размещаются **до** аргументов. После вызова вызывающая функция удаляет их вместе с аргументами.

| Аргументы | Байты аргументов | Выравнивающие байты | Всего удалить |
|---|---:|---:|---:|
| один 32-битный | 4 | 12 | 16 |
| два 32-битных | 8 | 8 | 16 |
| три 32-битных | 12 | 4 | 16 |
| четыре 32-битных | 16 | 0 | 16 |
| указатель на формат + `double` | 12 | 4 | 16 |

## Пример: `printf("%d\n", x)`

```asm
sub esp, 8
push dword [x]
push fmtOut
call printf
add esp, 16
```

Перед `call` были сняты `8 + 4 + 4 = 16` байт.

## Пример: `scanf("%d%d", &a, &b)`

```asm
sub esp, 4
push b
push a
push fmtIn
call scanf
add esp, 16
```

Здесь `4 + 12 = 16`. В `scanf` передаются адреса.

## Пример: `printf("%f", value)` через x87

```asm
sub esp, 12
fstp qword [esp]
push fmtFloat
call printf
add esp, 16
```

До `push` область `[esp..esp+7]` содержит `double`. После `push fmtFloat` значение непрерывно лежит по `[esp+4..esp+11]`, а выравнивающие байты остаются выше всех аргументов.

## Обычная функция и вспомогательная обёртка

Если текущее значение `esp % 16` неизвестно, не подбирай выравнивание наугад. Используй один из двух способов:

1. создай выровненный кадр через `and esp, -16` и восстанови исходный `esp` через указатель кадра;
2. вынеси вызов libc во вспомогательную функцию с явно доказанным состоянием стека на входе и выходе.

## Частые ошибки

| Ошибка | Почему неверно |
|---|---|
| считать выравнивание требованием только одной задачи | это часть взаимодействия с современной средой и libc |
| удалить только байты аргументов | выравнивающие байты останутся и изменят состояние кадра |
| добавить выравнивающие байты после аргументов | изменится расположение параметров для вызываемой функции |
| считать успешный локальный запуск доказательством | libc может случайно работать и при неверном выравнивании |
| передать `[x]` в `scanf` | вызываемая функция получает значение вместо адреса |

## Проверка

На точке останова перед каждым внешним `call`:

```gdb
p/x $esp
p $esp % 16
```

Ожидается `0`. После очистки стека значение `esp` должно совпасть с состоянием до подготовки вызова.
