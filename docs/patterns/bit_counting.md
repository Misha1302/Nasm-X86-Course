# Паттерн: битовые циклы

## Когда нужен

Когда задача говорит про:

- `K` подряд идущих битов;
- количество единиц;
- количество значащих нулей;
- двоичную запись числа;
- числа до `100000` или до `1000000000`.

Главный навык — превратить условие о двоичной записи в цикл по битам с явно выбранной разрядностью.

## Бит как маленькое окно

Для беззнакового 32-битного значения:

```text
bit = x & 1
x >>= 1
```

```asm
mov edx, eax
and edx, 1       ; edx = младший бит
shr eax, 1       ; следующий бит станет младшим
```

Для беззнаковых значений используй `shr`. `sar` сохраняет знак и для отрицательного значения может никогда не довести регистр до нуля.

## Подсчёт единичных битов

```cpp
uint32_t x = value;
unsigned count = 0;
while (x != 0) {
    count += x & 1u;
    x >>= 1;
}
```

```asm
xor ecx, ecx        ; count = 0

.loop:
    test eax, eax
    je .end

    mov edx, eax
    and edx, 1
    add ecx, edx

    shr eax, 1
    jmp .loop

.end:
; ecx = popcount исходного беззнакового eax
```

Сохрани исходное значение заранее, если оно понадобится после цикла.

## Длина двоичной записи

Для положительного `x` длина равна числу сдвигов до нуля:

```text
x = 1      -> len = 1    binary: 1
x = 4      -> len = 3    binary: 100
x = 18     -> len = 5    binary: 10010
```

```cpp
unsigned len = 0;
while (x != 0) {
    ++len;
    x >>= 1;
}
```

Для `x = 0` заранее выбери соглашение. Часто используют `bit_length(0) = 0`, но задача может считать запись `0` одноразрядной.

## Значащие нули

Для положительного числа значащими считаются нули между старшей единицей и младшим разрядом:

```text
18 = 10010b
len = 5
ones = 2
significant zeros = 5 - 2 = 3
```

```text
zeros = bit_length(x) - popcount(x)
```

Формула требует отдельно определить поведение для `x = 0`.

## Скользящее окно из `K` битов

В 32-битной модели задача «найти максимальное значение среди всех окон длины `K`» записывается так:

```cpp
uint32_t mask = K == 32 ? UINT32_MAX : (1u << K) - 1u;
uint32_t answer = 0;

for (unsigned shift = 0; shift <= 32u - K; ++shift) {
    uint32_t candidate = (N >> shift) & mask;
    answer = std::max(answer, candidate);
}
```

Предпосылка: `1 <= K <= 32`. Сравнение кандидатов — беззнаковое.

В NASM переменный сдвиг использует `cl`:

```asm
mov eax, [N]
shr eax, cl
and eax, [mask]
```

На IA-32 аппаратно учитываются только младшие 5 бит счётчика. Поэтому сдвиг на `32` фактически ведёт себя как сдвиг на `0`; это не способ получить ноль и не способ построить маску для `K = 32`.

## Маска `(1 << K) - 1`

Для `1 <= K <= 31`:

```asm
mov eax, 1
mov ecx, [K]
shl eax, cl
sub eax, 1
; eax = mask
```

Для `K = 32` маску надо задать отдельно:

```asm
mov eax, 0FFFFFFFFh
```

До выполнения сдвига проверь диапазон `K`; значения `0` и больше `32` требуют отдельного решения по условию задачи.

## Полный перебор или комбинаторика

| Ограничение | Подход |
|---|---|
| `N <= 100000` | часто допустим перебор `x = 1..N` |
| `N <= 1000000000` | полный перебор обычно слишком медленный; нужен подсчёт по битам |

Для большой версии задачи о двоичных нулях типовая идея:

```text
идём по битам N сверху вниз;
при единице считаем меньшие числа с нужным числом нулей;
используем C(len, k) только для оставшихся позиций;
отдельно учитываем границу N и запрет ведущих нулей.
```

Это уже алгоритмическая часть, а не новая инструкция NASM.

## Частые ошибки

| Ошибка | Почему плохо |
|---|---|
| хранить переменный счётчик не в `cl` | обычные IA-32 сдвиги читают счётчик из `cl` |
| использовать `sar` в цикле по беззнаковому шаблону | старшие единицы сохраняются, цикл может не завершиться |
| считать ведущие нули значащими | меняется определение двоичной записи |
| сравнивать окна как знаковые числа | окно с установленным старшим битом будет ошибочно считаться отрицательным |
| вычислять `1 << 32` | счётчик маскируется, ожидаемая маска не получается |
| не определить случай `x = 0` | длина и число значащих нулей становятся неоднозначными |
| полный перебор при `N = 10^9` | не проходит по времени |

## Мини-практика

Для `N = 12 = 1100b`, `K = 3`:

```text
shift 0: 100b = 4
shift 1: 110b = 6
shift 2: 011b = 3
answer = 6
```

Затем разберите отдельно `K = 32` и объясните, почему инструкция `shl eax, 32` не строит маску `FFFFFFFFh`.
