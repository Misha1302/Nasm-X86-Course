# Дополнительно: указатели на функции и переменное число аргументов

::: warning
Не переходи к этой теме до CDECL, кадров стека, массивов и выравнивания перед вызовом.
:::

## Когда нужен

Когда функция получает:

- указатель на функцию;
- переменное число аргументов;
- задачу вручную собрать вызов на стеке.

Пример на C:

```c
apply(array, length, fprintf, 2, stdout, "%d\n");
```

Здесь `fprintf` передаётся как адрес кода, а `stdout` и `"%d\n"` — данные, которые `apply` должна передать дальше.

## Вызов по указателю

Обычный прямой вызов:

```asm
call fprintf
```

Косвенный вызов:

```asm
call eax        ; eax содержит адрес функции
```

Если адрес функции находится в `[ebp+16]`:

```asm
mov eax, [ebp+16]
call eax
```

До вызова нужно знать не только адрес, но и контракт функции: порядок аргументов, возвращаемое значение и регистры, которые она может изменить.

## Кадр `apply`

Для сигнатуры:

```c
apply(int *array, size_t length, void (*fn)(...), int n, ...)
```

```text
[ebp+8]   array
[ebp+12]  length
[ebp+16]  fn
[ebp+20]  n
[ebp+24]  vararg[0]
[ebp+28]  vararg[1]
...
```

Предпосылки задачи должны ограничивать `n`; отрицательное или слишком большое значение нельзя использовать как число слов для чтения со стека.

## Какой вызов строится

Для каждого элемента:

```c
fn(vararg[0], vararg[1], ..., vararg[n - 1], array[i]);
```

Для `n = 2`, когда `[ebp+24]` содержит значение `stdout`, `[ebp+28]` — значение указателя на строку формата, а `esi` — текущее `array[i]`, вызов `fprintf(stdout, "%d\n", array[i])` собирается так:

```asm
mov eax, [ebp+16]     ; fn = fprintf
push esi              ; третий аргумент: значение array[i]
push dword [ebp+28]   ; второй аргумент: значение указателя fmt
push dword [ebp+24]   ; первый аргумент: значение FILE* stdout
call eax
```

Квадратные скобки здесь читают **значения указателей из кадра `apply`**. Они не разыменовывают `fmt` как строку и не читают содержимое объекта `FILE`.

В общем случае:

1. положить `array[i]`;
2. пройти `j = n - 1 .. 0` и положить `vararg[j]`;
3. вызвать `fn`;
4. удалить аргументы и padding одной согласованной операцией.

Адрес `vararg[j]`:

```text
[ebp + 24 + 4*j]
```

Перед вычислением адреса проверь диапазон `j`, чтобы арифметика не вышла за кадр вызывающей функции.

## Сохранение состояния

`fn` может изменить `eax`, `ecx`, `edx` и флаги. Значения цикла, которые нужны после вызова, храни:

- в локальных переменных;
- или в `ebx`, `esi`, `edi` с обязательным сохранением и восстановлением.

Сам адрес `fn` тоже нельзя бездумно оставлять в `eax`, если после вызова он понадобится снова.

## Динамическое выравнивание

Число передаваемых слов равно `n + 1`, поэтому размер аргументов меняется:

```text
args_bytes = 4 * (n + 1)
```

Используй единый канонический контракт из [страницы о libc и выравнивании](/patterns/libc_alignment): padding вычисляется для всей подготовленной области до первого `push`, а после вызова удаляются `padding + args_bytes`.

Нельзя просто «запомнить `esp`, выровнять его вниз и потом восстановить», если между этими действиями затрагиваются локальные данные или нарушается ожидаемая структура кадра. Сначала нарисуй точное состояние стека.

## Инвариант вызова

Непосредственно перед `call fn`:

```text
аргументы лежат в CDECL-порядке;
значение esp удовлетворяет требуемому выравниванию;
локальные данные и сохранённые регистры не перекрыты.
```

Непосредственно после очистки:

```text
esp возвращён к значению до подготовки padding и аргументов.
```

## Частые ошибки

| Ошибка | Почему плохо |
|---|---|
| вызвать параметр как статическую метку | реальный адрес приходит во время выполнения |
| положить `vararg` в прямом порядке | вызываемая функция увидит аргументы переставленными |
| забыть `array[i]` | последний параметр вызова отсутствует |
| спутать значение указателя с данными по этому адресу | в вызов попадёт не тот аргумент |
| удалить только `(n+1)*4`, забыв padding | стек смещается |
| хранить индекс в `ecx` через `call fn` | вызываемая функция вправе изменить `ecx` |
| не ограничить `n` | чтение выходит за переданные аргументы |
| считать любой указатель безопасным для вызова | неверный адрес или контракт приводит к неопределённому поведению |

## Мини-практика

Для `n = 2` и `vararg = [stdout, fmt]` выпиши порядок `push` для:

```c
fn(stdout, fmt, x)
```

Затем вычисли `args_bytes` и padding по канонической формуле для заданного остатка `esp mod 16`.
