# NASM x86 для олимпиадников на C++

Самостоятельный учебник по NASM IA-32: от модели процессора и памяти до CDECL, анализа машинного кода, структур, x87 и модели объектов C++.

> Ты уже умеешь C++. Теперь учимся видеть, как программа выглядит на уровне процессора IA-32.

## Что делает курс самостоятельным

Для каждого из 25 дней есть:

- точные входные знания и ссылка для возврата к пропущенной теме;
- объяснение через состояние регистров, памяти, флагов и стека;
- практика внутри главы;
- новая задача `TR-XX` в [рабочей тетради](docs/transfer_workbook.md);
- [диагностический ключ](docs/transfer_keys.md) с тем же номером;
- следующий шаг в конце главы;
- шесть [контрольных точек](docs/checkpoints.md) с постоянными номерами `CP`;
- [критерии оценивания и дополнительные варианты](docs/checkpoint_keys.md);
- [самостоятельный маршрут](docs/self_study.md) с интервальным повторением и журналом ошибок;
- необязательный [ИИ-наставник](docs/ai_tutor_prompts.md).

Главное правило:

> Если ты не можешь нарисовать состояние машины и объяснить нарушенный инвариант, тему рано считать закрытой.

## ИИ-наставник без недоказанных обещаний

Инструкции подходят для разных моделей, включая ChatGPT и DeepSeek. Но конкретная модель считается проверенной только после сохранённых воспроизводимых запусков.

- [инструкции для ИИ-наставника](docs/ai_tutor_prompts.md);
- [правила проверки](docs/ai_tutor_eval.md);
- сценарии проверки: `evals/ai_tutor_cases.json`.

Пока таких запусков нет, подтверждена только структура инструкций, но не поведение модели.

## Формат и границы

- NASM x86 / IA-32 без смешения с ABI x86-64;
- командная строка Linux или SASM;
- `nasm -f elf32` и `gcc -m32 -no-pie`;
- сначала задачи Spring-01: 01-4, 01-8, 01-14, 01-15, 01-16;
- затем флаги, поток управления, стек, CDECL, адресация, анализ машинного кода, структуры, безопасность памяти, числа с плавающей точкой и x87;
- современный x86-64 вынесен в отдельный следующий маршрут.

## Начать обучение

1. Открой [самостоятельный маршрут](docs/self_study.md).
2. Проверь [поддерживаемую среду](docs/support_matrix.md).
3. Начни с [Дня 01](docs/day_01.md).
4. После главы перейди по блоку `Следующий шаг` к задаче `TR-XX`.
5. После каждого раздела пройди контрольную точку и отдельно оцени каждое задание `CP`.

День 10 проходится как [пять отдельных занятий](docs/day_10_learning_path.md), а не как один длинный подход.

## Проверяемые примеры

Примеры находятся в `examples/*.asm`, а ожидаемый вывод — в `examples/expected/*.txt`.

```bash
for file in examples/*.asm; do
    name="$(basename "$file" .asm)"
    nasm -f elf32 "$file" -o "/tmp/$name.o"
    gcc -m32 -no-pie "/tmp/$name.o" -o "/tmp/$name"
    "/tmp/$name"
done
```

Базовая команда:

```bash
nasm -f elf32 main.asm -o main.o
gcc -m32 -no-pie main.o -o main
./main
```

Параметр `-no-pie` нужен потому, что ранние примеры используют простые абсолютные адреса. Механизмы PIE, GOT и PLT в начальную модель не входят.

- правильность подсчёта баллов в контрольных точках;
- критические задания и дополнительные варианты;
- файлы Markdown, ссылки и якоря;
- структуру инструкций для ИИ и сценариев их проверки;
- полноту автоматически создаваемого учебника;
- технические границы и исполняемые примеры NASM.

## Где ассемблер нужен сегодня

Ассемблер применяют точечно, когда нужна конкретная машинная инструкция, точный контроль ABI или доказанная измерениями оптимизация горячего участка. Типичные области: системное программирование, компиляторы и JIT, библиотеки среды выполнения, libc, кодеки, криптография, анализ машинного кода, встраиваемые системы и программы с жёсткими требованиями к задержке.

Правильный порядок оптимизации:

```text
измерить → изучить дизассемблирование → найти узкое место → решить, нужен ли ручной ассемблер
```
