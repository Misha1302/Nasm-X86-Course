# NASM x86 для олимпиадников на C++

Самостоятельный учебник по NASM IA-32: от модели процессора и памяти до CDECL, reverse engineering, структур, x87 и C++ object model.

> Ты уже умеешь C++. Теперь учимся видеть, как код выглядит глазами процессора IA-32.

## Что делает курс самостоятельным

Курс не заканчивается чтением главы. Для каждого из 25 дней есть:

- входные знания и конкретный маршрут возврата;
- объяснение через состояние регистров, памяти, флагов и стека;
- практика внутри главы;
- новая transfer-задача в [рабочей тетради](docs/transfer_workbook.md);
- отдельный [ключ с диагностикой](docs/transfer_keys.md);
- шесть [контрольных точек](docs/checkpoints.md) с прозрачной рубрикой;
- [самостоятельный маршрут](docs/self_study.md) с интервальным повторением и журналом ошибок;
- необязательный [AI-наставник](docs/ai_tutor_prompts.md) для ChatGPT, DeepSeek и других моделей.

Главное правило:

> Если ты не можешь нарисовать, что происходит с регистрами, памятью, стеком или флагами после инструкции, тему рано считать понятой.

## Формат и границы

- **NASM x86 / IA-32**, без смешения с x86-64 ABI;
- основная среда — Linux CLI или SASM;
- сборка через `nasm -f elf32` и `gcc -m32 -no-pie`;
- сначала задачи Spring-01: 01-4, 01-8, 01-14, 01-15, 01-16;
- затем флаги, control flow, стек, CDECL, адресация, reverse, структуры, безопасность, floating point и x87;
- современный x86-64 вынесен в отдельный следующий маршрут.

## Проверяемые примеры

Ключевые фрагменты находятся в `examples/*.asm` и имеют ожидаемый вывод в `examples/expected/*.txt`.

```bash
for file in examples/*.asm; do
    name="$(basename "$file" .asm)"
    nasm -f elf32 "$file" -o "/tmp/$name.o"
    gcc -m32 -no-pie "/tmp/$name.o" -o "/tmp/$name"
    "/tmp/$name"
done
```

Базовая команда:

```bash
nasm -f elf32 main.asm -o main.o
gcc -m32 -no-pie main.o -o main
./main
```

`-no-pie` используется потому, что ранние учебные примеры работают с простыми абсолютными адресами меток. PIE/GOT/PLT не смешиваются с первой моделью.

## Где ассемблер нужен сегодня

Ассемблер используют точечно там, где нужны конкретная архитектурная инструкция, полный контроль над ABI/машинным состоянием или измеренная оптимизация горячего участка: системное программирование, компиляторы и JIT, runtime-библиотеки, libc, кодеки, криптография, reverse engineering, embedded и low-latency код.

Современный компилятор часто генерирует отличный код. Правильный порядок работы:

```text
измерить → изучить дизассемблирование → найти bottleneck → только затем решать, нужен ли ручной asm
```
